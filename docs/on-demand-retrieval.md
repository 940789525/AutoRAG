# 按需检索

在可信配置中设置 `"retrievalPolicy": "on-demand"`，或在构造 `AutoRAGAgent` 时传入同名选项。若启动的是编译后的 CLI，请先使用包含此改动的构建，再重新启动 CLI。未设置或设为 `"legacy"` 时维持原行为。这个设置只改变代理问答，`retrieve()` 等显式检索 API 仍然执行调用方要求的检索。

按需模式下，普通首问的第一次回答模型请求没有自动本地预取，也不自动加载检索记忆。模型可以直接回答、调用网络、检索本地或指定数据源，或显式调用 `check_memory`。如果允许自配置，保留已有 Jev 的 config 判断；普通请求即使路由失败也进入工具可用的回合。自然语言索引操作和权限边界仍由原入口处理。按需模式只交付完整最终答案，配置了 `answerMode: progressive` 也不自动生成草稿。

这里保证的是**不在模型决策前预取**。模型仍可能选错工具；同一会话已经发送的正文仍在历史中。对于确实需要本地资料的问题，工具决策和随后回答通常需要两次模型请求；不承诺总费用、耗时或服务端 KV 缓存命中率下降。回滚只需将策略改回 legacy；无需重建索引或删除历史。

## 验证约定（在查阅分数前冻结）

采用 [1105 验收规格](../myself_dev/1105/05-验收与对照评测.md) 的发布门槛：首问自动预取 0 次、相关证据保留率至少 95%、无关正文注入率不超过 5%、本地任务成功率相对原版本下降不超过 2 个百分点。费用与缓存按实际提供方用量报告，不以客户端前缀相同代替。仅凭小规模离线样本不能改变产品默认。

本地分数实验固定使用原始 Qwen cosine；不使用融合后的排名。先用校准问题的必要证据确定仍能保留至少 95% 必要证据的最高阈值，再在不同问题与文档上检验，保留集结果不用于回调阈值。需要覆盖“同主题但资料中无答案”的困难负例。没有合格校准证据时不提供一个经验阈值来开启硬过滤。模拟请求、合成语料分数和真实模型效果分别记录。

两种语言的独立验证均未达标，详见[验证记录](../myself_dev/1105/06-验证记录.md)。当前版本只接受省略 `localEvidenceFilter` 或显式 `{"mode":"off"}`；`observe`、`enforce` 均未上线。已经调用本地工具时，既有 `contextSelection` 仍按原设置工作，不保证无关块一定被剔除。

复测时在隔离 QA 容器中启动自有离线 FastEmbed 服务，将 `AUTORAG_QA_EMBED_ENDPOINT` 设为它的 loopback 地址、`AUTORAG_QA_TOKENIZER` 设为对应模型 tokenizer 目录，然后执行 `node scripts/bench/retrieval-admission.mts`。脚本只使用版本控制中的合成材料和临时 workspace，输出校准及验证的原始分数；它不会生成可供产品启用的阈值文件。
