# 现状与方案决策

## 已观察到的问题

2026 年 11 月 5 日本聊天前序只读核查了开发容器内三份 Pi 会话及 `runs.jsonl`。它们不是本方案的受控实验，也没有记录最终 HTTP 请求正文的完整快照。

| 会话文件时间前缀 UTC | 问题摘要 | 原始用户消息中的 baseline 候选 | baseline 字符数 |
| --- | --- | --- | --- |
| `2026-11-05T11-47-52-835Z` | 吉利校招 Agent 或后端岗位 | 100 | 55,572 |
| `2026-11-05T12-04-58-886Z` | 今天合肥天气 | 100 | 83,329 |
| `2026-11-05T12-09-45-151Z` | 厦门银行校招及计算机岗位 | 100 | 51,674 |

会话位于容器 `/dev-home/.pi/agent/sessions/--data-workspace--/`。主要候选来自 TempMe、DiscoVLA、DGL 论文，另有开发说明和退款规则。字符数不是 token 数，也不能据原始 transcript 推断容量保护后仍发送了全部 100 块。天气首个模型响应报告 39,848 输入 token，包含系统、工具等全部输入，不能全部归因于 baseline。

当时配置为 Jev OpenRouter、`rerank: false`、未设置 `contextSelection`。三次首问在进入回答模型前均有 Jev error 用量记录；代码将路由失败回退为本地检索。记录未保存具体错误原因，不据此断言凭据缺失或网络故障。记忆文件当时的 `judgedEvidence`、`insights` 均为空，不应把 baseline 误归因于自动记忆。

本目录不复制私人全文 trace、认证文件或原始语料。后续回归使用合成材料，真实 trace 的进一步处理必须维持原有访问边界。

## 当前源码为什么会这样

| 环节 | 基线行为 | 对方案的影响 |
| --- | --- | --- |
| [query-routing.ts](../../src/agent/query-routing.ts) | `local/direct/config`；近期、特定或变化中的事实也归 local；默认回退 local | 修复 Jev 不能单独解决天气也查论文的问题 |
| [agent.ts](../../src/agent/agent.ts) 的 `planQuery` 与 `prefetchInitialRetrievalContext` | 首问先规划并预取，本地默认最多 100 个候选 | 需要在预取发生前改变流程 |
| 同文件 `isConversationTurn` 分支 | 后续 TUI 问题直接进入工具可用的 agent | 可复用此工作方式，但不能直接跳过 self-config 等首问责任 |
| [lance-store.ts](../../src/indexing/lance-store.ts) | vectorSearch 排名取 topK；原始 cosine 为 `1 - distance` | 有最近邻不代表有合格证据 |
| [method.ts](../../src/indexing/method.ts) | `localEvidence` 携带 profile、query、cosine、块向量和读取定位 | 无须为本地过滤重新向量化所有候选 |
| [context-selection.ts](../../src/agent/context-selection.ts) | 分差截断、MMR 多样性、去重、预算 | 可复用，不等于整批无关识别器 |
| [context-selection-projector.ts](../../src/agent/context-selection-projector.ts) | 已发送前缀＋新后缀；非简单事实等分支保守保留；可显式恢复正文 | 新准入必须先于软预算例外，不能被原有兜底重新加回 |
| [search-minsync-tool.ts](../../src/agent/search-minsync-tool.ts) 等 | 工具直接返回候选正文；原始 details 保留检索记录 | 只改 baseline 不够，工具路径也要覆盖 |
| [rerank.ts](../../src/retrieval/rerank.ts) | 当前工厂构建 OpenRouter/Dazzi 兼容实现，默认取 topN | 没有内置本地重排服务；排名与准入应分开 |
| `rerankPrefetchPool` | 非空池得到空重排结果被当作错误，回退原候选 | 不能把“全部被拒绝”直接塞进重排空数组语义 |
| `withMemoryContext` | 非空检索记忆自动进入请求；adaptive 使用当前后缀 | 新按需模式还要防止在工具决策前自动塞入记忆正文 |

## 方案比较

| 方案 | 收益 | 代价或限制 | 本规格决策 |
| --- | --- | --- | --- |
| 主模型先选工具 | 不必新增路由模型；复用已有 Pi 循环；允许本地与网络组合 | 本地问题可能多一次主模型往返；工具误选仍可能发生 | 首版主路径 |
| 独立 Jev 或 LLM 来源分类 | 可在预取前决定来源，适合保留预取优化 | 额外串行请求或现有 Jev 依赖；失败策略和混合意图复杂 | 不新增必经分类；保留既有非检索职责 |
| 本地向量意图路由 | 可利用既有 embedding，固定意图时便于校准 | 来源选择与语义相近不是一回事；依赖样本和拒判 | 暂不引入独立路由索引 |
| 现有分数加本地准入 | 不新增云端调用或模型服务 | 主题相似但答案无关可能分不开，必须评测 | 首版过滤候选方案 |
| 本地 reranker | 对问题和段落做额外相关性评分 | 新权重、服务、内存、延迟及许可核查 | 阈值方案未通过时再单独立项 |
| 微调 Self-RAG 或 Adaptive-RAG 类模型 | 可学习检索策略或反思信号 | 训练与部署复杂，不适合本次最小改动 | 不纳入首版 |

## 判断与发送必须分开

“需要外部信息”“需要本地资料”“这个候选有用”是不同判断。主模型先决定信息来源；本地准入再决定候选正文能否进入其上下文。库里没有有关天气的资料，不会因为向量检索返回了排名第一的论文而改变。

本地阈值只是一种可验证的启发式，不能被表述为充分性证明。若正负样本分数严重重叠，应停止强制过滤上线，保留仅按需检索版本并记录局限，不能通过调低测试难度来宣称问题解决。

## 调用与缓存取舍

只计主回答模型，简单的“预取后一次回答”可由 1 次变为“工具决策＋结果后回答”2 次；常识问题仍可 1 次，网络问题也可能沿用原有工具轮数。Jev、索引意图识别、记忆判断、分解、重试等辅助调用另计，不能遗漏后声称无额外调用。

规则过滤复用已有分数，不增加云端 token；额外本地模型仍有计算成本。减少正文不保证总费用减少，应同时测量输出、未缓存输入、缓存读取、缓存写入和重试。

先过滤再第一次发送，有利于后续沿用稳定前缀。每轮为了新问题重排或删除旧正文则可能降低服务端缓存命中。客户端维持前缀是必要工程措施，不是实际 KV 命中的证明；模型、工具 schema、系统提示或权限变化仍应正确失效。

## 研究依据

以下资料支持方法选择，不证明本项目已经获得质量或性能收益，也不要求引入这些框架。来源在 2026 年 11 月 5 日前序调研中通过 Exa 核对。

- [LangGraph Agentic RAG](https://docs.langchain.com/oss/python/langgraph/agentic-rag)：先由模型决定是否调用检索工具，再评价检索结果。
- [LlamaIndex Router Query Engine](https://developers.llamaindex.ai/python/examples/query_engine/routerqueryengine/)：按工具描述选择一个或多个来源；具体 SDK 示例不是本项目的依赖要求。
- [Adaptive-RAG](https://aclanthology.org/2024.naacl-long.389/)：学习选择不检索、单步或多步策略，分类目标与本地来源选择不同。
- [Self-RAG](https://selfrag.github.io/)：训练检索及反思标记，分别处理检索必要性和材料评价。
- [CRAG](https://arxiv.org/abs/2401.15884)：检索后的质量评价与纠正；其联网补充策略不能覆盖用户的禁止联网要求。
- [Semantic Router 校准](https://docs.aurelio.ai/docs/semantic-router/v1/get-started/quickstart)：原始相似度不是已校准概率，需要独立样本和无匹配场景。
- [DeepSeek 上下文缓存](https://api-docs.deepseek.com/guides/kv_cache)、[Anthropic 提示缓存](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching)：复用依赖有效前缀和服务商机制；本规格不固定服务商的价格、保留时间或命中率。
