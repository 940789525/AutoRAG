# 验收与对照评测

## 验证层级与证据

| 层级 | 验证内容 | 不能据此宣称 |
| --- | --- | --- |
| 文档自检 | 链接、需求追踪、JSON 模板、状态一致性 | 功能已经实现或性能提升 |
| fixture | 预设模型和工具输出，检查流程、拒绝、引用、调用次数 | 真实模型具备正确来源识别能力 |
| replay | 对冻结候选及分数复算门槛、投影 | 真实工具时延、实际 provider KV 命中 |
| local-live | 真实 Qwen embedding 与合成语料检索 | 云端回答质量和费用 |
| model-live | 当前产品模型真实工具选择、回答及 provider 用量 | 未测试模型/语言/语料的通用效果 |

所有场景结果使用 NOT_RUN、PASS、FAIL、SKIP。缺凭据、网络或原生存储的 lane 记 SKIP 并说明原因，发布所需 lane 未运行时结论为未完成，不能补一个成功值。

## 数据集与阈值选择

开发起点建议至少 240 个经人工复核的问题，按问题家族和来源文档划分开发、校准/验证、保留测试集；这不是足以证明所有线上情况的统计保证。种子集只用于明确合同，不能同时当作训练、调参及最终效果证明。

覆盖问候、常识、实时公共信息、明确本地、混合任务、指代追问、格式修改、全量/否定/例外、原生数据源、无答案与工具故障。困难负例包含“主题相似但对象/日期/数额不同”“旧招聘通知不能证明当前在招”“天气与气候论文”“不是本地某篇文档的通用定义”。

每个本地问题标注必需证据块或等价证据组、可接受来源、不得使用的干扰材料，以及是否需要多块联合回答。短段落的无上下文引用可能无法独立判定，应标为 uncertain 并人工复核，不强行二分类。

固定合成语料、检索参数和候选池采集 raw cosine。用校准集寻找低相关门槛，在验证集选择配置，冻结 profile/样本/阈值/hash，再运行保留集。阈值不能根据测试集结果反复修改；更换模型、profile 或评分定义后重新校准。

未支持组不得混入已支持组的成绩分母以夸大收益；同时报告 unsupported 候选和问题比例。分数无法在维持召回的同时减少干扰正文时，记录阈值方案不适用，不开放 enforce 默认。

## 四组对照

| 组别 | 首问策略 | 本地正文过滤 | 用途 |
| --- | --- | --- | --- |
| A | legacy | off | 当前行为基线 |
| B | on-demand | off | 单独观察取消预取和工具决策的影响 |
| C | legacy | enforce | 单独观察本地过滤的影响 |
| D | on-demand | enforce | 完整方案 |

另做 observe 回放检查决策，不把它当成正文已经省略。四组保持模型/provider、温度、工具配置、索引代、同一候选上限及合成数据一致；只改变表中的因素。保留 Jev 是否启用、校准版本等环境维度，避免把移除辅助请求误算成纯过滤收益。

真实模型每例建议至少 3 次独立运行，随机化组别次序；本地与公共问题分别汇总，避免大量简单问候掩盖本地问答退化。真实网络信息会变动，先用固定网页工具 fixture 检验流程，再用实际网络验证，并分开报告。

## 指标口径

| 指标 | 计算与解释 |
| --- | --- |
| 首问预取次数 | 第一次主模型 dispatch 前由 harness 发起的本地检索次数；on-demand 必须为 0 |
| 新正文数量 | 本轮首次进入 provider 输入的完整本地块数，与历史仍可见数量分开 |
| 无关正文注入率 | 标注无需本地证据的问题中，仍注入新的无关本地正文的问题比例；包含误工具调用 |
| 本地任务成功率 | 最终答案满足必要事实、来源与覆盖要求的本地问题比例，不能只看选择器正确率 |
| 必需证据保留率 | 实际召回的必需证据组中，最终视图至少保留一条等价证据或正确显式恢复的比例；另报检索本身召回率 |
| 正文削减量 | 相同问题组下比较最终请求新增正文 token；工具元数据、省略说明和历史正文另计 |
| 总模型调用 | 所有 scope 及失败/重试之和；分别列主模型、Jev、记忆、索引意图和其他辅助调用 |
| 输入与账单 | 分列未缓存输入、缓存读取、缓存写入、输出；按提供方口径避免把 cached input 重复相加；缺失值 null |
| 时延 | 总耗时、首个有用答案时延、主模型等待、本地检索、准入 CPU 耗时；分 P50/P95 |
| 前缀与缓存 | 客户端共同前缀长度/hash 与实际 provider cacheRead 独立报告，不能互相替代 |
| 质量与错误 | 误拒绝、幻觉、引用正确率、重复检索、unsupported、错误和 SKIP 分项列出 |

过滤器 CPU 只比较相同候选规模和硬件；100 个 1024 维候选可作为固定微基准。不得将 HTTP 等待、首次加载或模型 warmup 藏在另一个计时段后宣称低延迟。

## 发布门槛草案

以下数值是建议的工程门槛，不是实测结果。T-00 在看到保留集结果前冻结它们；修改必须记录理由、版本和新的独立测试集。

1. 确定性合同：全部适用 fixture/集成验收 PASS；原始错误、证据身份、权限、取消和最后可见性等硬性项不允许失败。
2. on-demand 的 harness 首问预取次数在所有普通问答测试中为 0；已冻结的天气/两类校招案例新本地正文为 0。开放语义集合的无关正文注入率目标不超过 5%，同时公布样本量和置信区间。
3. 支持分组的必需证据保留率至少 95%；本地任务成功率相对 A 下降不超过 2 个百分点；不得出现被总体平均掩盖的关键否定/例外证据丢失。
4. 质量比较报告配对差异及不确定性；小样本只能给出样本内结论。相关性分类准确率不能替代最终回答质量。
5. 费用和延迟每类都报告，不预设一定下降。默认切换前需对冻结业务权重下的总费用、P95 延迟和本地任务退化给出明确接受或拒绝结论；没有成本上限/样本权重和实际数据时保持 opt-in，不自动启用默认。
6. 实际缓存命中和未命中分别报告。热缓存测试不能用第一次冷请求失败或被取消的草稿冒充已建立缓存；未观测到命中时标记未证实。

不能通过把门槛调宽、丢掉困难例、只报告缓存命中比例或更换更强模型来使报告通过。

## 缓存实验

- 冷条件：独立会话、独立合成材料版本，记录服务商实际返回的缓存量；不能保证控制远端内部缓存，出现命中应如实归类。
- 热条件：同模型/系统/工具，在成功请求后复用准确前缀追加问题及工具结果；采样客户端投影和 provider usage。
- 重写对照：仅在隔离实验中删除/重排旧正文，度量可能的缓存损失；这不是首版产品策略。
- 日志中的 `cached` 高不代表费用最低。必须同时计算未缓存输入、输出、缓存写入和全部辅助请求；费率固定到评测日期和服务商，不能沿用过期价格。

## 隔离 QA 和项目检查

按 [AGENTS.md](../../AGENTS.md) 优先使用 Docker 的 QA 边界。进入 QA 的第一条 AutoRAG 命令前，使用同一 shell 的临时目录设置 AUTORAG_HOME 与 AUTORAG_CONFIG，确认配置路径在自己的 QA_ROOT 内。读取并记录真实配置 hash 前后是否一致，不修复真实配置。

live-E2E root 和 `.autorag-e2e` 必须属于本 clone；不挂载真实 HOME 或 native store 来消除 SKIP。模型调用仅用合成材料并遵循既有外发授权，凭据仅通过允许的环境/配置引用，报告不存值。embedding 仍用本地 FastEmbed，准备与安装是显式步骤，普通查询不能自行准备。

实现后至少运行：

```bash
bun run check && bun run lint && bun run typecheck
```

再运行覆盖首问、Jev、two-phase、search-followup、context-selection、evidence-read、memory、permission 和 CLI 配置的相关测试以及构建。根据实际改动评估完整套件和 Python contract；依赖/许可变化执行 supply-chain。review 并更新 fixed live-E2E 的冷/暖期望，受新策略影响的旧证据不能复用为新功能通过证明。

`bun run check` 含自动写入；若当次授权仅文档且禁止代码变动，在临时源码快照中执行这项检查，或明确记录未执行及原因，不能对工作区悄悄格式化。每个验证报告记录命令、exit、源码 hash、隔离目录/清理回执。只清理自己创建的目录和进程，不停止共享服务。
