# 按需检索与文本块准入需求规格

## 目标与范围

普通问答先由现有主模型选择信息来源，本地检索候选再经本地准入进入模型视图。首版覆盖 standalone API、CLI 和绑定 Pi 的 TUI，会话首问、后续轮次及 single/progressive 兼容行为。外部数据源继续由各自 CLI 或工具管理，不强迫迁移或中心化入库。

候选数量、通过准入数量、最终可见正文数量分别统计。正文被省略不等于候选不存在；服务错误不等于不相关；没有合格证据不等于能用常识回答。

## 功能要求

| ID | 必须满足的行为 |
| --- | --- |
| FR-01 | 按需模式的普通首问不得在第一次主模型请求前启动 baseline 本地预取；用户输入、必要历史和现有工具声明可进入请求。 |
| FR-02 | 主模型可以直接回答、调用网络工具、调用本地或指定数据源工具，或组合来源。问公共实时信息不自动等价于需要本地资料。 |
| FR-03 | 不新增必经独立意图分类模型。Jev 未配置、关闭、超时或返回无效决策时，普通问答进入工具可用的 agent，不能强制预取，也不能强制禁止一切工具后凭空回答。 |
| FR-04 | 保留自配置分支、索引意图处理、取消、steering、follow-up、MCP 工具及现有安全边界。任何新工具许可都不得由检索内容授予。 |
| FR-05 | 按需模式不自动注入新的检索记忆正文；需要时可显式调用 `check_memory`。现有会话历史保留规则另见 FR-13。 |
| FR-06 | 在 baseline（legacy 对照路径）及检索工具返回内容进入主模型前，对有可信身份和校准条件的本地候选执行同一准入规则；不能只改一种 formatter。 |
| FR-07 | 准入使用当前检索 query 对应的原始 cosine 及 embedding profile，不把 BM25、RRF、归一化排名或不同模型分数套用同一阈值。不重复向量化全部候选。 |
| FR-08 | 合格候选数可以为 0。记录“有候选但没有正文通过准入”，不得报成服务错误、检索为空或重新填入最高排名的无关正文。 |
| FR-09 | 缺少可靠分数、profile 或校准覆盖时，不以猜测分数做拒绝。首版明确记录 `unsupported`，沿用原有预算与读取机制；这些情况不计入过滤已覆盖场景。 |
| FR-10 | 准入、重排、去重和预算是独立阶段。已判不合格的自动候选不得被软预算、至少保留一条或 rerank 错误回退重新加入。真实工具失败继续保留原始错误。 |
| FR-11 | 原始检索 API、tool details、trace、原始 transcript 与证据 ledger 保持完整；只改变模型视图。引用 ID、来源和版本不得被重新分配或伪造。 |
| FR-12 | 当前已授权的显式原文读取可绕过自动候选相关性拒绝，但仍受范围、版本和容量检查。被省略正文不能登记为可见锚点；短引用必须指向实际可见完整正文。 |
| FR-13 | 正常追加只筛选新候选；不随每个新问题重写已发送历史。新会话不得继承旧会话正文。恢复、分叉、模型或权限变化按原生命周期重新验证可见性。 |
| FR-14 | 同一输入和校准版本的重试保持确定性；取消或派发失败不能提交“已发送”视图。最后一次容量保护后重新核验引用和最终可见数量。 |
| FR-15 | 记录工具决策、候选与准入数量、最终正文量、拒绝与降级原因、辅助调用及用量；测量点包含实际 provider dispatch，而不仅是原始日志。 |
| FR-16 | 缺省保留 legacy 行为。新策略、过滤 observation/enforcement 独立可控并可回滚；非法配置报明确错误，不静默转为“过滤已生效”。 |
| FR-17 | single 保持一次完整最终答案；progressive 若没有现成 baseline，不凭空生成无证据的快速答案再验证。具体兼容方案见设计，公共事件和引用合同仍须回归。 |
| FR-18 | 没有相关本地证据时允许澄清、如实报告不足，或在允许时使用网络；用户要求仅用本地、指定来源或禁止联网时不得扩大范围。 |

## 质量与运行约束

| ID | 约束 |
| --- | --- |
| NFR-01 | 首版不新增运行时依赖、本地模型服务或训练任务；不修改 Qwen embedding 后端、维度、索引存储和源文档。 |
| NFR-02 | 阈值绑定 profile、评分语义与校准样本版本。保留测试集不得参与阈值选择；无法证明足够召回时不开放 enforce 默认。 |
| NFR-03 | 不以缩小统一 topK、隐藏失败、降低输出质量或漏计辅助调用伪装 token 与性能收益。 |
| NFR-04 | 相同有效前缀与工具声明尽量稳定；不承诺服务商 KV 命中。权限收紧、必要配置变更和正确性优先于缓存。 |
| NFR-05 | QA 使用独立 home/config/workspace 和合成语料；不改维护者真实 home、其他服务和原生数据源。真实外发仍遵循 trusted-config opt-in。 |
| NFR-06 | 执行项目要求的 check、lint、typecheck、相关测试及受影响构建/QA。新依赖或许可变化另需审批和 supply-chain；SKIP 不算 PASS。 |
| NFR-07 | 模型工具选择和相似度过滤均可能误判；报告语义误触发、漏检和未支持比例，不能承诺任意问题零误判。 |

## 首版明确不包含

- 每轮全历史重新相关性排序、自动清空旧正文或额外的摘要模型。
- 本地 reranker 安装、独立意图模型、向量意图路由库、Self-RAG 微调。
- 原生数据源、网页、普通用户文字、助手回复、图片或显式 bash/read 正文的统一相似度过滤。
- 仅凭相似度证明答案充分，或者把“不相关”当作数据源不可用。
- 自动改变日常配置、模型凭据、默认 embedding 或当前运行容器。

跨话题后旧块仍在历史，是首版已知边界；本方案不以新预取为零来声称整份请求的本地正文为零。若以后要求每轮严格清除，必须另写上下文重建与缓存损失规格。
