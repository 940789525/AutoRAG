# 开发前置说明

## 目标与使用场景

用户围绕一个研究问题选择少量本地论文，按明确维度整理事实、核查原文、判断结果是否可比，最后形成可持续修订的研究决策。项目可以用于方法选型、文献比较和复现准备。

终端 RAG 继续承担即时检索和问答；Research 保存项目、逐项事实、人工判断和成果版本。网页的作用是减少查原文、抄录结果和反复核对条件的成本。

## 本轮授权与禁止事项

本轮仅写文档，不执行代码实现、依赖安装、数据库迁移、容器重建或模型调用。保留现有分支和工作区改动，不提交他人的改动，不创建 git worktree。

后续实现必须遵守：

1. 不改变主系统的问答提示词、检索链路、默认模型、embedding backend、CLI/MCP 输出和已有启动行为来适配 Research。
2. 新版 Research 的功能开发在独立工程进行，不把 React、Worker 或数据库依赖继续加入主系统根工程。
3. 主系统配置、索引、记忆、会话以及维护者真实的 `~/.autorag` 不作为 Research 的可写路径。
4. 原论文目录只读；所有解析缓存、审阅记录、导出和临时文件写入 Research 专属目录。
5. 不默认连接、启动、停止主系统的 MinSync 或其他推理服务，不扫描全库作为首次使用前置条件。
6. 不自动执行论文附带的陌生代码，不默认联网搜索或发送论文正文给远端模型。
7. 旧 Research 的清理和数据迁移独立规划，不能覆盖现有数据库来“初始化新版”。

这些约束属于需求。若实现发现无法满足，应先记录冲突及替代方案，不能静默放宽边界。目标工程对依赖、许可证或敏感配置有明确审批要求时沿用；已经取得的用户授权不重复询问。

## 当前实现与新版目标

现有实现可以参考 `/workspace/src/research`、`/workspace/test/research` 和 `/workspace/docs/research-inbox.md`。它已有文件指纹、论文资产、阅读任务、结构化输出、恢复、幂等和事件流。

现有根 package.json 仍包含 Research 依赖和构建入口；runtime 直接引用主系统配置、索引与模型解析；API 与 Worker 在同一进程启动。新版的独立工程、网页、逐格修订和决策版本均需实现，不能描述为现有能力。

## 术语

| 名称 | 含义 |
| --- | --- |
| Paper | 论文作品身份，标题相同不代表同一作品 |
| Asset | 一份具体 PDF 字节版本，绑定 SHA-256 |
| Parsed revision | 某 asset 经指定解析器版本生成的不可变文本版本 |
| Project revision | 问题、约束、论文集合和维度组成的不可变研究输入快照 |
| Cell revision | 一个论文与一个维度对应的事实建议版本 |
| Review | 用户对事实建议的确认、修正或拒绝，保留历史 |
| Assessment | 基于明确证据与条件进行的比较判断 |
| Memorandum | 基于输入快照生成和导出的决策备忘录；首版通过修改上游输入并生成新草稿修订，不直接编辑正文 |
| Run | 一次有界后台任务；与 Pi 会话、成果版本分开管理 |

## 交付边界

首版单机单用户、一个受信配置的本地 PDF 库；项目最多 10 篇论文、8 个维度，常用首轮为 3—5 篇、5—8 个维度。只处理能可靠提取文本的 PDF；表格、扫描件不可靠时显式标记，不将 OCR 或视觉理解作为首版必选依赖。

完整 MVP 包含：独立运行、比较矩阵、文本证据定位、人工修订、条件核验、备忘录、一次手动增量更新、导出及恢复测试。精确 PDF 高亮、全库搜索、论文订阅、多人协作和自动实验执行延后。

## 不影响主系统的承诺范围

功能不依赖和故障不传播是硬性验收项。共享机器上的磁盘、网络和硬件资源无法仅靠拆进程保证零波动，需要实际限额和测量；严格独立的推理性能需要独立计算或服务容量。未经测量不得声称“完全零开销”。

## SDD 执行规则

需求使用 `FR-*`、约束使用 `NFR-*`，任务使用 `T-*`，验收使用 `AC-*`。一个任务完成需要实现、相关验证和证据，而不只是勾选代码文件。所有评测结果标明模式：`fixture`、`replay` 或 `live`，示例回放不能冒充真实模型推理。
