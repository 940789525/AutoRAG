# 需求规格与 MVP

## 用户故事与范围

主要用户是维护本地论文库、需要比较方法并做选型或复现准备的开发者。典型输入是一个研究问题、个人约束、三篇以上论文和若干比较维度；输出是经过核查的比较成果，而非另一条临时聊天回答。

完整 MVP 的 P0 如下。P0 必须完成，才能将整体称为“已实现的 Research 工作台”。

| 编号 | 需求 | 优先级 | 可观察结果 |
| --- | --- | --- | --- |
| FR-01 | 创建研究项目及输入版本 | P0 | 问题、约束、asset 集合、维度保存后可重新打开 |
| FR-02 | 从只读库选择论文，按字节版本去重 | P0 | 同文件重复登记返回相同 asset；同标题不自动合并 |
| FR-03 | 按所选论文解析和缓存 | P0 | 不等待整库索引；单篇失败不删除其他论文成果 |
| FR-04 | 生成有证据的比较矩阵 | P0 | 已报告事实可追溯；缺失、解析失败与生成失败分开显示 |
| FR-05 | 核验比较条件 | P0 | 数据集、度量或设置不同不自动得出优劣排名 |
| FR-06 | 确认、修正与拒绝事实建议 | P0 | 保留原建议与用户记录；重跑不覆盖人工确认值 |
| FR-07 | 有界异步任务与恢复 | P0 | 幂等提交、阶段状态、取消、显式重试和中断恢复 |
| FR-08 | 生成可追溯备忘录 | P0 | 推荐、理由、未知项、下一步实验均关联输入版本 |
| FR-09 | 手动新增论文与局部更新 | P0 | 新论文触发相关结果重算，旧结论保留并形成待确认修改 |
| FR-10 | CSV 与 Markdown 导出 | P0 | 矩阵导出 CSV，备忘录导出 Markdown，保留证据定位 |
| FR-11 | 前端状态与事件恢复 | P0 | 刷新、断线或 Worker 离线后仍可重取真实状态 |
| FR-12 | 可明确识别的演示样本模式 | P1 | 样例结果标记 fixture/replay，不伪装成 live |

## 功能细则

FR-01：维度包含稳定 ID、名称、类型与说明。类型首版限制为文本、数值及条件描述，不提供任意公式或 SQL。问题、约束、论文集合或维度变化都创建新 project revision，同时建立新的 matrix snapshot；重新分析前也必须明确显示新输入下的待生成、可复用与过时项。历史矩阵可按 matrixVersion 精确读取。

FR-02：首版通过服务器列出的文件 ID 选择 PDF，不提供任意路径输入或浏览器上传。资产 ID 与文件路径分开；相同字节可以有多个只读位置。DOI/arXiv 身份只在可信元数据或人工确认时关联，不按模糊标题合并。

FR-04：每个单元格可处于 `reported`、`not_reported`、`unreliable_parse` 或 `insufficient_evidence`。后台任务失败不是 `not_reported`。模型声称“未报告”也必须带宿主校验的阅读覆盖说明，局部阅读通常只能给出证据不足；模型不能自报完整阅读绕过宿主记录。成果适用性与 valueState 分开显示。

FR-05：判断限定为 `comparable`、`different_conditions`、`insufficient_evidence`；“可比”只指显式列出的 2—10 篇论文、指定指标维度版本与已列条件，不代表方法整体优劣。未报告的关键设置应阻止肯定可比结论。输入事实被更正或拒绝后，依赖旧输入的比较立即标记过时，显式 repair 后才重新计算。

FR-06：修订区分“更正论文事实”和“用户研究判断”。更正事实需要证据，用户可以从模型未读取的原文段落选区登记新证据；用户判断可无原文支持，但必须显式标记。所有编辑携带版本条件。

FR-07：网络重试不产生新任务；成功任务通过显式 rerun 创建新 generation，失败/取消通过 retry 恢复，过时任务需要按当前输入提交。阶段成果落库必须防止“已提交但尚未记下恢复点”后的重复发布，不能只靠 workflow ID 去重。

FR-08：未确认的事实可以进入草稿，但必须标记；定稿前展示仍未解决的缺口。首版修订通过上游事实/判断或项目输入变更、关联 baseId 生成新草稿并人工接受，不提供正文手工编辑器。生成和接受新版本分开，模型不能自行覆盖已确认备忘录；接受时同时校验草稿和项目定稿指针版本。

FR-09：新增论文入口创建 project revision 后，由用户显式提交分析。首版不监听整个库自动消耗模型预算。修改问题或维度可能使全部项目相关结果失效；只有真实输入依赖不变的结果才复用。

## 非功能约束

| 编号 | 要求 |
| --- | --- |
| NFR-01 | 代码、依赖、启动、数据与资源隔离，主系统可独立运行 |
| NFR-02 | 受信配置控制根目录和远端处理许可；论文为不可信数据，凭据不进入浏览器或仓库 |
| NFR-03 | 有并发、大小、时间和模型预算；记录首次可用时间及主 RAG 性能回归 |
| NFR-04 | 每个任务有请求 ID、冻结输入、版本、阶段耗时、用量与底层错误 |
| NFR-05 | 桌面网页操作可达，键盘可定位单元格，状态不只依赖颜色 |

## MVP 分段

- M0：确认目录与版本兼容，建立隔离基线，不写主系统核心。
- M1：独立 API、Worker、数据库和契约，使用受控样本走通任务。
- M2：一篇真实论文的解析、证据、页面阅读和人工更正。
- M3：多论文矩阵、条件核验、版本并发控制。
- M4：备忘录、导出、新增论文的局部更新与修改审阅。
- M5：恢复、隔离、性能与模型质量验收，形成演示证据。

M2 是最小纵向切片，不是最终 MVP。外部论文订阅、通用聊天、多用户、知识图谱数据库、自动运行论文代码均不进入 M0—M5。

## 总体验收场景

给定一个只读目录内三篇可解析 PDF，用户创建项目并完成矩阵；能核对一条事实、识别一组不可比条件、更正一个单元格、导出备忘录，再加入第四篇论文并审阅修改建议。期间中断 Worker 后可恢复已提交阶段，主系统的配置与索引不发生非预期写入。
