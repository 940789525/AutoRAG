# 部署迁移与运行

本文描述后续运行要求，不提供已存在命令的保证。本轮没有创建镜像、修改 Compose、开端口或迁移数据库。

## 三类路径

| 路径 | 作用 |
| --- | --- |
| /workspace/myself_dev/1027_research | 当前开发容器可见的规格文档，仅用于阅读 |
| /research-app | 拟在新版专用容器挂载的独立工程源码；不是主系统 /workspace |
| /research-data | 新版专属解析缓存、导出和临时目录，使用独立卷 |
| /papers | 新版容器看到的 PDF 目录，只读挂载 |

宿主机独立工程的默认提案和权限核实见 02。文档不能因为在 /workspace 可见，就被误当成已创建了新版工程。

## 运行组件

- research-api：提供生产网页、JSON API、SSE、文件读取；无模型凭据。
- research-worker：DBOS、PDF 解析、受限 Pi；可写专属缓存，/papers 只读。
- research-db：专用 PostgreSQL 实例、数据卷和角色，端口仅在 Research 私有网络访问。
- migrate：一次性迁移入口，版本兼容检查通过后 API/Worker 才运行。

生产只发布网页/API 的本机端口；开发使用 VS Code 或宿主端口转发。容器之间使用服务 DNS，Windows 浏览器里的 localhost 与容器 loopback 不能混淆。端口由目标环境选择空闲值，不占用旧 Research 的 8765 或现有数据库端口。

## 可信配置

拟配置项包含：schemaVersion、libraryRoot、stateRoot、databaseUrlEnv、databasePasswordFileEnv 可选、modelProvider/modelId、modelCredentialEnv 或受支持的凭据引用、allowModelProcessing、allowedHosts、allowedOrigins、resourceLimits、预算、mode、workflowVersion。

配置只保留环境变量/密钥文件等引用，不硬编码 URL 密码或 token，不把密钥传到浏览器、argv 或示例文件。API 与 Worker 分别获得最小需要的配置，模型授权默认 false，fixture 模式默认不访问真实模型。

不默认读取主系统 AUTORAG_CONFIG、AUTORAG_HOME、全局 Pi 扩展和 sessions。若复用同一提供商账户，应显式配置引用，并说明可能共享额度；不把维护者可写 auth 文件挂入新版。

正文是否可发送远端由可信配置明确授权。已有旧 Research 的 true 值不自动复制为新版默认许可。此规则不阻止用户明确授权后继续开发或测试。

## 资源预检

记录 API、Worker、数据库三者总预算，必须为主系统和宿主保留余量。配置 CPU、memory、pids 和日志轮转，观察限额是否在目标 Docker/内核实际生效。不能只设置软 shares 后称为硬 CPU 上限，也不能靠禁用 OOM killer 保护主系统。

首版不启动 embedding 服务，Worker 并发按 05。文件大小、页数、解析时间、模型预算超限均显式失败或留缺口。内存压力时宁可让新版任务失败并恢复，不让宿主无限 swap。

## 实施后启动顺序

1. 核对 mount：/papers 为只读，/research-data 属于新版，未挂主系统状态卷。
2. 启动专用数据库，执行目标版本迁移并核对 schema。
3. 先启动 API，检查 live/ready、协议版本和网页。
4. 启动 Worker，检查心跳与已注册队列/工作流版本。
5. 用 fixture 项目做一轮不调用模型的冒烟测试。
6. 在获准的 trusted-config 和预算下执行一篇 live 论文，核对原文和错误处理。
7. 完成隔离验证后再开展多篇测试。

未来脚本需要提供这些入口，但具体脚本名在 T-01 创建后记录，不能现在声称 `bun run ...` 已可执行。

## 旧 Research 的迁用与迁移

优先迁用业务代码与测试设计，新建数据库，不直接对旧 research/research_dbos schema 升级。原数据库仍属于旧服务，不停止它或覆盖其状态。

需要导入旧数据时：先备份旧业务 schema、DBOS schema、缓存和版本信息；默认只导入可验证的论文身份与阅读成果，标记 imported provenance。不要把旧运行中的 workflow 直接解释为新版本任务，也不把旧卡片的反馈自动等同于新版逐格人工确认。

迁移脚本先在副本中验证，支持 dry-run、计数/摘要核对与错误报告；目标数据幂等，不修改原文。旧启动配置与依赖清理另行批准范围并回归，不顺带删掉现有用户工作。

## 发布与回滚

每版记录应用版本、specVersion、schema 兼容范围、workflowVersion、模型/解析/提示 schema 版本。API 发现不兼容版本拒绝写入；Worker 不领取不兼容 workflow。

首个新版迁移与 contracts 以 research-spec-v1.1 为基线，包含 run_outputs、read_observations、项目 edit_version、精确矩阵快照及比较 scope/依赖字段。它们目前只是规格，不代表已有可执行迁移。业务成果、output ledger 与覆盖记录必须一并备份恢复；不能清空 ledger 后重放任务，或丢失覆盖记录后仍声称完整阅读。

MVP 先保证同一版本重启恢复。工作流代码变更时，采用兼容迁移、排空旧任务或显式新 generation 重新执行；不能直接删除 DBOS 系统表。具体 appVersion/队列路由能力由 T-00 验证。

应用回滚只切换 Research 镜像，不操作主系统。schema 不兼容时停止回滚，使用已验证的兼容版本或恢复到新的专用卷，不能随意执行破坏性 down migration。

## 备份与恢复

同时保存业务 schema、DBOS schema、解析/导出缓存 manifest、应用版本、配置引用和源文件 hash 清单；凭据不打进公开备份。原始 PDF 保持原位置，恢复后重新验证其可读性与 hash。

恢复演练在新库、新卷中进行，先只启动 API 读取历史，Worker 保持停止且 live 模型禁用，防止恢复时自动消费待运行任务。核对成果与证据后，才在明确配置和预算下恢复调度。原卷保留，恢复结果不覆盖旧库。

## 手工 QA 边界

主系统 QA 遵守现有 AGENTS：独立临时 AUTORAG_HOME 和 AUTORAG_CONFIG，不以 --workspace 代替隔离；不动维护者真实 home 或其他 clone 的服务。新版 QA 使用自己的测试库和卷，测试之前验证名称与目标路径。

测试完成只清理本次创建的资源，保留证据和清理回执。不得以清理为由删除主系统、旧 Research 的卷、论文目录或共享模型缓存。
