# 前端交互规格

## 设计原则

默认中文桌面工作台，围绕“选论文—比较—查原文—修正—形成决策”组织。页面直接显示业务对象与操作，默认不展示 SDK、数据库或提示词配置。任务日志作为展开查看的诊断信息，不能替代成果界面。

## 页面与导航

| 路由 | 页面职责 |
| --- | --- |
| /projects | 项目入口，创建项目，显示最近成果与真实任务状态 |
| /projects/:id/setup | 问题、个人约束、论文选择与比较维度编辑 |
| /projects/:id/workbench | 比较矩阵、原文审阅、比较条件和任务抽屉 |
| /projects/:id/memoranda | 草稿、定稿、历史和待接受修改 |
| /runs/:id | 可直接打开的任务详情，刷新后能恢复 |

证据审阅面板在 workbench 内，通过 cellId/evidenceId 查询参数定位，复制链接可恢复选中项。首版不开发复杂通用聊天页。

## 主布局

```text
┌────────────────────────────────────────────────────────────┐
│ 项目名   问题摘要   当前版本   分析所选论文   导出           │
├─────────────┬────────────────────────┬─────────────────────┤
│ 项目导航    │ 比较矩阵               │ 证据审阅            │
│ 论文 4/10   │ 行：论文               │ 抽取结果/人工值     │
│ 维度 6/8    │ 列：比较维度           │ 原文及上下文        │
│ 待审阅 8    │ 单元格：值+状态        │ 来源有效性          │
│ 比较条件    │ 过滤缺口/查看差异      │ 确认 更正 拒绝      │
├─────────────┴────────────────────────┴─────────────────────┤
│ 任务：已解析 2/4 篇，正在抽取第 3 篇   查看详情  取消       │
└────────────────────────────────────────────────────────────┘
```

桌面宽度不足时证据面板切换为抽屉，不挤压到表格不可读。键盘可在单元格之间移动、打开和关闭审阅面板；每个状态有文本标签，不只用颜色。

## 创建与选择论文

项目可先保存问题、约束和维度。候选论文来自受信本地库，展示相对文件名、大小与登记状态；选择后登记为后台任务，完成后获得 asset ID，再将 asset 加入项目版本。

未完成登记的项目不能发起依赖该资产的研读；页面解释“正在登记/文件仍在写入/不是可解析 PDF/超限”。不会因为一个文件失败就清空已选择论文。

问题和维度编辑保存时显示将创建新研究版本。保存成功后立即打开新矩阵快照，分别展示保留成果、过时成果和待生成格子，不把旧矩阵当成新输入的结果。保存中禁用重复按钮，但仍使用服务器幂等键处理网络重试；不能仅依靠按钮防重。

远端处理未获可信配置许可时，页面允许整理库和查看已有成果，但研读操作解释权限状态；不提供能绕过配置的一键授权开关。

## 矩阵与审阅

单元格展示简短事实、报告/缺失/解析不可靠/证据不足状态，以及未审阅/已确认/已修正/已拒绝标记。后台生成失败使用单独错误标记和重试入口，不伪装成论文未报告。

点击后右侧展示当前 AI 建议、有效人工值、引用原文和覆盖说明。支持：

- 确认：接受当前建议，记录具体建议版本。
- 更正论文事实：填写更正值并选择原文证据；现有证据不足时，在解析文本中选区，经服务端登记后取得 evidence ID，不受模型已读范围限制。
- 添加用户判断：显式标记为个人研究判断，不冒充论文原文事实。
- 拒绝：保留旧建议并说明原因，不删除历史。

重跑产生新建议时，人工值继续显示，新建议标为待审阅。源文件改变时，历史值标为来源已变化，不能仍显示绿色“已验证”。

阅读覆盖展示宿主计算的已读/未读范围、解析缺口和主张范围；not_reported 使用“在所示范围未报告”等准确标签，不把局部覆盖写成全文核验。人工选区不增加模型阅读覆盖率。

编辑遇到 412 时保留本地未提交文本，展示服务器新版本，由用户比较后重新提交；禁止前端自动覆盖较新值。断网时不显示“保存成功”。

## 原文阅读

首先保证解析文本证据的精确区间与上下文可读，PDF 在相邻标签页预览。pageHint/bbox 可信时才跳页或高亮；没有映射时解释“当前定位到解析文本”，不提供假精确位置。

PDF 读取失败时仍可显示带历史标记的已保存文本证据；注明原始文件缺失或版本不一致。不得展示路径输入框让浏览器访问任意本地文件。

## 比较条件、备忘录与增量

条件面板显式列出参与论文、指标维度版本和条件，展示 comparable/different_conditions/insufficient_evidence 及各方证据。全组结论不能只展示其中两篇的证据。“不同条件”不渲染为论文质量差或真假判断。用户更正/拒绝事实后，立即重取矩阵和比较，依赖旧值的结论显示“过时，待重新核验”，不继续展示为当前可比；用户显式 repair 才消耗预算。

备忘录展示建议、理由、适用约束、未知项和下一步实验。草稿、已接受、过时明确区分；未确认输入的摘要可展开。用户接受新版本后才替换定稿指针。

首版没有正文手工编辑器。修订入口引导用户更正上游事实/判断或项目输入，再关联原备忘录生成新草稿并比较差异。接受时提交页面读取的 expectedProjectETag 和草稿 If-Match；412 保留用户正在审阅的草稿，展示当前定稿并由用户重新决定，不能自动覆盖另一标签页的新定稿。

新增第四篇论文后，页面提示创建项目版本并分析新增行。更新中心分别展示新事实、受影响的比较、备忘录修改建议；旧成果继续可读。不能将整个新报告直接覆盖旧报告后只显示“已更新”。

历史矩阵链接携带 matrixVersion，按快照显示精确的事实、review 和比较版本，并固定显示“历史，只读”；不能通过当前 cell 查询替换历史值。需要编辑时切回当前输入并重新读取 ETag。

成功任务的“重新分析/重新生成”说明将再次使用模型预算，显式发送 rerun=true 和新幂等键；网络重发沿用原键。失败/取消显示 retry，过时任务引导分析当前输入，不提供会反复执行旧快照的重试按钮。

## 任务和异常状态

| 状态 | 界面行为 |
| --- | --- |
| 空项目 | 指引选择论文与维度，不空白等待 |
| queued | 显示已接受、排队时间和 Worker 是否在线 |
| running | 显示真实 phase 和已完成单位，不估算模型进度百分比 |
| 正在取消 | 表示持久请求已提交，直到终态确认；不立即假装完成 |
| failed | 保留已有行，显示底层错误和局部重试入口 |
| superseded | 解释研究输入发生变化，提供新版本分析入口 |
| SSE 断开 | 显示重连中，重取快照；不清空已完成成果 |
| Worker 离线 | 可浏览成果，待运行任务显示等待原因 |
| 数据库/API 不可用 | 展示连接错误与重试，不能把缓存假装为已保存新状态 |

## 前端状态实现

TanStack Query 管理 project、matrix、cell、run、memoranda 查询；键包含项目/输入版本。SSE 只触发对应资源失效与重取，按事件 ID 去重。项目修改后重新读取输入，不能继续提交旧 revision。

编辑首版采用服务器确认后更新的方式，不优先做复杂乐观合并。浏览器关闭仅断流，显式取消才影响任务。保留 `requestId` 便于诊断，不把模型凭据或完整提示写入 localStorage。

## 前端验收

完成真实服务的创建、登记、研读、查证、更正、冲突恢复、导出和增量流程；另外覆盖空态、解析失败、Worker 离线和 SSE 断线。fixture 模式固定显示“示例数据”，不能用回放延迟冒充模型性能。
