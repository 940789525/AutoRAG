## T-00 前置核验

1. 阅读全部规格，记录 `research-spec-v1.1`、当前代码与旧实现参考版本。
2. 明确独立工程路径、来源挂载、数据卷和专属端口；有授权/挂载限制先解决，不绕过隔离要求。
3. 记录主系统 tracked diff 摘要及受保护配置/代码/状态摘要，保留现有改动。动态写入的会话文件需要区分维护者正常活动，不能将其删除来获得“干净基线”。
4. 在临时专属环境验证：Pi 禁止资源发现、工具提交、abort、usage；DBOS API/Worker 分离与稳定 ID；PDF 页块和 UTF-16 区间。只用合成或获准公开夹具，不触碰真实 home。
5. 确认精确依赖、许可证、原生构建和浏览器 E2E 工具。遵循目标工程有效的依赖审批规则，已有授权不重复请求。

退出条件：兼容性结论和失败原因均落盘，不能只有“安装成功”。当前本轮未执行这些实验。

## T-01 独立骨架

建立 02 中的模块布局。contracts 先定义 Run、Cell、Evidence、错误、事件和版本；TypeBox 生成 OpenAPI/类型，加入契约快照验证。建立独立只读 check、lint、typecheck、build 脚本，不能调用主系统的格式化命令修改现有工作区。

API 提供健康检查和静态网页壳，Worker 独立启动；生产三个容器。先证明 AutoRAG 关闭时 Research 可展示健康状态，Research 关闭时主系统不需要它。

## T-02 数据

将 03 的逻辑模型落实成版本迁移和约束，先实现项目版本、单元格建议/人工记录、run、事件和幂等；比较与备忘录表可以随后添加，但必须迁移兼容。

使用真实临时 PostgreSQL 验证并发重复提交、If-Match 冲突、跨项目引用拒绝和状态/事件同事务。不要用内存 mock 替代这些一致性测试。

实现项目 PATCH 同事务创建新矩阵快照、按 matrixVersion 历史投影、dependency_digest 与 applicability；加入 run_outputs 唯一键及业务成果/事件原子提交。冻结迁移前验证 AC-20/21/22 涉及的数据约束与仓储事务；实际 DBOS 跨进程恢复在 T-03 完成，不能把 workflow ID 当作成果幂等证明。

## T-03 异步流程

先用确定性测试阶段模拟慢任务，完成 pending 派发、稳定 workflow ID、租约回收、事件推送和快照。测试“事务提交后尚未派发”“已入队尚未标记”“执行完成尚未发布”的中断窗口。

实现取消标志、跨进程轮询、AbortSignal、发布前检查和显式新 generation 重试。API 只用任务客户端/仓储，不导入 Worker 或模型运行时。

落实 03 的提交状态表：成功 rerun、失败/取消 retry、过时输入拒绝以及活动后继复用。补测“成果已提交但 DBOS 恢复点未记下”的窗口，确认恢复不重复 revision、事件或 matrix version（AC-21/22）。

## T-04 登记解析

通过 fileId 选择而不是任意路径，真实路径和 symlink 解析后验证根边界。Worker 稳定观察、流式 hash、PDF 有效性/大小检查，生成 asset 和不可变解析缓存。双位置同字节去重，单位置内容改变生成新 asset。

先生成简单可解析 PDF 测试 Unicode、断行和证据偏移，再测试获准的真实论文。首版不复制整库，不调用主系统 refresh，不要求先有向量索引。

提供按 parsedRevisionId 和全局 UTF-16 区间读取文本、人工登记证据的 API；宿主切片 quote 并复核 asset 归属，不能要求该段原文预先被模型读取（AC-24）。

## T-05 单篇切片

按“创建项目—选择一篇—登记—任务—单行矩阵—点击证据—人工更正”完成纵向流程。页面连接真实 API、真实数据库和任务服务，模型部分暂用清晰标记的 fixture。此时先发现交互与契约问题，再投入完整研读。

退出条件：刷新后成果与编辑还在；重试网络请求不重复保存；原文缺失时界面有正确状态。

## T-06 受限 Pi

用固定版本 SDK 重建受限适配器，移除旧 reader 对主工程 profile 的 import。先 evidence pack 结构化提交，再补 list_sections/read_section/find_evidence。数据、权限和模型配置由宿主控制。

加入原文区间验证、语义支持状态、缺失值和预算。模拟 provider 验证协议，获准 live 小样验证真实输出；真实失败保留，不能用固定结果掩盖。

宿主冻结阅读覆盖计划，记录实际模型交付区间并计算 coverage；测试截断、分页、未命中搜索和伪造 complete 的情况，未覆盖不能输出 not_reported（AC-25）。复核阶段成果恢复不会绕过覆盖记录和预算。

## T-07 比较与人工修订

扩展到 3—5 篇，逐篇成果可见。对指定指标核对条件，保存实际使用的事实与 review。完善重跑新建议与人工值并存、输入失效、编辑冲突及待补证操作。

退出条件：能展示一个条件不同和一个证据不足的案例，不能只展示全部可比的成功样例。

比较 scope 显式包含参与 asset 集合和指标维度版本。用户修订后在同事务使依赖比较过时；发布比较检查实际 cell/review 输入向量。补测同 revision 内的并行修复与人工更正竞争，迟到结果不能成为当前结论（AC-23）。

## T-08/T-09 决策闭环

根据冻结 matrix version 生成草稿，用户接受后形成定稿。新增第四篇建立新项目版本，复用仍有效的旧事实，生成新事实和受影响的比较/备忘录建议。查询依赖不变才复用，不能仅按论文 hash 缓存全部答案。

实现版本差异和用户接受操作，CSV 安全格式化与 Markdown 引用导出。导出已有成果不再调用模型。完整处理空态、超限、失败、断线和 Worker 离线。

备忘录修订采用上游更正后关联 baseId 重新生成，不扩展正文编辑器。接受操作在项目锁内同时检查草稿 If-Match 与 expectedProjectETag；两个标签页接受不同草稿只有一个成功（AC-26）。历史矩阵与其导出必须保持精确版本一致（AC-20）。

## T-10/T-11 收尾

按 08 执行恢复、隔离和性能实验；在专用 fixture 库演练备份恢复与版本回滚。模型质量采用独立标注样本，不把单元测试数当准确率。

演示记录区分 fixture/replay/live；简历只列已实现并有证据的内容。任何未达标项保留为失败/未验证，不因时间不足改为通过。
