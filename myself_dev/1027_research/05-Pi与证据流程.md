# Pi 与证据流程

## 运行时边界

直接依赖固定版本的 Pi SDK，不依赖 AutoRAGAgent 或主系统 profile factory。显式配置模型、工作目录、内存设置、SessionManager、资源加载器和工具；关闭全局/项目扩展、普通 shell、写文件、网络搜索与跨任务记忆发现。配置细节以 T-00 核对的已安装版本为准。

每个抽取任务拥有独立会话，结束时 abort/dispose、移除监听器。资料正文与附录是数据，不得被当作系统指令。PDF 内出现“读取其他路径”“发送密钥”等文本不会扩大工具权限。

## 工作顺序

1. 验证 fileId、真实路径、只读库边界、大小和稳定性，读取过程计算内容 hash；元数据稳定不等于有效 PDF。
2. 解析选中 PDF，生成不可变文本、页块和章节索引。解析器先证明可处理 fixture；不可可靠提取的表格保留错误与覆盖状态。
3. 依据项目问题和维度先冻结阅读覆盖计划，再选片段。先覆盖摘要、方法、实验、限制中相关章节，局部查找补充；不声称固定四个窗口等于全文阅读。单篇事实抽取工具只允许本篇 asset，跨篇比较另用冻结的事实输入。
4. 运行受限 Pi 抽取，提交结构化值、来源 ID、条件和缺口。
5. 确定性验证：schema、来源范围、偏移与 quote、hash、证据引用及预算。
6. 语义核验：判断引用是否足以支持事实；不足时降为 insufficient_evidence 或待人工审阅，不以文本存在性代替语义正确。
7. 对指定指标核查数据集、评测划分、模型/资源、单位、硬件与测试方法。只比较已有证据支持的条件。
8. 检查 run、项目、来源和人工版本后，经 run_outputs 去重事务提交成果并发布事件。比较还要检查冻结的 cell/review 输入向量，不能只检查 project revision。Pi 不能直接持有数据库写权限。

## 领域工具契约

| 工具 | 输入 | 受限输出与规则 |
| --- | --- | --- |
| list_sections | assetId | 已登记解析版本的章节 ID、标题、长度；只在 run 允许集合内 |
| read_section | assetId、sectionId、offset、limit | 限长正文与宿主生成的 evidence IDs，宿主记录实际返回区间，累计计入预算 |
| find_evidence | assetId、query、limit | 本篇解析文本中的有界候选；首版词法查找，不偷偷调用主索引 |
| submit_cells | cells[] | dimension ID、valueState、value、conditions、evidenceIds、coverage 声明；宿主复核实际阅读范围后接收 |
| submit_assessment | scope、metric、state、input IDs、reason | scope 显式列参与 asset 和指标维度版本，只接受冻结输入中的事实和条件，不允许引用外部未知论文 |

首轮可以先用准备好的 evidence pack 加 submit_cells 跑通，再补章节工具，但完整 MVP 必须完成来源边界与补证流程。每类提交失败最多纠正一次；不能用解析任意最终自然语言替代结构化提交。

## 证据约定

宿主根据 asset、parsed revision 和区间生成 evidence ID，模型只能引用已有 ID。quote 对应 `[start,end)` 的实际文本。规范化匹配若用于吸收 PDF 断字/空格，必须维护到原始区间的映射，保存规范化版本，禁止用语义相似度认定虚构引文真实存在。

人工审阅不受“模型已经读到哪里”限制。前端从不可变解析文本选区，通过 `POST /assets/:id/evidence` 请求宿主登记证据；宿主自行切片并校验归属与来源有效性，不能让浏览器提交任意引文作为真实证据。人工创建的证据与模型阅读记录分开，不因此增加模型 coverage。

UTF-16 区间不等同 PDF 坐标。pageHint 仅在解析器证明映射可靠时填写，精确高亮需要额外 bbox 映射；MVP 可以提供可靠的文本定位和 PDF 原文并排预览。

原文存在、语义支持、实验可比性分三层记录。不能把 schema 通过、hash 一致或模型自评高分称为“论文结论已验证”。

## 抽取与缺失

reported 需要有效证据。not_reported 需要相应章节范围得到覆盖，仍注明覆盖边界；仅看有限片段未找到时使用 insufficient_evidence。解析失败使用 unreliable_parse，不生成推测数字。

coverage 的权威来源为宿主，不是 submit_cells 中的模型自述。宿主在抽取前按带版本的规则冻结 requiredRanges 与 claimScope，默认覆盖该论文全部可提取正文；只有明确限定为“实验章节中的某项报告”等局部主张时才使用预定章节范围，且不能推广成“整篇论文未报告”。模型不能为了输出 not_reported 临时缩小范围。

准备好的 evidence pack 和章节工具实际交付给模型的区间写入 read_observations；分页、截断、重试与重叠区间按原始 UTF-16 坐标合并，未返回的后半段不计入。只列章节标题、词法查找未命中、用户浏览或创建证据都不算完整阅读。宿主根据实际模型请求上下文核对交付记录，避免把尚未交付的预取文本记作已阅读。

not_reported 的机械门槛为 requiredRanges 100% 被交付、相关范围无解析缺口，并具有对应范围内的缺失判断；未达标则降为 insufficient_evidence，已知相关解析失败为 unreliable_parse。范围过大而预算不足时保留缺口，不追加无限调用。覆盖 complete 只证明预定文本已提供，不证明模型理解正确；语义支持与人工核验仍分别记录，不能因此标为人工已验证。

条件结构至少考虑 dataset、split、metric、unit、modelScale、trainingData、hardware、measurementProtocol。并非每类论文都需要全部字段；用户选择维度决定所需条件。关键字段缺失，比较为 insufficient_evidence；有明确差异则 different_conditions。数值先核对单位和统计定义，不跨口径直接排名。

## 默认预算与失败策略

这些是初始可配置上限，需要 T-00 在目标环境验证，并在可信配置中固定；不能从普通浏览器请求任意提升。

| 项目 | 初始上限 |
| --- | --- |
| 单个 PDF | 50 MiB、250 页；超限先拒绝或明确不支持 |
| 单篇解析 | 60 秒，解析并发 1 |
| 同时模型研读 | 1 |
| 单次模型调用 | 120 秒，输入估计不超过 16k tokens |
| 单篇抽取 | 最多 4 次模型请求，合计输入 32k、输出 4k tokens |
| 比较汇总 | 最多 2 次模型请求，合计输入 32k、输出 4k |
| 备忘录生成 | 独立任务，最多 2 次模型请求，合计输入 32k、输出 4k |
| 一次分析 N 篇 | 最多 4N+2 次请求，输入预算 32k×N+32k，N≤10 |

模型提供商的自动重试也计入请求与时间预算；离线 tokenizer 只是估算，账单用量单独记录。若 SDK 隐式重试无法观测，必须关闭或注明不可准确统计，不能宣称硬预算已落实。每个工具也需要条数和返回长度上限。

超时、连接失败、预算耗尽和无效提交均写入实际错误，保留已发布结果。模型错误默认要求用户显式重试，不隐藏地无限重跑。每阶段记录实际 usage；未返回用量时为 unknown，不能记作零。

## 备忘录与增量

输入只来自冻结的有效事实、人工判断和比较结论，输出包含选择建议、理由、条件、未知项与下一步实验。作者事实、系统推断、用户判断应标记来源类型。

新增论文后先生成新行，再评估比较与备忘录的影响。旧备忘录仍可读，新内容形成带依据的修改建议，必须由用户接受。不会仅因导入就自动替换结论。

MVP 不直接编辑备忘录正文。需要修订时先修正事实/判断或项目输入，再以 baseId 关联旧版生成新草稿；主动在相同输入上重算需显式 rerun，并按新 generation 计预算。接受草稿同时检查其 ETag 和项目 expectedProjectETag。人工更正导致旧比较失效时不自动发起模型请求，等待显式 repair。

## Pi 版本兼容验证

验证会话事件、运行结束语义、abort、工具提交失败、资源加载关闭和用量读取。不要仅以一个低层 agent_end 事件判断所有恢复都结束；按实际 SDK 的宿主结束 API/事件判断，并检查有效结构化提交及错误消息。测试模拟 provider 与真实 SDK 适配，不能只 mock 掉整个会话。
