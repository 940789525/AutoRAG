# 项目问题与变更分析助手开发任务

## 实施规则

以下保留原验收任务清单；未勾选项不能直接等同于没有代码。当前实现与剩余工作见下表，只有相应验证通过后才勾选整项。

开始实际代码修改前，按 AGENTS.md 只读核对本 clone 的当前分支、提交及工作区状态，并默认在当前分支继续开发。未经用户明确要求，不得切换分支、新建本地或远端分支、同步 `main`（任一方向），不得为开始或结束任务自动 fetch、pull、merge 或 rebase。继续剩余任务不代表需要从 `main` 重新开分支。已有未提交、已暂存修改先辨明归属，不自动提交、stash、覆盖或清理其他任务的内容。禁止创建 worktree。当前分支源码与本目录历史基线不同时，以当前实现核对并更新现状与接口依据，不切换到历史基线。

只实现本场景缺少的部分。某项需求现有代码已经满足时，用验证记录交付，不为了体现“做过开发”重复造轮子。

## P3 完成 PR 与 CI 分析流程

- [ ] 在业务 skill 中明确先核验 PR 身份、仓库和 head SHA，再获取评论、diff、Issue、CI。
- [ ] 使用模型生成的 codemode 脚本组织调用；独立请求可并发，有依赖的请求按真实结果派生。
- [ ] 验证部分失败时仍保留成功证据；不能让 `Promise.all()` 的一个拒绝吞掉整批结果。
- [ ] 对大 diff、分页评论、过期日志说明读取范围。优先使用服务参数减少不必要输出，而不是下载整个仓库。

交付：成功 PR、失败 CI、无评论、无关联 Issue、结果截断等业务样例。没有 CI 失败的 PR 不得强行制造失败结论。
