## 首版决策

- 一个入口：用户在现有 TUI 提交一个明确的 GitHub PR 链接；不增加网页产品或通用规划框架。
- 一个真实服务：GitHub 官方远程 MCP；连接名固定为 `github`，默认 `exposure: codemode`。
- 一个只读场景：读取 PR、关联 Issue、评论、变更和可访问的 CI 日志，给出有依据的分析。
- 复用 Pi 的服务注册、连接、工具发现、QuickJS 执行与工具管线；不在 `node_modules` 中修改框架。
- 优先补齐 GitHub MCP 结果与 AutoRAG 证据引用的衔接，并复用现有事件采集调用证据。
- 首次真实联调只使用公开、可复核的 GitHub 资料。不导入私人知识库，不改变 embedding 后端，不新增运行时依赖。

## 开发边界

本目录最初仅交付开发准备文档。后续执行开发任务前，重新读取仓库 [AGENTS.md](../../AGENTS.md)，只读核对当前分支、提交及已有修改，并默认在当前分支继续开发。未经用户明确要求，不得切换分支、新建本地或远端分支、同步 `main`（任一方向），也不得为准备、测试或收尾自动 fetch、pull、merge 或 rebase。任务完成后仍保留当前分支；不创建 git worktree，不改写历史，不自动合并 PR。

文档中的源码基线用于理解历史状态，不要求将工作区切回该提交，也不要求从最新 `main` 重新开始。发现源码与文档不一致时，以当前分支的实际实现为准核对并修订文档；旧版文档或 CONTRIBUTING.md 中的分支流程不构成用户授权。

实际实施可能涉及 `src/`、`test/`、`scripts/`、`skills/` 和 `docs/`，具体范围见任务清单。本目录中的配置不得自动覆盖现有 `mcp.json`、认证文件、`.vscode/launch.json` 或日常 AutoRAG home。

新增运行时依赖、embedding 后端、许可清单或仓库安全治理政策的变化，仍按 AGENTS.md 的既有规则处理；本方案不要求这些变化。真实认证由操作者通过环境变量或既有凭据机制提供，文档和代码只保存引用。
