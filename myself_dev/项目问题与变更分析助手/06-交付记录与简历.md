## 演示材料

完成后保留一个 PR 分析和一个 CI 失败定位案例。每例附用户原始问题、实际模型、PR/SHA/run/job 身份、发现与脚本、父子调用、结果与原错误、最终答案、引用核对及清理收据。公开演示采用公共或合成资料，不附认证文件。

面试时可以沿调用记录解释以下问题：

- 为什么复用 MCP，而不是直接增加一套 GitHub REST 工具？现有 GitHub 索引仍解决什么问题？
- 系统提示提供的服务简介和按需发现的完整工具说明有什么区别？哪些时候可以省略发现？
- codemode 为什么能组合调用？并发如何处理依赖和部分失败？
- Pi 工具管线与 QuickJS 各自负责什么？哪些能力来自框架？
- 工具调用成功为什么不等于答案有证据？GitHub 结果怎样进入现有 ledger？
- 如何处理结构化 MCP 错误、限流、日志缺失、取消及会话恢复？
- direct 与 codemode 的实际代价是什么？对照条件和样本限制有哪些？
