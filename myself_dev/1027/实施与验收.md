# 增量论文研读收件箱实施与验收

## 实施原则

先验证范围过滤与阶段恢复，再做完整的自动导入和研读链路。用现有索引和模型运行时完成业务，不同时更换 Agent 框架、嵌入后端或全文解析器。

当前仅交付方案。以下路径和接口为未来实施计划，不代表目录、依赖、迁移或命令已存在。当前工作区存在未提交改动，实施前应明确这些改动在目标分支上的可用状态，不自动提交、清理或切换它们。

## 阶段零 技术关卡

| 项目 | 最小验证 | 通过标准 |
|---|---|---|
| DBOS 与当前运行时 | Node.js 24+、Postgres、两个有副作用计数的 step，中途终止自己的 Worker 再恢复 | 已完成 step 结果复用，运行中 step 的重试有记录，重复 workflow ID 不重复提交业务结果 |
| Pi profile | 现有模型解析和独立会话，自定义只读工具、结构化提交、AbortController | 没有 bash/write/web 工具；输出校验成功；取消能阻止最终写卡片 |
| DBOS 与 Pi 的组合 | step 内构造会话，结束 dispose，只持久化 JSON | 会话对象不被序列化，崩溃后新建会话仍能完成阶段；不声称恢复内部 token 流 |
| 基线过滤 | 同时索引新论文 A、旧论文 B；仅允许 B | BM25/vector/hybrid 在 top-k 前排除 A；空 allowlist 返回空；调用链不忽略参数 |
| 版本证据 | 取到证据后替换目标 PDF/正文 | 校验失败或提示不可核验，不能仍宣称引用有效 |
| Fastify 与 TypeBox | 校验主题输入和研读输出，序列化响应 | 错误请求被拒绝，代码定义 schema 可用，模型额外字段无法注入路径或配置 |

阶段零输出：锁定版本、许可证/供应链结果、复现步骤、明确通过/未通过的兼容性清单。DBOS 不通过则回到选型，不同时叠加第二套任务调度框架。

新增运行时依赖按 AGENTS.md 先取得确认。其后按仓库流程更新主分支和创建工作分支；禁止 worktree。当前方案文件位于用户指定的未跟踪开发目录，不能顺手连同其他未跟踪文件提交。

## 阶段一 可靠导入与身份登记

交付：登记库、seed 扫描、手动增量扫描、路径/论文/资产建模、批次列表、成功与失败可查询。此阶段不调用模型，PDF 仍在原位置。

拟新增：

- `src/research/catalog.ts`：论文/资产/位置与身份关联。
- `src/research/discovery.ts`：扫描、稳定读取、批次形成及补偿。
- `src/research/store.ts` 与 `src/research/migrations/`：参数化 SQL 和迁移。
- `src/research/index-adapter.ts`：既有 refresh/mirror/index 结果的逐文件对账。
- `test/research/discovery.test.ts`、`catalog.test.ts`、`index-adapter.test.ts`。

复用 `fileSha256`、现有 parser 与 mirror、AutoRAGLite.refresh。服务只管理自己的监听与周期扫描；不去安装/重配现有自动化服务，不启动另一组争用 workspace 的 refresh daemon。

验收：初次 20 个 PDF 只登记；追加 3 个真实新文件与 2 个同字节副本，目录位置增加 5、唯一资产增加 3。seed 阶段所有模型调用计数为 0。

## 阶段二 主题与受限检索

交付：主题 CRUD、冻结基线、按目标资产读取、旧文献 source allowlist、可解释筛选结果；先用确定性模型夹具验证流程。

拟新增：`src/research/topics.ts`、`retrieval.ts`、`evidence.ts`、`planner.ts`、`schemas.ts`。

必须贯穿的共享改动：

1. `src/retrieval/types.ts` 的类型化本地 sourceIds 约束及选择传播。
2. `src/indexing/pipeline.ts` 的查询选项与转发。
3. `src/indexing/types.ts` 的 store 查询契约。
4. `src/indexing/lance-store.ts` 在查询 top-k 前组合 source scope 与 sourceIds 谓词。
5. 检索 method、engine 与 profile 包装层的转发及不支持时的明确错误。

具体采用专用本地接口还是扩展既有选项，在阶段零比较后选择最小完整路径。无论哪种，都必须经过方法调用链验证，不能只改类型或测试 stub。没有 sourceIds 参数时保持现有调用行为；显式空数组返回空。SQL/谓词只从宿主规范化 ID 生成，使用现有安全转义方式，不接收模型 SQL。

不通过全库 top-k 后过滤模拟冻结基线。若初版选择逐旧论文 exact scope 检索作为关卡原型，必须标记其性能限制；正式容量验收以前需要确定可用的前置集合过滤实现。

## 阶段三 单篇研读与收件箱

交付：指定资产与主题，获得一张结构化、可核验的阅读卡片，支持反馈；不要求文件监听自动触发。

拟新增：

- `src/research/profile.ts`：围绕一个论文/主题的只读 profile。
- `src/research/analyzer.ts`：调用已有模型运行时、分阶段分析与结果校验。
- `src/research/inbox.ts`：卡片、覆盖说明与反馈。

profile customTools 只提供宿主已授权的论文/证据句柄读取，以及 `submit_paper_note`。默认关闭 projectFiles、skills、extensions，不接入交互式 retrieval memory。论文正文视为待分析数据，不授权其改变工具或模型配置。

元数据提取不因看见一个 DOI 就认定是本篇；摘要不足时展示提取失败/不完整，不自动联网补全。引用验证至少检查资产归属、指纹、原文片段、章节/偏移；结构合法不等于语义有支撑，语义支撑另用人工金标评测。

验收：无旧论文时输出有效单篇卡片；有旧论文时最多比较 3 篇并列出实际来源；不能编造未读取的实验数字、章节或 PDF 页码。一次输出修复仍失败进入 needs_review。

## 阶段四 后台任务与自动批次

交付：DBOS 工作流、pending 补发对账、监听与定期扫描自动处理、取消/重试、每主题数量上限、故障恢复。

拟新增：`src/research/workflows.ts`、`runtime.ts`、`reconcile.ts`。

DBOS 管任务领取和执行历史；业务库保存用户能理解的状态与结果。初始研读并发为 1，索引写入每 workspace 为 1，不将同一个 AutoRAGAgent 会话跨并发任务共享。容量验证后才提高并发。

业务 run 登记先于 DBOS 入队，以固定 workflow ID 补偿；结果提交与终态事件同事务。自动失败最多两次重试，使用有界退避；解析格式错误、schema 无效、权限拒绝等不可修复失败不盲重试。未知底层错误保留全文，重试策略不替代用户诊断。

模型 step 设置默认 180 秒截止时间，单篇总任务默认 10 分钟，阶段取消信号必须传到读取、检索与模型请求。具体超时应依据实际 provider 和长论文样本调整；超时表现为失败/延后，不能生成伪成功卡片。

首版在同一服务中实现 API、协调器和 Worker。独立 Worker 池与分区公平队列暂不实现；不为了展示分布式而让同一库并发写索引。

## 阶段五 接口与部署

交付：主方案中的 HTTP 路由、SSE、健康检查、独立 Compose 配置说明、数据保留与恢复步骤。可以通过 HTTP 客户端完整演示，不将前端设计纳入 MVP。

拟新增：`src/research/http.ts`、`routes.ts`、`index.ts`，以及后续经确认的开发 Compose 文件。生产入口的 package.json/build/export 需要按仓库允许范围和变更审批另行确认，不在实现业务时隐式扩大到根配置。

健康接口区分：API 存活、Postgres/DBOS 可用、资料库可读、索引就绪、嵌入可用、模型凭据可解析。健康检查不发真实模型请求或写配置。模型未登录时仍可完成发现和索引；研读任务明确处于缺少模型条件的失败/待重试状态，不自动选择其他 provider。

SSE 事件仅推送阶段/计数，按运行内事务序号恢复；检验慢连接缓冲上限。localhost 部署及 token 引用遵循主方案，不复制真实凭据到 Compose、日志、数据库或 argv。

## 功能验收矩阵

所有用例使用合成 PDF/明确获准的公开论文及隔离目录。

| 场景 | 预期结果 |
|---|---|
| 初次启动已有大量 PDF | seed 登记，无自动全文研读；可选手动补研读 |
| 停机期间复制新 PDF | 启动扫描发现，创建一次批次项和研读任务 |
| 临时下载后 rename 成 PDF | 最终文件就绪后处理，不读半份文档 |
| 连续同一路径事件 | 合并后对同资产只处理一次 |
| 同字节换名/移动 | 多位置一个资产；不重复深读 |
| 同 DOI 不同字节 | 同作品多个资产，不自动覆盖历史版本 |
| DOI 出现在参考文献里 | 不误识别为本篇身份 |
| 预印本与正式版无法确认 | needs_review，可保留两者，不自动合并 |
| 同主题本批 15 篇相关论文 | 最多自动深读 10，其余可查询并手动追加；覆盖说明含限额 |
| 新论文和旧论文都很相似 | 比较只从冻结旧集合检索，同批新增不能自我佐证 |
| allowlist 为空 | 没有旧文献结果，不回退全库 |
| 外部源或文件不可读 | 原始错误可见，不当成“无关”或“无新增” |
| 解析失败的某篇 | 该 item 失败，其他论文仍完成，批次 partial |
| 目标/证据原文被替换 | 指纹校验阻止错误引用或标记覆盖缺口 |
| 主题中途修改 | 旧 run 使用原快照，新 run 使用新 revision |
| DB 提交 run 后进程退出 | pending 对账用原 workflow ID 补发 |
| 入队成功但确认丢失 | 不出现第二个同身份 workflow/card |
| step 完成后进程退出 | 已完成阶段复用，执行中阶段可能重跑且有记录 |
| 结果提交后确认丢失 | 相同 run_id 读回原卡片，不重复创建 |
| 取消与完成竞争 | 事务确定唯一终态；取消先成功后不写迟到卡片 |
| 浏览器断开 | 后台继续；重新查询/连接可获得结果 |
| SSE 序号提交顺序竞争 | 不越过尚未提交事件；重连可去重 |
| 多次相同 HTTP 幂等键 | 同请求返回原资源，不同请求体返回 409 |
| 重新挂载路径/符号链接换目标 | 重新授权与哈希验证；不能读取根目录外文件 |
| 关闭研究服务 | 普通 AutoRAG 搜索、CLI/TUI 默认行为保持可用 |

## 质量与性能评估

### 研究质量

准备 3 个主题、30 篇有明确使用许可的论文，人工标注相关性、阅读价值及可比较关系。按主题区分基线与新增；冻结模型、提示、源 hash 和输出 schema 版本。

首版建议门槛，属于验收目标：

- top-10 入选论文的人工相关比例至少 80%，同时报告基于全部人工相关论文的召回率，不能只报精确率。
- 所有最终引用均能解析到登记资产和对应原文；抽样至少 30 条核心主张，至少 90% 被引文语义支持。
- 不把条件不同的实验分数直接判作性能优劣；人工标注的关键不可比案例不得漏报。
- “没有比较依据”的案例允许 abstain/待核实，不能用编造关系换取高完成率。

30 篇是工程验收样本，不足以证明跨领域泛化。保留错例和逐主题结果，不只保留平均分。

### 性能和成本

在当前 4 CPU、8 GiB 容器记录 seed 100/1,000 篇及 warm 导入 1/10/50 篇。分开报告下载模型/冷启动、索引、排队、首个进度事件、单篇研读与端到端完成时间。记录队列积压、峰值内存和每篇模型 token；provider 不报告 usage 时明确缺失。

对照“每次全库重新分析”和“只处理新资产”，用同一输入测实际解析、嵌入和模型工作量。目标是稳定无变化库不触发模型调用，同字节重导入不重复深读；不预先承诺固定加速倍数或每篇成本。

## 仓库检查与隔离 QA

实施后的必需检查为 `bun run check && bun run lint && bun run typecheck` 及覆盖修改的测试；运行时依赖变化还需要 supply-chain gate。`check` 会写文件，应在有意验证的工作分支或仓库支持的隔离检查副本运行，不能在当前方案阶段为了验收文档而运行。

本地检索或 sourceIds 过滤改变后，需要按 AGENTS.md 的 Docker 隔离流程执行真实 MinSync 语义 QA，证明本地嵌入、命中源路径绝对且可读；缺少嵌入条件时保留精确阻塞诊断，不能以 mock 测试冒充 live QA。

每个 QA 进程都显式使用任务临时 AUTORAG_HOME/AUTORAG_CONFIG 与独立研究 workspace/数据库。不能写真实 `~/.autorag`，不能重配当前 Finder、MinSync 或其他 clone 的 daemon。按仓库要求记录真实 config 前后哈希，清理只限自己创建的目录、库和进程。

## 完成标准

在同一个演示中完成 seed、主题创建、批量新增、重复识别、证据研读、反馈，以及一次进程中断恢复。附逐文件状态、数据库唯一性断言、基线成员清单、引用核验结果和质量/延迟报告。

首版最大的不确定性是论文解析质量、主题筛选与比较效果，以及 DBOS/Pi 的取消与重试边界。它们分别由阶段零技术关卡、合成故障测试与人工标注论文集验证，不以增加更多中间件代替验证。
