# 增量论文研读收件箱：实现与使用

实现日期：2026-10-28。用户已允许在 `codex/observable-local-index` 继续，复用当前未提交的本地索引与证据功能。本文件记录实际实现；原方案文件保留为需求与设计依据。

## 已实现的闭环

1. 用可信配置固定一个 PDF 根目录、独立研究 workspace、原 AutoRAG 模型配置和 Pi 账户目录。
2. 创建资料库并执行 seed：登记存量、解析和构建索引，不进行模型筛选或研读。
3. 新 PDF 导入后，以目录监听触发扫描；启动及每五分钟补偿扫描。稳定观察两秒后计算 SHA256。
4. 分开保存论文、文件版本与文件位置。同内容重复导入只登记位置；现代 arXiv 文件名识别同一论文的不同版本，其他身份通过接口明确。
5. 每批开始前固定旧库清单；新文件完成索引后，为当前启用主题登记工作流。LanceDB 在排名前应用精确 source allowlist，排除目标文件及同一论文已知版本。
6. Pi 独立会话先做主题筛选，再生成结构化研读卡片。单主题每批最多自动深读十篇；其余记录 deferred，可以显式补读。
7. 收件箱可查询、查看证据、标为已读/稍后读，并反馈有用性和相关性。主题修改不自动重读历史文件。
8. DBOS 支持阶段恢复；取消先落库，再终止当前模型请求。业务提交再次检查取消与唯一约束，阻止重复卡片和迟到结果。

后续已增加 TUI `/research` 收件箱菜单和开发容器 F5 组合启动，具体步骤见 [TUI使用说明.md](TUI使用说明.md)。HTTP JSON/SSE 继续作为后端接口，尚未制作网页前端。

## 在当前开发容器中使用

`1027` 位于仓库的 bind mount 中：

- 宿主路径：`/home/xsy/projects/AutoRAG/myself_dev/1027`。
- 容器路径：`/workspace/myself_dev/1027`。

提供两个示例文件：`research.example.json` 与 `compose.research.yaml`。示例会读取已有 AutoRAG 配置，但把研究索引与记忆路径覆盖为独立的 `/data/workspace/research-inbox`，模型处理默认关闭。不要把示例直接当成已部署实例。

1. 在宿主机通过自己的凭据管理方式准备外部数据库密码文件，并将其绝对路径设为 `AUTORAG_RESEARCH_DB_PASSWORD_FILE`。文件不放在仓库内。
2. 在宿主机执行 `docker compose -f myself_dev/1027/compose.research.yaml up -d`。只新增独立 PostgreSQL 18 服务，不重启已有开发容器，不发布数据库宿主端口。
3. 通过环境提供 `AUTORAG_RESEARCH_DATABASE_URL`，指向该网络的 `research-db:5432/autorag_research`，用户为 `research`。密码来自前述凭据。不要把实际连接串写入配置文件或命令行参数。
4. 构建：`docker exec autorag-xsy-dev-dev-1 bun run build`。
5. 在宿主机已具有上述环境变量的前提下，前台启动：

   ```bash
   docker exec -e AUTORAG_RESEARCH_DATABASE_URL \
     autorag-xsy-dev-dev-1 \
     node dist/research/index.js /workspace/myself_dev/1027/research.example.json
   ```

6. 另一个终端用容器内 HTTP 客户端访问 `http://127.0.0.1:8765/research/v1`，按 `docs/research-inbox.md` 创建 library、topic、seed，随后导入新 PDF。容器内 `/documents` 对应当前开发环境的资料夹。
7. 确认模型选择后，在可信研究配置中将 `allowModelProcessing` 设为 `true` 并重启研究服务，再进行研读。它允许论文摘录发给已配置模型；若模型是远端提供商，摘录将离开本机。HTTP 请求不能开启此权限。

服务只监听其所在容器的 loopback；不能直接通过宿主端口访问。停止前台进程只会停止本研究服务。完整启动、请求和字段示例见 `docs/research-inbox.md`。

若公开 tokenizer 资源下载受限，可在可信 AutoRAG runtime 配置的 `localIndex.tokenizerPath` 指向已有的匹配模型缓存；目录必须同时有 `tokenizer.json` 和 `tokenizer_config.json`。不要修改共享配置来做 QA，验收脚本支持通过 `AUTORAG_RESEARCH_QA_TOKENIZER` 指定只读缓存。

## 实施时收紧的边界

- 只有请求时显式创建的历史研读会回读存量；新主题不会悄悄消耗整库模型调用。
- 索引和稳定观察失败最多自动重试两次；模型失败交由显式 retry，避免后台无感重复计费。崩溃中的步骤仍可能重复，这是阶段恢复的边界。
- 卡片使用至多十二个摘录，默认 `partial`，不是全文精读或系统综述。引用是解析 Markdown 的 UTF-16 区间，不能当作 PDF 页码。
- 当前 usage 记录深读会话的请求数、token 和提供商报告成本，不含单独的筛选会话；token 预算采用 cl100k 估算，不是所有提供商的账单计量。
- `/health` 目前证明 API/PostgreSQL 存活；嵌入与模型账户可用性通过 seed/实际研读阶段诊断。没有用健康检查冒充模型已验证。
- 未对真实论文集进行模型输出质量、阅读优先级准确率或 1000 篇负载基准。这些仍需要后续人工标注验收，不能从流程测试推断已达到质量目标。
- 未启动正式研究资料库或修改现有论文；示例配置与启动步骤已交付，可以由用户选择资料库后启用。

本任务创建的两个临时 PostgreSQL 测试容器及其匿名卷已清理；原开发容器和已有 MinSync daemon 保留。
