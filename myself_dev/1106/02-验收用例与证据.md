# 验收用例与证据

**执行记录见 [03 实施与实测记录](03-实施与实测记录.md)。** 下表是预先定义的通过标准。历史会话仅用于说明原问题，模拟故障与真实 TUI 的结果分别记录。

## 固定样本

使用隔离的本地测试目录，先索引 4 份可识别的合成文档，再新增第 5 份 `新增纪要.md`，不刷新。核实最近任务为成功、目录中有 5 份、活动索引只登记前 4 份。这个样本能区分“索引整体就绪”和“每份文件都已登记”。只用合成语料，按 [AGENTS.md](../../AGENTS.md) 隔离 HOME/config 并保留基线；不要为复测改动共享服务。

## 验收矩阵

| 用例 | 需求 | 输入或故障 | 通过标准 |
| --- | --- | --- | --- |
| A1 | R2、R3、R6 | “当前有哪些文件，这些文件是否都已建立索引？”及“当前本地资料库中有哪些内容，资料库是否都已完成索引建立？”各跑一次 | 两种都进入普通问答，列全 5 个名字、指出新增文件未登记。每条至多一次分类、无索引写任务。 |
| A2 | R2、R6 | “库里都有什么？还有哪几份没被收录？”及无关常识问题 | 对此无候选词的改写，分类为 0 次，前者给出清单和缺项；无关问题不自动读取本地文档或清单。 |
| A3 | R3、R6 | 在 A1 注入分类返回 `operation/status`，活动索引为 ready | 普通问答收到完整原话；不得只显示最近任务 JSON。即使状态分类成功，仍查到缺项。 |
| A4 | R4 | 分别注入提供方 `Request timed out.`、12 秒本地超时、无效分类 JSON | 诊断保留原始错误；当前输入交回正常问答一次，无分类重试、无索引任务。覆盖问题用独立可用的回答模型桩验证，避免把“分类故障”与“回答模型也不可用”混为一谈。 |
| A5 | R1、R3 | “帮我建立索引”、`/index status`、“查看当前索引进度” | 建立请求零分类且只提交一次合法任务；首建走 build、合适的既有索引走 refresh。两种显式状态查询均不写入。 |
| A6 | R3、R5 | “先更新索引，再总结新资料”；“先列出文件，再看是否均已建索引”；“文档里写的‘重建索引’是什么意思？” | 第一条按旧约束澄清，不执行半条指令；后两条走问答，不把连接词或引号当操作授权。 |
| A7 | R4、R5 | 分类中 Esc 或被下一条输入替代，然后让旧模型迟到返回 build | 旧输入无回答、无任务；新输入按自己的路径处理。普通失败回退不得复活旧请求；取消其他会话任务的原有保护有效。 |
| A8 | R6 | 目录不可读、扫描不完整、活动索引不可用或只读核对被拒 | 报告可确认的范围和无法核实的原因；不得宣称全覆盖，也不以刷新或重建代替核对。 |

## 如何取证

先扩展 [路由单测](../../test/agent/index-intent.test.ts)，覆盖状态误判、两类超时、无效 JSON、取消和迟到响应。再走绑定 TUI 的输入入口，核对 `autorag.user-request` 只记录一次，`runs.jsonl` 中的 `index_intent` 调用数与预期一致，普通回答走 `search_started`；对照任务记录确认写任务数。只跑 CLI 的 `search` 无法验证 TUI 输入拦截。复查[已有状态控制测试](../../test/agent/index-controls.test.ts)及受影响的会话、权限测试。

最后用同一模型、同一合成样本，在独立新会话中实跑 A1 的两种问法和 A2 的改写；记录会话与运行日志路径、实际文件覆盖、分类调用数、回答模型调用数、提供方报告的输入／输出 token 和用时。模拟分类结果能验证分支，不能证明真实模型理解了改写。通过仓库要求的静态检查和相关测试后，再根据这些证据决定是否交付；环境无法运行或用量缺失的项目分别记为未执行或未知。
