# TUI 索引意图分流 · SDD

**最终决策**：明确命令沿用原入口；自然语言命中“索引”等现有候选信号时，用当前会话模型判断一次。只有用户明确要求执行索引操作，才把请求交给操作流程。询问、分类失败或仅被判为查询状态的自然语言候选，都将**完整原话**交回正常问答。取消和被新输入取代的旧请求直接结束。

例如，“当前有哪些文件，这些文件是否都已建立索引？”和“当前本地资料库中有哪些内容，资料库是否都已完成索引建立？”应查到同一份文件清单和覆盖情况。“帮我建立索引”仍走原有任务流程。

规格基线为 `41090eda`，日期为 2026-11-06。**已在规格提交 `78755776` 上实施，并在开发容器的真实 TUI 验证两种问法和明确索引指令。** 适用范围是交互式 TUI。复用现有模型、工具和索引，不新增工具、模型、工具操作类型或配置项。

后续优化按新的使用要求复用 `manage_local_index` 的现有 `status`。仅当 `includeFiles:true` 时，工具枚举允许范围内的本地文件并核对活动索引登记表。大目录每页最多 100 个文件，可将 `nextOffset` 传给 `fileOffset` 取下一页；无法核实或扫描不完整会附上诊断。普通状态查询不枚举文件。05 的两次最终复测均为一次带明细的 status、零次 bash、两次回答模型请求；04 的 5 次和 7 次是优化前的基线，其中第一种问法有一次连接错误。

依据是[已复核的问题记录](../问题记录/2026-11-06-TUI-本地文件与索引状态查询.md)：四次复合提问中，三次分类超时，一次分类成功却只显示任务状态。方案同时针对这两条失败路径。沿用 [1102 索引操作约束](../1102/01-需求与设计边界.md) 和 [1105 按需检索约束](../1105/README.md)。
