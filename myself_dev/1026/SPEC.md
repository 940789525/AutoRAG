# 多轮证据追加去重与容量整理：实现规格 v2

## 0. 状态、术语和优先级

修订日期：2026-10-27。本文取代本目录 v1 的“全历史分差／MMR 投影”主方案。**v2 核心及第 10 节按需证据恢复已进入代码实现与验收；工程／本地／真实生成证据分别记录于 IMPLEMENTATION。完整质量、缓存与费用发布门槛仍待满足。** 实际检查以 IMPLEMENTATION 为准，旧数字见其历史章节。示例和阈值是需求或实验初值，不能当成实测收益。

| 术语 | 定义 |
| --- | --- |
| 候选池 | 检索完整结果，不等于实际发送的正文 |
| 原始会话 | 完整用户、助手、工具记录，保留追溯用途 |
| 已发送视图 | provider 实际接收的消息内容；可以不同于原始会话 |
| 完整正文锚点 | 当前有效模型上下文中真实存在的、未截断的某条证据正文位置 |
| 可见索引 | 按最终模型视图登记完整正文锚点，不是 ledger，也不是服务端 KV 状态 |
| 新后缀 | 本轮尚未提交给模型的消息／内容 |
| epoch | 两次集中整理、会话分支／模型切换等失效边界之间的稳定视图阶段 |
| 集中压缩／整理 | 在容量触发点批量省略可恢复的历史候选正文并重建视图，不是逐轮重排历史，也不必调用摘要模型 |
| 前缀稳定 | 同一 epoch 正常追加时，此前实际发送的消息序列及内容不变 |

优先级：**来源与事实完整性 → 模型容量合法性 → 可恢复性 → 前缀稳定 → 减少新增输入**。不能为缓存保留已无权读取的资料，也不能为省 token 构造没有正文支撑的引用。

## 1. 目标与范围

### V2-R01：目标

降低多轮同主题检索中重复正文的新增量，尽量保留原请求前缀可复用性；真实效果以整段会话累计成本、延迟和质量验收。块数、估算 token 和缓存命中率分别报告，不相互冒充。

### V2-R02：保留现有检索契约

不减小统一 topK 来伪装优化，不替换本地 LanceDB、Qwen3 嵌入、索引存储格式和远端 opt-in。第 10 节仅允许为已有索引补最小只读精确块查询，以及现有结果／session entry 的可选读取定位元数据；不新增索引列、向量数据库或正文快照库。完整 API、原始工具结果、trace 和 transcript 保留；新增短引用是模型视图，不把检索 `resultCount` 改成正文发送数量。不新增运行时依赖、摘要／选块／裁判模型或新的充分性判定请求。

### V2-R03：第一版覆盖面

覆盖 baseline、`semantic_search_local_docs`、`search_all_documents` 的可靠本地块、single / progressive、standalone 和绑定 Pi 会话、多轮及同轮多次工具请求。新增的 `read_local_evidence` 是显式完整正文读取，按第 10 节接入同一生命周期，但其本次正文不能立即再去重成短引用。普通用户文本、助手回答、显式 bash／read 原文、网页、图片和原生数据源首版不做自动正文去重；来源原样保留并计入容量。需要来源不在范围内时保守透传，不用正则把任意文本猜成本地块。

### V2-R04：完全重复与语义选择分开

首版只对身份可信、正文完全相同的本地证据做追加去重，不需要向量、cosine、MMR 或自然语言意图分类。全量、计数、例外问题、启用 Rerank、steering 不能自动关闭安全的精确去重；它们仍可能需要保留更多新正文。部分重叠、相似但有不同金额／否定／日期、不同来源或版本不合并。

v1 分差／MMR 可保留为**新候选**的独立实验选项，参数与旧算法保持可追溯；缺乏向量不影响精确去重。不得借适配之机新增调参面板或语义摘要方案。

## 3. 用户可见与请求级效果

### V2-R05：正常追加

```text
已发送 P1：system + user(Q1) + baseline[A 全文、B 全文] + assistant(A1)
Q2 工具召回：B、C
准备 P2：P1 + user(Q2) + assistant(toolCall) + toolResult[B 短引用、C 全文]
Q3 工具召回：B、D
准备 P3：P2 + assistant(A2) + user(Q3) + … + toolResult[B 短引用、D 全文]
```

示意省略了既有工具消息包装，不允许删掉真实 toolCall / toolResult 配对。正常情况下 P2 的既有前缀必须与 P1 相同，P3 不得因新结果而改变 P2 中已经发送的内容；provider 所需角色和特殊 token 以实际序列化核验。

### V2-R06：短引用不是新答案

示意格式：`[e2] 本轮再次命中；完整正文见本上下文消息 m12 的证据 e2。` 使用稳定绝对消息／证据身份，禁止“前两轮”等随轮数变化的相对定位。短引用保留来源和必要的本轮命中信息，不声称正文已经核验、答案充分或检索完整。

- 引用直接指向完整正文，不能指向另一个短引用形成链条。
- 如短提示（含来源、分隔符）不比原正文更短，可继续发送原文并记录 `stub_not_smaller`。不以“零重复率”牺牲净长度。
- 全部重复时仍返回有效 toolResult 和简短命中回执，不能改成“无结果”。
- 不在旧锚点上更新本轮 score／排名；这些信息只出现在新后缀或运行日志。

### V2-R07：恢复与变化

B 从未被选中、锚点被部分截断／删除、会话恢复后无法证明锚点存在时，重新发送 B 全文。同一路径正文／版本改变时发送新正文并保留旧证据身份。来源在当前配置不再授权可见时优先执行既有隔离规则，记录前缀失效，不能为了缓存保留旧内容。

## 4. 数据、状态与正常处理

### V2-R08：证据身份与可见记录

内部精确身份至少包含可信 source、chunk ID、实际原始正文 SHA256，以及存在时的版本标识；eN 用于引用，不能单独作精确去重依据。不同 source／ID／版本首版不跨身份合并。不得仅用路径、排名、向量或文件 mtime 推断正文相同。

当前 ledger 的空白规范化 hash 继续作为引用兼容规则；精确去重另校验原始正文 hash 和已呈现正文，避免将代码、表格等空白差异当成完全一致。原始正文与渲染后的空白压缩正文要区分。块 ID 或 eN 一样但内容指纹变化也必须视为需要全文。

可见索引最少记录 epoch、证据身份、锚点消息身份、正文是否完整、渲染版本；只记录实际留在有效模型上下文里的完整正文。候选池／ledger／原始 transcript 中存在、SDK 缓存命中、模型曾经看过，都不是单独充分条件。索引不存 KV、不另建持久化语料库。

### V2-R09：先验证前缀，再处理新后缀

1. 根据会话分支、消息稳定身份和上一份已发送视图，确认本次历史是否仍是可重用前缀。
2. 保留该前缀；只对新 baseline / 工具消息做结构化展开和可选的新候选选择。
3. 在当前有效视图中查完整正文锚点。完全相同且引用更短时替换新正文；否则发送全文。
4. 同批多个新工具结果按稳定消息顺序规划；只有更早的计划完整正文能成为后面的引用目标，不以异步完成先后随机决定顺序。
5. 相同 raw messages 重试必须产生相同输出；不在每次重试更新引用、时间文本或历史省略计数。

正常同 epoch 必须满足 `render(history + suffix)` 的旧部分等于此前实际发送的 `render(history)`；只改 latest 为 earliest 而继续每轮重选全部历史不合格。

### V2-R10：最终核验与提交

去重不能在 formatter 看到 eN 时就“标记已读”。先生成 provisional 计划，再经容量保护、provider 输入限制和所有会影响正文的变换，检查最终视图中的引用目标是否仍完整且位于引用之前。

- 锚点丢失时，在新消息补回可信全文；若仍装不下，取消对应短引用并明确容量省略，不谎称可读。
- 修复后再次检查容量；不做无界“裁剪 → 补回 → 裁剪”循环。每个请求至多一次计划的集中整理和一次有界修复；仍无安全输入则走现有明确超限错误，不发送悬空引用。
- 只有请求已实际派发且成功消费的边界可确认对应视图；取消、派发前失败、重试未提交的草稿不能登记成锚点。无法确认时保守重发正文或开启新 epoch，不用猜测的“已发送集合”。
- 最终模型视图、索引更新和 epoch 切换按一个提交结果处理；失败不保留半更新状态。

### V2-R11：记忆、规则与工具前缀

开启 v2 时，本问题动态 memory_context 作为**当前后缀**追加一次，可用独立的请求视图用户块承载；不修改真实用户输入，也不每个工具循环重复插入。此前已发送的 memory_context 保持原样，集中整理时才批量处理；本问题记忆为空不改变旧前缀。

不改动必要的系统指令、当前来源权限或正确的工具开关。稳定序列化活跃工具 schema、顺序和规则；模型、工具、系统规则、provider、思考参数等必要变化要记录前缀变化原因和新的 epoch，不能声称保持完整缓存可用性。不要把 Date.now() 的内部字段直接当成 provider 可见文本；测量真实序列化结果。

### V2-R12：新证据软预算与语义选择

保留可信 `contextSelection.mode=off|observe|adaptive` 和 `evidenceBudgetTokens`，缺省 `off`，现有合法配置无需新增必填项。v2 策略版本必须改变并记录迁移，不能把新结果混进 v1 指标。

- `off`：维持禁用新功能的既有请求路径，现有容量保护照常执行。
- `observe`：计算假设计划，不改变 off 的最终模型输入，也不提交真实去重／整理状态；假设收益不得作为实测缓存或 token 收益。
- `adaptive`：采用 v2 追加去重与容量整理；不能再正常执行 v1 的全历史重选。
- 6000-token 默认软预算改为**每个活动用户问题新增的唯一、本地候选正文及呈现开销预算**，跨 baseline 与多次工具请求共享；已经保留的前缀不再为满足它而重写。引用和省略提示的新增开销单列并计入预算测量。
- 普通事实题可在新候选上复用 v1 分差／MMR；保守问题不做激进语义截断，必要新证据、显式原文读取可超过软预算并记录。精确去重仍执行。
- 对未呈现候选不能永久标为已见；后续明确补取仍可发送，并记录软预算超支。更新 query 不能在同一问题内重复获得无穷份 6000。

这是受控实验配置语义迁移，后续须同步 `docs/context-selection.md` 和配置说明；本次代码阶段同步产品说明，不更改调试配置。

## 5. 接近容量时集中整理

### V2-R13：触发量与初始阈值

容量基准 `B_safe` 为沿用当前 context guard 的安全输入上限（含输出预留、安全余量），并取已知 provider token 输入限制的更严格者；按**最终模型消息＋实际系统／工具开销**估算占用 T，不只统计本地正文。字符、字节、图片等非 token 限制仍独立检查。

冻结的第一轮开发初值：`T >= 0.80 * B_safe` 时触发，目标 `T <= 0.60 * B_safe`；两者是内部版本常数，不新建用户调参配置，不是已证明最优值。未知 contextWindow／限制时不能伪造百分比，保留现有保护，记录 `capacity_unknown`。

- 新问题／新工具结果进入前检查计划输入；一次触发覆盖这个阶段全部可整理历史，不能按一个块一次触发。
- 软预算不足、query 改变或本轮没有新块，不能单独触发历史整理。严重容量错误是紧急触发，独立记录。
- 整理未达到低水位但仍满足硬容量时，可发送并记录未达目标。正文集合未变、没有新的可整理内容时不反复空整理；保护内容本身超限则明确报错／沿用既有恢复机制。

### V2-R14：首版确定性的整理内容

首版只批量整理可靠映射的、较旧的本地候选正文；不新增摘要 LLM。按稳定时间顺序优先省略最旧、未被当前新后缀明确引用且非当前核验需要的正文，保留最新必要正文直至目标或没有可整理项。当前活动问题中已呈现的本地正文及新用户问题明确点名的既有 `[eN]` 按必要上下文保守保护；不能仅靠“某次模型回答写完了”判定全部旧证据无用。

保留当前问题及限制、最新 steering、必要工具调用／结果结构、来源和 eN 追溯。原始候选和原始会话不删除。省略位置仅有确定性的短回执，不能虚构综合事实或伪造完整来源正文。

- 如果需移除已有短引用的正文锚点，不能留下仍声称“完整正文见上”的指针：保留目标全文，或在**同一次整理**中将受影响短引用改成“正文已省略、需重新读取”的追溯回执。
- 普通历史助手回答中的引用可以作为来源记录留下，但不能据此认定原文可见；当前待回答问题的活动引用必须可解析到完整正文。
- 显式读原文、非本地工具结果等首版不由新整理器压缩。它们占满容量时记录限制，不能声称压缩了全部来源；最终仍受既有 guard 约束。
- 不强求达到低水位而删除当前必要原文；无法同时保留必要内容和合法请求时报告原始容量错误。

### V2-R15：整理是显式 epoch 边界

仅在整理计划成功并能形成安全请求后提交新 epoch，记录触发原因、前后量、移除锚点、重发数量和预计前缀失效位置。承认这次旧前缀不能完整复用；此后继续保持新的前缀稳定，不每轮重复重建。

重建可见索引时只登记仍完整保留的正文，eN 不重编号。旧重复块此前已在历史中存在的，不为追求零重复立即改写；等容量整理或显式用户压缩统一处理。

### V2-R16：与 Pi compaction 的协调

接入已有 `session_before_compact` / `session_compact` / `session_compact_failed`，区分 manual、threshold、overflow、retry 和取消。成功后基于新的有效上下文重建可见索引；失败／取消不能假装成功整理。不要在 AutoRAG 和 Pi 各启动一套无协调的压缩循环。

依赖中的手动 `AgentSession.compact()` 会先 abort 当前 agent operation；禁止在 `context` 回调中直接调用它来实现本方案。优先复用正常请求的确定性视图整理，Pi 原有自动／手动摘要按既有设置保留；其真实模型调用也必须统计成本。standalone 没有 Pi compaction 时仍满足确定性整理和容量安全，不能仅给绑定会话实现。

## 6. 生命周期、回退与兼容

### V2-R17：会话隔离与恢复

每个 session／branch／epoch 单独拥有状态。`/new`、会话删除、dispose、ledger reset 释放引用计划和可见索引；分支移动、恢复、model/provider 变化重新验证。不能把全局 memory、另一会话的 eN 或落盘 ledger 当成当前可见正文。

重启后只有既有会话元数据能证明已发送视图及其身份时才恢复锚点；否则在下一次请求建立有记录的新 epoch，并重新提供必要正文。不新增独立长期数据库。需要持久化最小视图元数据时复用现有 session entries；不能新增向量／私有正文快照。元数据丢失／过期保守降级，内存有界，未知格式保留。

### V2-R18：安全回退

去重失败但前缀仍可信时保留已发送前缀、新结果发全文，记录原始错误；不因回退把历史全量 raw transcript 重新塞回。若前缀不可重建、权限变化或最后 guard 改写历史，显式新建 epoch，修复引用后才发出。

候选被容量限制省略、无结果、所有结果重复、来源未检索是不同状态，不能混写。原始 CLI stderr／错误路径照常透明；仅限制输出长度，不以原因码替代正文。不新增远端调用，不读取／改写共享真实 `~/.autorag`。

## 7. 观测与验收契约

### V2-R19：逐请求观测

至少记录 session／question／request 匿名身份、策略版本、epoch、mode、候选总数、完整正文数、短引用数、重发／省略数、去重新增估算 token、最终可见正文数；不得更改 raw resultCount 定义。

另记前缀可复用长度／最早变化位置与原因、整理次数及前后 token、预算超支、无可整理量、修复／回退、dispatch / commit / abort 状态。prefix 指标是应用层可验证量，不等于 provider 已命中 KV。

provider 的 input、cacheRead、cacheWrite、output、TTFT 和最终耗时在可用时分列，缺失为 unavailable。scope 区分 answer_session、规划、Pi compaction 和其它实际模型调用；已记录的 answer_session usage 不能冒充完整会话成本。默认日志不新增正文、向量或凭据。

### V2-R20：评估与默认值

对比不处理重复、v1、只做追加去重、追加去重＋容量整理；V2-A—E 在同语料、模型和工具条件下做多轮配对。新增 V2-F 单独研究恢复工具可用性，工具声明及必要使用说明的差异必须披露，不冒充同工具面的纯去重消融。新方案不保证每个请求最短或绝对缓存命中，也不保证一次整理后立刻省钱。发布门槛以 VALIDATION 为准，未通过维持产品默认 off；配置显式 adaptive 不算验收。

## 9. 研究依据与适用边界

- [Manus：Context Engineering](https://manus.im/en/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)：稳定前缀、append-only；不是 AutoRAG 的性能证据。
- [vLLM prefix caching](https://github.com/vllm-project/vllm/blob/main/docs/design/prefix_caching.md)：缓存 key 包含 parent hash，重复文字换前文不等于命中。
- [Headroom cross_turn_dedup](https://github.com/headroomlabs-ai/headroom/blob/42ebbc6c/headroom/transforms/cross_turn_dedup.py)：保留最早正文、后续短指针、prefix monotonic 检查；本项目只借鉴约束，不引入依赖。
- [LibreFang file_read_tracker](https://github.com/librefang/librefang/blob/dceae897/crates/librefang-runtime/src/file_read_tracker.rs)：内容 hash、固定原文锚点、压缩后状态重置。
- [Anthropic context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing)：清理旧工具结果有缓存代价，需批量节省和后续复用摊销；本方案不自动启用其 API。
- [Lost in the Middle](https://arxiv.org/abs/2307.03172)：旧证据的位置会影响使用质量；需在实际回答模型上评估，不能直接外推旧论文的性能数值。
- [CacheBlend](https://arxiv.org/abs/2405.16444)：非前缀 KV 复用需推理服务配合；首版排除，不把证据 hash 当作 KV 索引。

v1 的 Adaptive-k／MMR 研究属于新候选选择的历史背景，不再是本版正常跨轮去重的算法依据。

## 10. 真实实验与按需证据恢复（实现与验收约束）

本节扩展既有 v2，不引入通用记忆框架、分层摘要服务、观测平台或任务恢复系统。真实实验沿用 VALIDATION，新增机制只解决“已检索过的本地块被省略后如何精确补读”。

### V2-R22：最小只读工具契约

工具名为 `read_local_evidence`，唯一必填参数 `evidenceId`，格式为当前分支已登记的 `e[1-9][0-9]*`；未知参数拒绝。不接受路径、URL、SQL、profile、hash、scope 覆盖或模型自填的来源定位，不支持首版分页／任意范围裁切。

成功返回单个完整索引块的原始 `text`、稳定 eN、原始绝对 source、chunk ID、正文 SHA256、profile，以及存在时的标题／位置／版本信息和 `complete: true`。位置仍是规范化 Markdown 的 UTF-16 偏移，不能当成原文件字节／PDF 页码。正文不含向量，不生成答案或摘要，不把 heading／embedding prefix 拼成原始正文。

必须从已存在索引按可信精确定位读取，不做相似度查询、query embedding、自动 refresh、下载、自动安装或服务启动。不创建缺失索引；索引不在、版本不符时明确不能恢复。此工具不是新的检索候选，不增加公开检索 resultCount，也不重新评分／排序或伪造新的证据身份。

### V2-R23：可信定位、范围与调用时授权

只有本地索引检索结果可登记读取定位，至少关联 source、source ID、chunk ID、profile、原始完整正文 SHA256，以及足以复核源版本的可信指纹。复用现有登记路径，不从模型返回、普通文本、路径形状或未知 metadata 猜测权限。eN 只是查找入口，不是授权凭证。

每次调用检查当前分支、会话可读范围、search roots 和当前问题的 scope。原始命中 scope 只能作为来源记录，不能扩大当前权限。对本地路径使用一致的规范化／实际路径边界规则，防止前缀相似目录或符号链接变化越界；读取和返回之间复核相关身份，不能检查后换源仍返回成功。

网页、显式 bash/read 登记、原生 datasource、Obsidian opaque identity、其他分支或其他会话的 eN 首版均不能借此读取。不能对 `/kakao/...` 等原生身份执行文件读取，也不能尝试把一个不可恢复的 ID 当路径打开。拒绝结果不泄露当前权限之外的正文或来源定位。

### V2-R24：精确版本与完整正文

正文 SHA256 按原始块 text 计算，不使用 ledger 空白规范化 hash；profile、source 和 chunk ID 也须一致。ledger 的 2000 字符 excerpt 只用于原有用途，不能冒充完整块。现有 IndexStore 尚无精确块读取接口，需在后续代码阶段补最小只读查询，不复用 vector search 或拼接任意 SQL。

检索登记时保存的可信来源版本与读取时来源版本须可比；优先复用现有可靠指纹，不足时只补本地源内容指纹及必要元数据，不保存原文快照。mtime／大小不能单独证明内容未变。还需复核解析镜像与索引块是否属于登记的版本，避免源已变化但旧索引仍在时误报“当前正文”。无法验证版本时明确报告不能恢复，不伪造成功。

源删除、源版本变化、重新分块、profile 切换或索引重建后旧块缺失，不用新块冒充旧 eN；给出重新检索／核验的明确建议，保留旧身份。此版本不承诺恢复已删除的历史正文，不为此新建内容快照库或全盘扫描。不同源即使正文相同也不能替换。

### V2-R25：有界读取、错误和生命周期

首版单块正文上限冻结为 UTF-8 64 KiB（内部保护常量，不新增调参面板），并继续受实际模型输入容量限制。超限必须说明实际大小与限制，不悄悄截断后标 complete；已知错误或无法恢复的结果不能登记成完整锚点。未提供的正文／usage 标缺失，不当作空正文／零费用。

复用现有 AbortSignal 与工具取消边界，查询失败、取消或最终容量失败不提交已呈现状态。结构化不可恢复原因可以辅助调用者，但实际数据库／文件／CLI 错误须保留原始 message、路径及 stderr；不能用固定枚举替代错误文本。拒绝或失败不自动 refresh、切换来源、调用新模型或无限重试。

定位表与现有 ledger 同会话分支、reset/dispose 及有界状态规则协同，不新增独立长期数据库。旧会话没有可信定位时正常恢复既有引用，但该新工具明确不可恢复；不得从 excerpt 猜完整正文。需要跨重启定位时仅用带版本的可选 session 元数据，恢复后重新校验，不能持久化向量、私有正文快照或跨分支锚点。

### V2-R26：最终请求、模式与工具兼容

在当前支持本地检索的主 Agent 的 single/progressive、standalone/Pi 入口注册只读工具；不顺带扩展 Lite MCP、远程 bridge、自动化 profile 或原生 datasource 能力。工具声明在会话开始时稳定配置；`off`／`observe`／`adaptive` 均可显式读取，模式只决定上下文投影。因新增工具产生的 schema／必要提示变更是明确的 epoch 边界，不能声称与加工具前请求完全相同；同一工具面下 off/observe 仍须一致。

显式读取成功的当前工具回包必须提供全文，不能马上被精确去重再次换成短指针；后续普通检索才可引用该已成功呈现的正文。记录 trusted body 边界，复用 prepare → 最终 guard → dispatch → commit/abort；最终 guard 若裁掉正文，不再将其登记为完整锚点，也不能给模型留下误导性的 complete 宣称。补读计入本问题软预算超支、总输入和工具次数，不能自动获得一份新预算。

恢复工具的存在不表示“已核验答案”或“资料覆盖完整”。恢复时不改历史、不重编号、不丢 toolCall/toolResult 配对；容量不足走现有有界修复／明确错误。新策略实现时另记版本 `append-context-v2-evidence-read-experimental`；本轮不修改源码常量，旧版本证据保持原标识。

### V2-R27：真实实验前置条件与冻结

先修复或明确记录现有 npm 缺失和 tokenizer 下载阻塞，在隔离环境取得新代码的结构回归及真实本地索引／语义命中；不能用历史 QA 替代。30 段多轮会话、开发/测试划分及原有质量／成本门槛保持不变，增加整理后补读和版本变化场景，冻结后才访问 test。

仅使用可信配置已经授权的回答模型及非敏感自建语料；未配置授权、缺依赖／资产／完整 usage 时按阶段标 blocked/unavailable。此功能请求不授权自动新增远端 provider、裁判、费用额度或私有正文外发；缺少独立评审时明确披露单人标注，不虚构人工复核。已有判断／规划模型的必要调用同样计入成本。

复用现有 QA／bench 工具，不为实验引入通用平台或运行时依赖。先冻结输入、工具回包与对照实现，区分固定回包结构回放和真实工具＋模型执行；工具参数不匹配时不套用旧回包。不能仅改一个 mode 字符串就把相同代码当作多个消融实现。

### V2-R28：新增工具对照与发布结论

原 V2-A—E 保留；V2-F 为 E 加按需恢复工具及其必要说明。E→F 是工具方案对照，明确计入新增 schema／提示开销和可能变化的工具路径；两组其余模型、语料、权限、题目、总预算和评价规则一致。已有 A—E 的工具面可由实验入口在运行前固定，不新增面向用户的实验开关，不在同次会话中动态增删工具。

使用六类多轮会话，分别报告无补读、整理后补读、源变化而拒绝、重复补读和取消的结果；测恢复成功、错误版本、失效拒绝、补读／重新检索次数、完整会话 token/费用、TTFT、P50/P95 与质量。缓存缺失或不可控共享命中必须披露，不能把正常请求前缀字节一致当实际 KV 命中。

原 E 对 A 的门槛不因新增 F 放宽。F 在可恢复夹具中必须提供匹配完整块，错误版本／越权读取／悬空引用为零；真实回答质量不低于 E。F 不承诺每题更便宜；若质量、费用、延迟均无可证收益，应保留更简单方案，产品默认 off 不变。所有实现、工程 QA、真实本地 QA、质量、缓存、费用分别标状态，不能以一项通过覆盖其余缺失。
