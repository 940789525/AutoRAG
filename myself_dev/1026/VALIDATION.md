# v2 验证计划、发布门槛与证据规范

修订日期：2026-10-27。与 [SPEC.md](SPEC.md) 的 V2-R01—V2-R28 对应。**原 V2-A—E 与 U/I 门槛保留；第 11 节 V2-F、ER-U／ER-I／ER-X 已进入代码验收。实际执行范围和阻塞逐项记录于 IMPLEMENTATION；未执行项保持待验收，不由部分冒烟实验推定通过。** 已执行的工程检查见 IMPLEMENTATION，不能由 v1 绿测或单轮字节数替代真实发布验收。先确定数据、算法、阈值和评分，再实施和测试。

## 本轮用户确认的复核方式

用户已明确选择“由你逐项核对，明确披露为单人自动复核；不宣称独立人工通过”。本次可按来源编写/校验 gold 并进行可复现自动评分，在冻结 dataset/implementation 指纹和该确认后访问 test。报告必须使用 single_agent_automated_authorized_by_user，independentHumanReview 始终为 false；不能把这一确认写成独立人工或独立语义评分通过。原质量、费用阈值不放宽；自动规则无法判断的答案记 needs_review，不记自动通过。

## 当前获准模型与认证边界

DeepSeek 余额不足后，用户明确指定 GPT-6.1 Sol、low 思考；新模型单独冻结并从各组重新运行，不与旧模型费用混算。允许复用有效 Codex 登录的 access 进行内存调用，不允许刷新/改写原认证或复制凭据到工作区；失效则停止并保留原诊断。API-equivalent 价格估算与订阅实际使用额度分开。

## 1. 验证层次与顺序

1. 固定现有 v1 工作区和 v2 规格指纹；原样保存既有未提交工作，不重写历史。
2. 先写正文身份／锚点可见性／前缀稳定／epoch／最终修复的确定性测试，再接实际请求入口。
3. 模拟 provider 捕获多轮实际消息，验证精确去重和容量安全；不把它当真实缓存实验。
4. off / observe 配对验证，再做显式 adaptive；观察计划不污染真实已发送状态。
5. 隔离环境中的真实本地嵌入＋模拟回答请求 QA，核验来源路径与正文。
6. 仅用已有获准回答模型，在开发会话校准整理阈值和提示；冻结后执行盲测。
7. 真实 provider warm / cold 成本、延迟与质量实验；发布结论逐项标 pass / fail / blocked。

## 2. 数据与多轮场景

既有 120 题（六组、48 dev / 72 test）保留为 v1／新候选选择回归素材，仍需独立人工复核；不能把单题改写当成已验证多轮数据。

v2 首轮增加**至少 30 段多轮会话规格**，六类各 5 段，每段 4—8 个用户轮次并包含同轮多次工具调用。按文档家族划分，每类 2 段 dev / 3 段 test，即 12 开发、18 测试。优先扩展既有 fixture，不要求在本规格目录创建数据文件。

| 组 | 内容 | 关键验证 |
| --- | --- | --- |
| M1 | 同主题追问、50% 以上重复块、新增少量事实 | 原前缀稳定、新命中保留、重复正文不再新增 |
| M2 | 主规则／例外／否定／不同金额日期／版本 | 不把相似内容当完全重复，不丢证据边界 |
| M3 | 全量／统计／多来源、启用 Rerank／steering | 精确去重不受题型绕过，新候选覆盖不收缩 |
| M4 | 长证据接近高水位、跨低水位、再次触发 | 集中整理频率、必要正文保留、无反复抖动 |
| M5 | Pi compact、取消／失败／重试、resume／分支 | 无悬空指针、不污染状态、必要时重发 |
| M6 | 主题切换、中文／表格、非本地混合、未知格式 | 容量口径、去重边界与保守降级 |

每轮 gold 标注问题、关键事实、完整性要求、可替代来源、预期版本、是否应补读。记录每个块的原始身份与正文指纹；另标注每次请求仍完整可见的正文锚点。模型输出不能反向当 gold；私人资料不发给 Exa／新远端裁判。测试标签盲化，披露独立评审或单人评审限制。

## 3. 对照组：与 v1 A–F 分开命名

| 组 | 配置 | 目的 |
| --- | --- | --- |
| V2-A | 当前 off，保留既有记忆和容量行为 | 产品现状基线 |
| V2-B | 冻结的 v1 adaptive：历史重选、保留最新 | 比较“短输入但破坏前缀”的现有实验 |
| V2-C | 稳定已发送视图＋记忆追加，不去重、不做新集中整理 | 分离前缀稳定本身的收益；原有硬容量保护保留 |
| V2-D | V2-C＋新结果精确去重 | 分离追加去重的新增量和成本收益 |
| V2-E | V2-D＋高低水位集中整理 | 目标方案，考察缓存损失的摊销和长期容量 |

v1 分差／MMR 若用于新候选，在 V2-C / D / E 中保持一致并单列配置；默认核心对照关闭该可选步骤，不因算法差异掩盖重复去重。A / B 保留真实旧路径，不假装差异只有去重；C→D 与 D→E 才是机制消融。

先用相同工具结果回放保证结构公平，再真实运行工具与模型看补取／输出差异。全部组模型、授权、题目、语料、scope、生成约束和允许工具一致，不单独给 E 更大调用预算。

| V2-U26 | 整理／恢复失败 | 保留已提交状态或显式安全重建，不半更新 |
| V2-U27 | Pi 手动／阈值／overflow 压缩、取消 | 成功重建、失败不假提交；context 回调不调用手动 compact |

| V2-U29 | 未知格式、非本地消息、显式 read | 不猜测正文、不自动去重；容量仍计入 |
| V2-U30 | 去重后 provider 限制移除锚点 | 最终修复再检查容量；安全失败，绝不发送悬空引用 |

| V2-U33 | 缺失容量／usage／tokenizer | 标 unavailable／capacity_unknown，不能声称精确或 0 |

| V2-U35 | 超限后补回仍放不下 | 最多一次整理＋有界修复；保留原始超限诊断，无无限请求 |

属性检查：对同 epoch、固定模型／系统／工具的任意前缀 H 与新增 N，已有已发送消息的序列化应保持不变；恢复／容量／权限等例外必须有对应 epoch 和原因。不得只检查 eN 唯一性或最终块数。

## 6. 真缓存实验：不拿 mock 代替

每种方案完整会话至少运行 3 次，区分首次 cold 和顺序 warm 请求，交错／随机方案执行顺序，记录缓存保留时间、路由／key、并发和 provider 版本。不得擅自清共享缓存、停止已有服务，或在前缀加入动态实验标签来“隔离”后再把损失算给方案。

- 先记录是否支持缓存、是否启用、是否超过最小缓存长度；不可控的共享命中／跨组污染需披露，必要时在独立的获准配置复测。
- 缓存过期但正文仍可见时仍能安全去重，只是无法保证 cache hit；正文已删但缓存可能在时必须重发。
- 分开看无整理的正常请求、发生整理的请求、整理后再次 warm 的请求，并看整段会话成本。
- 只给出前缀字节一致不能宣布 KV 命中；只给出 cacheRead 也不能宣布答案更准确或总成本更低。

## 7. 指标口径

| 指标 | 定义与边界 |
| --- | --- |
| newEvidenceTokensEstimated | 新后缀的本地正文、短引用、路径和省略说明估算；与全输入区分 |
| duplicateBodyTokensAvoided | 相同新结果不去重呈现与短引用呈现的差值，不包括删除历史带来的收益 |
| eligibleDuplicateBodyOccurrences | 确认有完整锚点且短引用更短的新增重复正文数；去重后目标 0 |
| retainedPrefixBytes / Tokens | 本次历史与此前已提交视图可匹配部分；不是服务端缓存已命中量 |
| unexpectedPrefixChanges | 固定条件、同 epoch 正常追加中既有消息被改写次数；必须 0 |
| danglingReferenceCount | 最终请求活动短引用没有更早完整正文锚点的数量；必须 0 |
| compactionCount / Removed / Rehydrated | 整理次数、前后占用、重发正文与原因；包括未达目标和失败 |
| sessionInputTokens / cacheRead / cacheWrite / output | 整段会话所有真实模型调用分别累计，失败可获取 usage 也纳入；不是只统计最终回答 |
| sessionCost | 按实际 provider／模型／缓存读写／输出价格或可信 cost 数据归一化；无法获得则 unavailable |
| TTFT / finalLatency / sessionLatency | 首个用户可见答案、每轮完整回答、整段会话耗时；progressive 分阶段 |
| prepareOverheadP50 / P95 | 新增投影、索引、整理和修复的开销；不混入检索／模型等待 |
| rereadCount / retrievalCalls | 检查短引用是否反而导致更多工具补读 |
| quality / citationSupport | 按 gold 评分每轮与整段关键事实、版本、例外、完整性和引用支持 |

**usage 必须先核对 adapter 语义。** 某些 provider 的 input 已含缓存 token，另一些 SDK 将 input、cacheRead、cacheWrite 分开；不能机械相加或重复扣除。保存原始字段定义、归一化公式和 scope；reasoning 若已包含在 output 中不重复计费。当前日志 `scope=answer_session` 不覆盖全部外部调用，缺字段必须补测或标缺失。

无答案题事实覆盖为 N/A，依据无支撑回答率验收，不伪造 100%。失败、超时、blocked、skipped 都保留，不只统计成功样本。

## 8. 预先确定的发布门槛

以下是 v2 首轮工程门槛；不是已实现收益或跨 provider 保证。未通过不能悄悄调整到刚好通过。

| 维度 | 最低条件 |
| --- | --- |
| 结构正确性 | 全部 V2-U01—U36、V2-I01—I12 通过；raw/API 不丢候选 |
| 来源／隔离 | 0 个来源身份破坏、0 次未经授权外发、0 次真实共享配置写入 |
| 前缀／指针 | 正常同 epoch unexpectedPrefixChanges=0；所有最终请求 danglingReferenceCount=0 |
| 去重效果 | eligibleDuplicateBodyOccurrences=0；没有必要锚点时重发全文，不追求无条件零重复 |
| 整理行为 | 阈值、低水位、每请求一次计划＋有界修复符合规格；无空整理抖动或循环 |
| 质量硬项 | M2／M3／M5 不新增因去重／整理造成的错误版本、例外漏项、虚假全量结论或悬空引用 |
| 整体质量 | E 相比 A 的整段通过数不得减少，关键引用支持率不下降；逐轮和逐组原始计数公布 |
| 新增量收益 | M1 中 D 相比 C 的新增本地证据 token 估算配对中位降幅 >=20%，同时报告实际总 input；样本重复正文占比应 >=50% |
| 正常缓存收益 | 在缓存可用、条件相同且无整理的配对请求中，D 的归一化未缓存输入 token 中位数不高于 C；实际 cacheRead 和缺失比例另报 |
| 整段成本／速度 | 获准 provider warm 会话中 E 相比 A 实际总成本中位数至少下降 10%，整段延迟 P95 不超过 A 的 1.05 倍；B / C / D 全部公布 |
| 自身开销 | 100 个候选正常追加 warm P95 <=100ms；整理和恢复开销另报，不塞进普通路径平均数掩盖 |
| 方案必要性 | 若 E 被 D 在容量安全、质量、成本、延迟同时支配，保留更简单方案，不为复杂度维护无收益组件 |

18 段测试会话样本较小，任何通过都必须附配对差值及按会话 bootstrap 95% 区间，区间跨过无收益则结论为“证据不足”。质量失败保持 off；只验证结构则只报告结构通过；成本通过但速度未改善不宣传加速。新阈值只能在 dev 上校准，修改后重冻结再测，重复使用的 test 不再声称盲测。

## 9. QA 与执行边界

使用仓库支持的 Docker QA；容器内独立临时根，首次运行 CLI／AutoRAGAgent 前同时设置 AUTORAG_HOME、AUTORAG_CONFIG，所有新 shell／子进程重复传递。真实配置存在则运行前后 hash 相同，不存在记 absent，禁止新建占位或覆盖正式 `.vscode/index-debug.config.json`。

真实本地检索需要 Qwen3／1024 维本地后端，保留他人的 daemon，不启动远端嵌入作为隐式回退。没有获准回答模型、完整 provider usage 或可控缓存时只报告已有阶段；不得默默选择新远端服务。原文 source 应为绝对可读路径，原生数据源仍是原生身份。

按 AGENTS 审查 live-E2E／输出契约影响，新行为不得沿用旧 cold/warm 证据。只清理任务临时根与自建进程，保存配置前后哈希、清理回执与原始失败诊断。

## 11. 按需证据恢复与新增真实实验（逐项验收）

本节定义新增验收，不改变原 V2-U01—U36、V2-I01—I12 及 E 对 A 的发布门槛。原代码阶段已执行的结果只证明其对应快照；新增项全部以新执行记录为准。

### 11.1 确定性用例

| ID | 输入／边界 | 必须断言 |
| --- | --- | --- |
| ER-U01 | 有效 eN／非法格式／多余字段／空参数 | 严格参数检查；不把 eN 当路径，不接受覆盖定位 |
| ER-U02 | 当前分支可靠本地命中 | 按 source/profile/chunk 精确读取；零检索／嵌入／refresh／下载调用 |
| ER-U03 | 正文超过 ledger excerpt、中文、表格及原始空白 | 返回匹配完整块与 SHA256；不拼 heading 或规范化正文；位置语义正确 |
| ER-U04 | 普通用户／模型文本伪造 eN 和定位 | 不产生可信读取授权，不访问该来源 |
| ER-U05 | 其他分支、其他会话、memory ID、旧会话无定位 | 明确不可恢复；不猜正文或跨分支取证据 |
| ER-U06 | 收紧 roots／当前 scope／权限后重读 | 当前限制优先；被撤销的旧命中不能凭 eN 读取 |
| ER-U07 | 相似目录前缀、符号链接换目标、并发来源改变 | 拒绝越界或不一致版本；不能只检查原始字符串路径 |
| ER-U08 | 源文件修改但索引未刷新；mtime/大小相同而内容不同 | 不用旧索引伪装当前版本；不能仅依赖 mtime/大小 |
| ER-U09 | 重建索引、不同 profile、同 ID 不同 text | 不把新版本当旧 eN；不同 source 的相同正文不能替代 |
| ER-U10 | 源删除／块缺失／解析镜像版本不明 | 明确不可恢复；不创建索引、不用 excerpt 或相似块兜底 |
| ER-U11 | 同版本完整读取／版本无法复核 | 前者 complete 且元数据可核对，后者不能假成功 |
| ER-U12 | UTF-8 64 KiB 边界及多字节正文 | 边界内完整，超限说明实际大小与限制；无隐式截断 |
| ER-U13 | 数据库／文件异常／取消／无 backend | 原始错误保留；不启动 embedding，不写假 usage 或空成功 |
| ER-U14 | 成功读取后在模型 dispatch/commit 前失败 | 不提前提交锚点，重试保持相同身份和正确正文 |
| ER-U15 | reset/dispose／定位容量淘汰 | 释放状态；淘汰后明确不可恢复，eN 不重用 |
| ER-U16 | session 只保存旧 excerpt 或被伪造定位 | 没有完整可信定位时不升级权限；恢复后仍复核当前版本 |
| ER-U17 | 同一工具面下 off/observe/adaptive | off/observe 最终输入一致；adaptive 显式读取本次不再短引用；后续普通重复命中可引用 |
| ER-U18 | 原生 opaque identity、Obsidian、网页、显式 bash/read 证据 | 首版拒绝此恢复路径；零 OS 误读，无新增原生 store 写入 |

这些是测试责任，不要求一条编号恰对应一个 test；未知来源／配置变化要有独立失败断言。文件读取与索引查询的测试应验证实际拒绝访问，而非只比较返回的原因码。

### 11.2 多入口与最终请求集成

| ID | 场景 | 必须核验 |
| --- | --- | --- |
| ER-I01 | single/progressive、standalone/Pi | 同一最小工具契约，mode 不暗中改变工具注册；不扩展远程 bridge/Lite MCP/profile |

真实本地 QA 要新建隔离索引、完成语义命中、按证据 ID 直接读取长于 excerpt 的原始块，再执行整理后补读及源变更拒绝。保存真实绝对 source 可读性、完整块 hash、索引 profile、读取次数、零额外 embedding 的证据。模拟回答只证明请求与工具结构，真实生成评估另行执行。

M1—M6 各组五段结构不变，其中显式覆盖无需恢复、整理后恢复、重复恢复、源变化／未知版本而拒绝及取消；不要把拒绝过期正文算作无答案失败，也不能把实际需要新版本的任务改成只判“拒绝即通过”。gold 同时指定预期恢复动作、最终答案和允许的新检索行为。开发阈值调整后重冻结，不复用已看过标签宣称盲测。

固定回包回放若参数、scope 或来源版本不同，应明确 mismatch，不能直接喂旧回包。真实模型可能选择不同合法工具路径，不以工具序列完全一致判质量。

V2-F 指 E 加 `read_local_evidence`；E 与 F 的工具面差异是显式干预，不是严格相同输入／前缀实验。新增 schema 和说明的 input／缓存影响单列，但仍计入总费用。实验入口在运行前固定工具面，不为不同组隐式增加模型次数或放宽总预算。

### 11.4 补充指标与门槛

新增指标：完整恢复成功/请求数、版本变化正确拒绝/相关请求数、未知版本次数、越权读取、错误版本返回、补读次数、重新语义检索次数、恢复耗时 P50/P95、实际读取字节、额外 embedding 次数、完整会话费用与任务质量。分母为零记 N/A，不写成 100%；源内容指纹计算等额外 I/O 纳入开销。

- 受控可恢复夹具的正文及元数据必须精确匹配；首版路径不应触发额外 embedding、refresh、自动下载或索引创建。
- 越权读取、错误版本返回、悬空引用、私有正文未经授权外发均须为零。
- 最新结构测试、真实本地 QA、真实回答质量分别通过；缺少获准模型或 usage 时不对质量／成本作结论。
- F 相比 E 不新增关键事实、版本、例外或引用错误；原 E 对 A 的质量和成本门槛保留，不用 F 的少数题覆盖原失败。
- F 可能多一次工具调用，不要求每题更快更便宜；整体收益必须附配对差异、波动和适用场景。区间跨无收益写“证据不足”，仍为实验功能，默认 off 不变。
- 最新版本对受影响 live-E2E／工具说明／API 测试需重新审查；逐项实际结果见 IMPLEMENTATION，工程检查不能替代真实质量门槛。
