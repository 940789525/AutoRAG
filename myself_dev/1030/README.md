## 已确定的决策

1. 本地默认模型固定为现有 `Qwen/Qwen3-Embedding-0.6B`，保持 1024 维，由 Python FastEmbed 运行，CPU 是必测路径；Python HTTP 包装层保持小型，不承担索引、解析和任务调度。
2. 本地/API 向量数据均使用 HTTP 传输，不经过 MCP。TUI 直接调用 AutoRAG 内部任务模块，语言模型只解释自然语言意图，不搬运整批向量。
3. 复用 `src/embedding`、`src/indexing`、`AutoRAGAgent.refresh` 和已有刷新事件，提供内部 start/status/cancel 能力。现有 CLI/程序接口按需兼容，不为本阶段新增外部控制服务。
4. 本地与 API 显式选择，不自动跨提供方降级。API 凭据只引用环境变量；远程发送需要可信配置明确允许。
5. 首次从 MinSync 迁往 FastEmbed 时，同一 Qwen 模型也先建立独立索引 profile 并重新向量化，验收成功后切换。旧索引保留供回退，不直接跨引擎复用未经验证的向量。
6. 移除 MinSync 运行依赖，短期可保留旧字段和方法名称作为弃用别名；别名必须落到 AutoRAG 实现。
7. 首版不引入 Qdrant 服务、Redis、通用 RAG 框架、独立队列或 GPU 强依赖。
8. `BAAI/bge-small-zh-v1.5` 仅作为后续可选性能优化，不是首版默认模型，不在本轮迁移中下载、切换或作为验收前置条件。
9. 现有 MCP 能力保留，只在共享接口变化引起回归时做必要兼容修复；不新增索引 MCP 工具、不新增 MCP 服务或配置要求，不以外部 MCP 索引客户端作为交付前提。

保留 Qwen 模型不等于保证直接复用已有 `safetensors` 文件；FastEmbed 需要兼容的 ONNX 制品，可能需要另行下载同模型制品或转换。具体版本与准备方式见 [02](02-向量服务与配置契约.md)，原缓存保留。

## 发布条件

“能够正常使用”必须由验收证明：无 MinSync 二进制和原生 addon 的隔离环境中，本地/API 均能建索引和查询；TUI 索引操作、记忆和已启用数据源通过相应测试；失败不会破坏已激活索引或静默切换数据边界。现有 MCP 功能按受影响范围做回归检查，不要求新增 MCP 索引接口。验收清单见 [06](06-测试验收与性能评估.md)。

首版目标是在保留 Qwen 模型的同时移除 MinSync 依赖、增加可调试性并保留 API 选择；Python 或 ONNX 本身不能保证提速。模型已确定，ONNX 制品版本、输入上限、分块和批处理参数仍需验证后锁定。未完成制品与许可证核验之前，不发布“安装即用”的默认后端。
