## 已确定的决策

1. 本地推理选择 Python FastEmbed，CPU 是必测路径；Python HTTP 包装层保持小型，不承担索引、解析和任务调度。
2. 向量数据使用 HTTP 传输；MCP 负责发起、观察、取消索引任务，不让语言模型搬运整批向量。
3. 复用 `src/embedding`、`src/indexing`、`AutoRAGAgent.refresh` 和已有刷新事件。TUI 原生入口直接调用同一 TypeScript 服务，外部 MCP 服务再包装它。
4. 本地与 API 显式选择，不自动跨提供方降级。API 凭据只引用环境变量；远程发送需要可信配置明确允许。
5. 新模型建立独立索引 profile，验收成功后切换。旧索引保留供回退，不复用不兼容向量。
6. 移除 MinSync 运行依赖，短期可保留旧字段和方法名称作为弃用别名；别名必须落到 AutoRAG 实现。
7. 首版不引入 Qdrant 服务、Redis、通用 RAG 框架、独立队列或 GPU 强依赖。

## 发布条件

“能够正常使用”必须由验收证明：无 MinSync 二进制和原生 addon 的隔离环境中，本地/API 均能建索引和查询；TUI、MCP、记忆和已启用数据源通过相应测试；失败不会破坏已激活索引或静默切换数据边界。验收清单见 [06](06-测试验收与性能评估.md)。

更快的推理具有可行性，但 Python 或 ONNX 本身不能保证提速。默认模型、输入上限、分块和批处理参数需经真实语料测试后锁定。未完成模型与许可证核验之前，不发布“安装即用”的默认后端。
