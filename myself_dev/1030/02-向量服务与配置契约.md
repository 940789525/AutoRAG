# 向量服务与配置契约

本章定义拟实现的配置和 HTTP 行为。示例不是当前配置文件可直接接受的格式；实施时必须同时补配置 schema、迁移器、校验和测试。

## 统一配置

新配置从 `minSync.embedder` 中独立出来。建议顶层增加 `embedding`，按 profile 选择，不把凭据放在配置或命令参数里。

```json
{
  "embedding": {
    "defaultProfile": "local-zh",
    "profiles": {
      "local-zh": {
        "kind": "local-http",
        "protocol": "openai",
        "baseUrl": "http://127.0.0.1:18382",
        "model": "BAAI/bge-small-zh-v1.5",
        "dimension": 512,
        "modelManifest": "./models/local-zh.manifest.json",
        "allowedConsumers": ["local-documents", "memory", "chat-sidecars", "gist", "native-cli"],
        "batchSize": 16,
        "maxConcurrent": 1,
        "timeoutMs": 120000,
        "maxRetries": 2
      },
      "api-example": {
        "kind": "api",
        "protocol": "openai",
        "baseUrl": "https://embedding.example.com",
        "model": "YOUR_EMBEDDING_DEPLOYMENT",
        "dimension": 1536,
        "modelManifest": "./models/api-example.manifest.json",
        "apiKeyEnv": "AUTORAG_EMBEDDING_API_KEY",
        "allowRemote": false,
        "allowedConsumers": ["local-documents"],
        "batchSize": 16,
        "maxConcurrent": 1,
        "timeoutMs": 120000,
        "maxRetries": 2
      }
    }
  }
}
```

`api-example` 的域名、部署名、维度均为占位示例；`allowRemote:false` 故意禁止发送，配置者确认提供方和数据范围后才能开启。`allowedConsumers` 首版取 `local-documents`、`memory`、`chat-sidecars`、`gist`、`native-cli` 的明确集合，不支持隐式 `*`。每个消费者的检查必须发生在 HTTP 请求前。

本地 profile 同样声明消费者范围，作为共享策略，但本地无需远程 opt-in。示例列出本地共享的目标消费者，不代表外部 CLI 已通过兼容验证。默认消费者集合由发布配置显式给出，不由模型推断。相对路径相对于配置文件目录解析。模型 manifest 属于受信配置，不能从语料中的指令加载。

## 模型 manifest 与向量身份

每个可用 profile 的 manifest 至少锁定：模型 ID、模型文件版本/哈希或提供方部署版本、tokenizer 版本/路径、维度、实际最大输入 token 数、pooling、normalization、query/passage 前缀、FastEmbed 是否额外预处理。

对远程 API，若提供方不公开模型内部细节，记录提供方声明的版本与 `provider-managed`，另设操作人员维护的 `deploymentRevision`；变化时使 profile 失效并重建。不得伪称已验证隐藏模型权重。

身份分两层：

1. `runtime`：端点、鉴权环境变量名、CPU/GPU、批大小、超时，用于连接与诊断。
2. `semanticFingerprint`：模型/部署版本、维度、tokenizer、pooling、normalization、角色前缀及预处理版本，用于索引与向量缓存兼容性。

另用 `indexFingerprint` 记录解析、chunker 和词法分析版本及参数。改变分块策略时重新生成 chunk，并仅在文本和语义指纹均相同的情况下复用向量。

更换端口不应单独强制重建；仅维度相同不代表可以复用。API 与本地实现默认按不同 profile 隔离，除非通过专门的一致性验证。服务声称的 model 与配置不一致必须失败。现有各消费者仅使用 `EmbeddingIdentity` 的地方需补足语义指纹，避免前缀或版本变化后误用缓存。

## 本地 HTTP 接口

以下接口由拟新增 Python 包装层提供，FastEmbed 本身不会自动提供这些路由。端口 `18382` 是可配置示例，不是必须占用的固定端口。

| 方法与路径 | 约定 |
|---|---|
| `GET /health` | 真正就绪返回 200；加载中或不可用返回 503，包含原始诊断 |
| `GET /v1/models` | 返回已加载且允许调用的模型 ID，不扫描和下载任意模型 |
| `GET /autorag/embedding-info` | 返回 manifest 身份、实际输入上限、前缀责任、批限制和运行设备 |
| `POST /v1/embeddings` | OpenAI 兼容的批量字符串输入与浮点向量响应 |

请求示例：

```json
{
  "model": "BAAI/bge-small-zh-v1.5",
  "input": ["需要向量化的段落一", "需要向量化的段落二"]
}
```

响应要求 `object:"list"`、实际 `model`、`data`；每条 `data` 包含 `object:"embedding"`、唯一的 `index` 和 `embedding` 数组。512 维模型的每个数组必须恰有 512 个有限数值，不在说明中省略数组后冒充可发送 JSON。

首版只支持字符串数组和 float 向量；不接收 token ID 输入、不提供任意路径模型加载。遇到未知模型、超过批次/字节/token 限制应返回明确 4xx。服务推理失败返回 5xx 与诊断。对包含用户正文的错误不另行上传遥测。

`/health` 返回 404 不能视为本地模型就绪。远程提供方可能没有该接口，因此 API 连通性验证使用其协议文档和显式小型 embedding 探测；探测内容应为非敏感固定文本，且仍遵守远程授权。

## 前缀与 token 限制

统一规则：AutoRAG 客户端按 `role` 添加 query/passage 前缀；HTTP 服务把传入文本视为完整待嵌入输入，不再自动添加同类前缀。

FastEmbed 的模型适配可能自带文档或 query 预处理，Python 实现必须实际检查所选版本的行为，关闭重复预处理或实现经过测试的原始推理路径。若无法保证上述责任边界，该模型不能进入首版支持列表。不能通过“再调一次 embed”猜测等价。

分块预算必须覆盖最终输入中的标题、上下文、前缀与特殊 token；使用与服务相匹配的 tokenizer。服务端再次验证并拒绝超长，禁止静默截断。

中文候选的官方输入窗口是 512 tokens；可从 `targetTokens=320`、`maxTokens=448` 开始评测，但最终值以实际前缀和服务 tokenizer 实测为准。[模型资料](https://huggingface.co/BAAI/bge-small-zh-v1.5)

当前索引默认 `maxTokens=768`，不能直接套用到 512-token 服务。远程 API 也需已验证的 tokenizer 或可靠计数器；未知别名不能触发任意模型下载。长查询应明确报错并提示缩短，首版不静默截断或改写问题。

## TS 接口调整

保留 `Embedder.identity/embed/capabilities` 主干和 `EmbedOptions.signal`。`ManagedEmbedder` 增加准确的 `local-http` / `api` / `none` 健康分类、语义指纹及就绪元信息；`describeEndpoint` 的分类同步更新所有外部 CLI 适配。

旧的 `daemon/in-process/remote` 分类可以在旧输出适配中保留，但不能让 FastEmbed 被误认成 MinSync daemon。连接与推理探测不能调用安装器。`close()` 只关闭自身资源；是否拥有服务进程由独立生命周期对象判断。

HTTP 响应统一检查：条数一致、index 为连续且唯一的整数、每个维度一致、数值有限且不是零向量、model 与声明规则一致。向量排序恢复输入次序，校验完成后才交付消费者。规范化是否需要执行由 manifest 明确，禁止无版本的自动修正。

现有 HTTP batch 默认 32 且内部串行。首版保留单并发，测量后调整 batch；`maxConcurrent`、`maxRetries` 若接受配置就必须传到实际实现，不能出现 schema 接受但运行忽略的字段。

仅对可恢复网络错误、429 和明确可重试 5xx 做有上限的退避，遵守 `Retry-After` 与总截止时间。401/403、模型错误、维度错误、超长输入不盲目重试。取消优先于等待重试。诊断保留 HTTP 状态、原始错误和失败批次位置；不要记录鉴权头。

## Python 运行约束

固定 Python、FastEmbed、ONNX Runtime 和 HTTP 层依赖，CPU 与 GPU 使用独立依赖组合，避免两个 ORT 变体互相覆盖。模型实例单次加载，首版一个推理工作槽，有界等待，过载明确返回忙碌。

模型下载只在明确准备/启动操作中执行，展示模型、大小、来源和缓存路径；校验模型文件后才标记 ready。已准备模型在断网下可启动。请求取消可以结束 HTTP 等待，但正在执行的 ONNX 计算未必可立即中断；不得承诺立刻释放所有 CPU/GPU 资源。

模型库许可证、模型权重许可证和再分发条件分别核验。不能因为 FastEmbed 许可宽松就推定每个支持模型都可无条件分发。
