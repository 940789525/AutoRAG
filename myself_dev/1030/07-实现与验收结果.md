# 实现与验收结果（2026-10-31）

主体代码已实现，本地真实 Qwen 路径通过验证。**目前不能把 05/06 的完整发布门禁标为全部通过**：真实网上 API 缺少运营者授权配置/凭据，新的 Docker QA 镜像被 Docker Hub 网络超时阻断，原生外部账号/数据源以及真实对话模型自然语言操作未做 live 验收。以下将通过的证据与这些缺口分开记录。

## 实际架构

```text
TUI /index 命令（不需要对话模型）
或明确的自然语言请求 → Pi 原生 manage_local_index 工具
        ↓
IndexJobs：start/status/cancel、持久化、进度、幂等与 owner 生命周期
        ↓
AutoRAG：原文解析 → 分块/token 预算 → 缓存 → 写入 LanceDB
        ↓                              ↑
共享 Embedder/profile → HTTP → 本地 Python FastEmbed / 授权 API
        ↓
候选索引查询验证 → 原子 ready.json 激活 → vector/BM25/hybrid 查询
```

FastEmbed 只生成向量，索引由 AutoRAG 持有。没有新增 MCP 协议、索引 MCP 工具、独立向量数据库或后台任务服务。Pi 维持 1.4.0。Python 服务及模型清单随 `dist` 打包，源码和发布安装都能定位它们。

本地固定 Qwen3-Embedding-0.6B、1024 维、CPU、last-token pooling、L2 normalization。使用 Qdrant 同模型 ONNX 制品 `af95f2c416ffe9379369ad64f9113e865db6112c`，六个文件逐项 SHA256 校验。没有切换 BGE、量化或 GPU。ONNX 权重约 2.38 GB；旧 MinSync 缓存未改动，旧向量不自动复用。

## 入口与配置

可在 TUI 使用：

```text
/index build --embedding local-qwen3
/index status
/index refresh
/index cancel --job JOB_ID
/embedding status
/embedding on
/embedding off
```

`status` 同时显示最近任务和实际活动 profile/就绪状态。候选失败不会把“失败的目标 profile”显示成已激活模型。构建异步执行，进度、错误和报告可追踪；进程退出时协作取消自己的任务，只关闭自己启动的服务。

本地/API 都使用同一个 HTTP 客户端。API profile 必须在可信配置中显式授权 `allowRemote` 和消费者集合，凭据仅引用环境变量。`/index build --embedding online` 选择已配置的 API；切回本地同样先 build。API 错误不会隐式切回本地。文档授权不自动授权聊天、邮件、memory 或原生 CLI。

自然语言写操作还检查当前用户明确请求的操作类型；“查看索引”不授予 build 权限。未登录对话模型时使用上面的命令。真实 LLM 是否正确选择工具仍需对应模型凭据做 live 验证；路由、原生工具和命令调用已有自动测试。

完整配置、安装和迁移用法以 [实际运行说明](../../docs/embedding-setup.md) 为准。迁移脚本只预览或写入一个新文件，拒绝覆盖输入和已有输出。本次没有修改真实 `~/.autorag/config.json`，没有替换日常运行配置或重启现有开发容器。

## 实现范围

- 新配置和 manifest 严格校验；角色前缀只在客户端加一次；HTTP 有界重试、取消、超时和向量完整性检查。`maxConcurrent` 首版只支持 1，并串行化共享请求。
- 每次 build 建立独立 generation，查询验证通过后原子激活。失败/取消保留旧活动索引；refresh 复用未变 chunk，可如实报告部分提交。查询在首个 await 前固定索引代。
- 任务写入共享索引锁，提交请求也有短期锁；历史 requestId 可幂等重试。任务记录带版本、owner、PID、配置指纹及终态；Linux 另核对进程启动标识。局部 scopeIds 明确拒绝，首版只索引全部已配置本地根。
- memory、聊天 sidecar、Gist 使用语义指纹；Obsidian 在共享 profile 变化时重新建立身份，不混用同维度向量。各消费者独立重建，不宣传全局原子切换。
- mailcrawl/discrawl/Hister 识别本地 HTTP 与 API。Hister 保持本地边界。lazykatok 现有接口无法传递 Qwen 角色前缀，因此其 CLI 保留原生独立配置；AutoRAG 的聊天 sidecar 仍单独受消费者授权约束。
- 删除 MinSync daemon、in-process/native addon、安装器与执行客户端。保留 `minsync` 方法名、`minSync.embedder` 转换和 `syncMinSync` 等兼容名称；它们不执行 MinSync。旧导出的执行客户端不再可用。
- 更新开发/QA Docker 定义、Compose healthcheck、live runner、安装包资源、setup/doctor 技能与迁移文档。Docker 定义已更新，镜像尚未成功构建。

## 性能与边界

实测为 i7-10750H / Linux-WSL、12 逻辑 CPU、约 15.57 GiB 内存，未使用 GPU。18 个合成源文档含 PDF 和长 Markdown，生成 26 个 chunk、25 个独立向量：

- 本地 build 约 36.05 秒，其中 embedding 约 33.99 秒。
- 无变化 refresh 约 13.5 ms，18 个文档 unchanged，重新 embedding 为 0。
- 修改一个文档约 310 ms，仅重新 embedding 1 个 chunk；删除一个文档约 69 ms。
- 32 个不同问题，热查询 p50 约 257 ms、p95 约 359 ms，失败为 0。中文、英文及双向跨语言目标的合成集 Recall@5/@10 均为 100%。
- 常驻 Python 服务一次观测 RSS 约 1.97 GiB，Node 测试进程峰值约 0.82 GiB。准备好模型后的发布包启动约 35.66 秒，包含文件校验约 25.49 秒与加载约 7.51 秒；当时同时运行回归，不能当作独占机器的基准。

这些是小型合成集证据，不能替代真实资料评测。没有旧 MinSync 的可复现实测基线，不能宣称提速、相对 Recall 达标或引擎间位级等价。尚未在 4 CPU/8 GiB 容器限制下复测；真实 API、原生账号/store、Windows/macOS、GPU 和真实 LLM 自然语言选择仍未验证。BGE、量化、GPU、MCP 扩展均保持后续独立任务。

## 本次保留与后续人工支持

项目内 Python 环境 `.venv-embedding` 已准备并被本地服务控制器自动识别，不跟踪提交。已下载验证的 Qwen ONNX 与 Kiwi 制品保留在本克隆 `.autorag/embedding-models/`，同样不提交；它们不是对共享 MinSync 缓存的替换。若复用该目录启动服务，需同步给 profile 配置对应的本地 tokenizer 路径，示例见运行说明。

真实 home 配置前后均不存在（ABSENT）；所有验证使用独立临时 home/config。合成 runner 已清理其临时工作区，本次启动的 FastEmbed 服务、临时 PyPI 中继和打包测试子进程已停止。没有清理别人的卷或原生存储，也没有推送或切换分支。

要继续完整验收，需要运营者将所选 API 的凭据配置到本机环境变量并指定可信 profile（不要在聊天中粘贴 key），以及恢复 Docker Hub 拉取网络后重跑隔离镜像/live QA。当前不宣告整体发布门禁完成。
