# 测试验收与性能评估

以完整路径与故障行为证明可用性。最低要求是：不安装或运行 MinSync，本地 FastEmbed 和显式授权的 API 都能完成真实索引与检索，TUI/MCP 可以操作，失败不会混用向量或破坏原文。

本章是后续实施的验收要求，不代表这些验收现在已经执行。此前 Pi 升级检查也不能替代新向量后端验证。

## 静态检查与相关测试

实现后执行仓库要求：

```bash
bun run check
bun run lint
bun run typecheck
bun run supply-chain
bun run build
```

`check` 会写文件，执行前确认改动边界，保留其他既有改动。供应链 gate 按仓库生成/刷新 SBOM 的实际流程运行；增加 Python 依赖和模型制品时，另附 Python 依赖树、版本/哈希、许可证清单，不能把 TS gate 通过当成全部依赖已审计。

运行覆盖 embedding、索引、配置、刷新、MCP、TUI、memory、受影响 datasource 和 research 的测试；最终移除阶段执行完整测试套件。测试文件名以实施时工作区为准，不能因本地文件未跟踪而漏掉现有研究/索引测试。

## 核心验收矩阵

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| A01 | 无 MinSync 二进制和 addon | setup/status、build/refresh/search 不安装、不探测启动、不动态加载 MinSync |
| A02 | FastEmbed 本地冷启动 | 显示加载状态，只加载一次模型，实际 ready 后才接收推理 |
| A03 | 已下载模型断网启动 | 本地 build 与查询成功，无远程 embedding 请求 |
| A04 | API 已授权且凭据正确 | 真实提供方 build/查询成功，profile 与发送范围正确 |
| A05 | API 未授权/缺凭据 | 第一批正文前失败，不回落本地或其他 API |
| A06 | 本地与 API 双向切换 | 新 profile 重建后查询成功；相同维度不同模型也不能复用旧向量 |
| A07 | 普通查询 | 不触发解析、索引更新、模型下载或隐式 refresh |
| A08 | 来源验证 | 命中原始文件路径绝对、存在、可读；解析镜像不是最终假来源 |
| A09 | 全链路可调试 | parse/chunk/cache/embed/write/maintain 分段计时、计数与原始失败可查 |
| A10 | 新配置及旧兼容输入 | 一致转换、冲突报错、旧别名执行 AutoRAG 而非 MinSync |

API 协议模拟只能证明请求/响应处理正确，不能替代 A04 的真实提供方测试。真实 API 仅用无敏感 fixture，先核实可信配置 opt-in，记录提供方/模型/维度和成功证据，不记录 key 或完整鉴权报文。

## 索引与故障验收

| 编号 | 场景 | 预期 |
|---|---|---|
| B01 | 首次 build | 计数正确，完整文档提交，激活 manifest 正确 |
| B02 | 无变化 refresh | 不重新嵌入未变化 chunk；缓存复用与 unchanged 可解释 |
| B03 | 修改/新增/删除 fixture | 对应 chunk 更新或删除，未变化内容不多算 embedding |
| B04 | 相同模型改端口 | 语义指纹未变且模型验证一致时可复用 |
| B05 | 改模型/版本/前缀/tokenizer | 指纹失效，不混用向量，必要重建明确 |
| B06 | 超长段落与长查询 | 分块在真实 token 预算内；长查询明确报错，无静默截断 |
| B07 | 缺向量、乱序、重复 index、NaN/Inf、零向量、错维度 | 在共享边界拒绝，未污染文档/记忆/sidecar 存储 |
| B08 | 429、5xx、网络超时 | 有界重试可观测，最终原始错误保留；401/403 不盲重试 |
| B09 | embed 或 write 中断 | journal 可恢复，无半文档；已提交增量结果如实报告 |
| B10 | build 失败或取消 | 旧激活索引仍能查询，不指向半成品 profile |
| B11 | 切换时并发查询 | 查询固定旧或新的一代，不能新模型配旧向量 |
| B12 | 两进程竞争写入 | 只有一个任务写，另一个 busy/返回已存在 jobId |
| B13 | 幂等重试 | 相同 requestId 不重复建库，不同参数报冲突 |
| B14 | owner 崩溃/重启 | 孤立任务 interrupted，允许显式恢复刷新，不伪报成功或继续运行 |

普通 refresh 的失败可能让索引处于 degraded，并保留已提交文档；验收不能要求并未设计的全库事务回滚。候选 build 则必须满足激活前全量成功条件。

## TUI 与 MCP 验收

| 编号 | 场景 | 预期 |
|---|---|---|
| C01 | 无对话模型登录 | `/index build/status/cancel` 可用，API embedding 凭据独立检查 |
| C02 | 有对话模型的自然语言 | 正确调用受限操作工具，不先因缺索引而检索失败 |
| C03 | 索引中查看/取消 | TUI 可响应，显示 jobId、阶段和实际状态 |
| C04 | 退出/断开/重启 | 符合 owner 生命周期；任务终态准确，无无主后台承诺 |
| C05 | MCP stdio 客户端 | start 迅速返回 jobId，status 能获得终态与报告，cancel 有效 |
| C06 | MCP readOnly | 写工具不可用，不能只靠注解限制 |
| C07 | scope/profile 越界 | 服务端拒绝未配置目录、未批准 URL/profile 和远程发送 |
| C08 | 取消传播 | 正在等待 HTTP、重试、阶段切换能终止；ONNX 不可抢占时界面状态准确 |
| C09 | 搜索与索引命令交错 | 命令不被当成搜索 steering；索引和查询资源不失控 |

MCP 2025-11-25 的 progress 为请求关联能力；若使用应按协商 token 转发，不把已结束请求当作无限通知通道。[MCP Progress 规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/progress)

## 共享消费者验收

memory、各聊天 sidecar、Gist、Obsidian、Research 分别验证新模型可用、指纹失效、错误传播和原有词法降级规则。尤其测试同名模型前缀/版本变化，避免仅 model/dimension 比较带来的误复用。

discrawl、lazykatok、mailcrawl、Hister 分别验证 endpoint 格式、前缀、凭据引用与本地/远程分类。Hister 不因 API 默认 profile 而被自动改成远程；外部原生配置改写保持显式操作。

真实 native store 缺失时记录 SKIP 与具体原因；已存在且配置有效却失败时记录 FAIL。任何未验证的外部模型共享组合都不应出现在“全部兼容”的交付结论里。

## 隔离运行要求

优先使用更新后的 Docker QA 入口：仅挂载本克隆，临时 HOME，不挂载真实主机 HOME/native stores，不传默认主机凭据。现有 runner 含 MinSync health/启动约束，必须先改成新后端再用，旧的绿色证据不能复用为新后端证据。

如确需在主机运行手工 QA，每次新的 shell 都先设置隔离路径：

```bash
QA_ROOT="$(mktemp -d /tmp/autorag-embedding-qa.XXXXXX)"
export AUTORAG_HOME="$QA_ROOT/.autorag-home"
export AUTORAG_CONFIG="$AUTORAG_HOME/config.json"
mkdir -p "$QA_ROOT/docs" "$AUTORAG_HOME"
echo "$AUTORAG_CONFIG"
```

确认输出在本次 QA_ROOT 下后，才能执行任何写配置命令。此处只演示隔离准备；新 `/index` 和 profile 配置须等实现后按真实 CLI 用法加入 runner。

手工 QA 前后记录真实 `~/.autorag/config.json` 的哈希，两者必须相同；文件不存在则前后均记录“不存在”。不得借 QA 修复或覆盖它。清理只处理本次 QA_ROOT、测试创建的进程和卷；不能停止共享 MinSync 或删除共享模型缓存。

固定 fixture 至少覆盖中文、英文、中英混排、长文、标题/列表、PDF 解析和非 ASCII 路径。文档索引命中后检查 `source` 绝对路径、存在和可读；原生 datasource 则检查其 source-native 身份，不当作 OS 路径读取。

## 性能与检索质量

比较旧 MinSync 基线、FastEmbed CPU、授权 API 三条路径；GPU 可另列。若旧基线受黑盒限制无法拆分，记录可获得的端到端时间，不伪造内部耗时。

使用相同原文、明确记录 chunk 策略，分别统计解析、分块、embedding、索引写入和查询。模型 token 窗口不同时既报告真实最终配置的端到端指标，也报告字符/tokens 量，不能只比较 chunk/s 掩盖分块数差异。

| 指标 | 测量方法 |
|---|---|
| 冷启动与首次下载 | 下载、加载、首次推理分开；不能把下载时间算成每次推理时间 |
| 全量构建 | 相同语料量，记录字符/token/chunk 数和各阶段时间 |
| 无变化刷新 | 记录 unchanged、reused、embedded；验证非必要重算为零 |
| 小幅增量刷新 | 固定少量修改，记录实际重算量与总耗时 |
| 向量吞吐 | inputs/s、tokens/s、batch、CPU/线程限制、峰值内存 |
| 查询延迟 | 模型热启动后至少 30 次，报告 p50/p95 与失败率 |
| 检索质量 | 固定至少 30 个含中文/英文的问题和人工相关文档标注，比较 Recall@5/10 |
| 资源占用 | Python+Node 总峰值 RSS、空闲驻留、索引和模型磁盘；GPU 另记显存 |

建议初始放行门槛：核心正确性和隐私/模型身份测试全部 PASS；关键来源定位用例全部命中；固定评测集 Recall@10 相比可获得旧基线下降不超过 5 个百分点；本地 embedding 阶段吞吐至少提高 30%，否则不能以性能改进为迁移收益。以上性能/质量数值是项目拟定门槛，不是已有测量结果；若基线缺失，必须另定有人工标签的绝对质量门槛再验收。

资源门槛以实际可用内存和当前 4 CPU / 8 GiB 开发容器为准，至少不发生 OOM、不持续阻塞 TUI。API 路径记录实际网络延迟、429 和费用相关用量，不能与本地吞吐混成一个分数。

## 最终移除审计与证据

用 `rg -n -i 'minsync|minSync|@nomadamas/minsync-native' src scripts skills package.json bun.lock myself_dev` 生成引用清单，逐项区分运行调用、弃用转换、历史说明和测试 fixture。`rg` 零结果不是唯一标准；应检查动态导入、子进程执行、安装器、镜像下载和启动脚本。

最终证据应包含：基线/实现版本、依赖和模型 manifest、环境资源、命令与退出码、测试数量、API opt-in 范围、后端与模型身份、build/refresh/query 报告、来源可读证明、故障恢复结果、原配置哈希前后对照、清理记录和未测范围。

MinSync 缺失时核心路径仍 PASS，才证明运行依赖已移除。历史别名可暂留，但必须附清单与后续移除策略。所有证据使用无敏感 fixture，不提交真实语料、key 或登录文件。
