# 开发顺序与交付边界

以小步替换并保留每步可验证的结果，最终目标是保留 Qwen3-Embedding-0.6B、使用 FastEmbed 完整移除 MinSync 运行依赖，并保留网上 API 选择。阶段性接通不代表整体迁移完成，不能以单次 HTTP 成功替代系统验收。

本阶段新增入口限于 TUI 索引命令和自然语言原生工具。MCP 索引工具、协议进度/Tasks 与外部客户端接入均延期；现有 MCP 能力仅做受影响的兼容回归。

## M0 核对基线与依赖方案

先检查当前工作区改动与 Pi `1.4.0` 依赖，不切走或覆盖正在进行的研究/索引改动。核对现有 `src/embedding`、`src/indexing` 与 TUI 的接口，记录当前受影响测试与构建状态；`src/mcp` 只核对共享变更的兼容影响，不规划新增功能。

准备待审的依赖和模型清单：Python 版本、支持当前 Qwen 的 FastEmbed 版本、ONNX Runtime、FastAPI/Uvicorn 及同模型 ONNX 制品。记录版本、许可证、下载来源与哈希，核对现有缓存版本和可复用文件；新增依赖/后端的批准按仓库要求在实际引入前完成。当前文件写作不等于批准任意版本或模型许可。

完成条件：依赖方案明确、现有数据边界有记录、受影响消费者全部列出，能够在隔离环境复现实验。Pi 已升级，不在本阶段重复改锁文件。

## M1 实现 Qwen 本地向量服务并锁定制品

建议新增一个独立的小型 Python 包目录，如 `scripts/embedding-service/`，容纳应用、依赖锁定、模型 manifest 和服务测试；具体打包方式需支持源码及发布安装，不依赖发布包中未包含的脚本。

实现 [02](02-向量服务与配置契约.md) 的 HTTP 契约：一个常驻 Qwen 模型、真实 readiness、明确输入限制、输出验证和可观察日志。首版固定 `Qwen/Qwen3-Embedding-0.6B`、1024 维、`local-qwen3` profile，不开展 BGE 默认选型或下载。

关键验证：同模型 ONNX 制品来源和转换、FastEmbed 的实际前缀/预处理行为、last-token pooling、L2 normalization、tokenizer 限制、CPU 常驻内存和批推理稳定性。优先保留现有分块参数，以真实服务 2048-token 限制作为初测起点；确认中文、英文及跨语言检索正常。默认模型已确定，制品仍须附可复现 manifest，不能把模型名当作制品版本。

完成条件：同模型制品已锁定且不覆盖旧缓存；断网可从准备好的缓存启动；模型只加载一次；有正常、超长、模型错误、过载和服务异常测试；与同版本 Qwen 的参考推理在输入处理、数值与检索质量上完成一致性验证。首版仍独立重建索引，不因该验证通过就自动复用旧向量。没有这些证据就不进入全项目默认替换。

## M2 接入新配置与共享 Embedder

主要修改 `src/embedding/{embedder,index,managed,http-embedder,settings}.ts` 和 `src/cli/config.ts` 的 schema/转换入口。目标是本地和 API 都能通过现有 Embedder 契约调用，且无 MinSync 前置探测。

补足消费者授权、语义指纹、capabilities、严格响应验证、重试/超时/取消和真实健康检查。旧配置解析在兼容模块中隔离，不让新 embedder 工厂继续依赖 `src/minsync/types.ts`。

完成条件：本地/API 的确定性测试都通过，缺凭据和未授权状态在发送正文前被阻止；配置字段确实影响运行行为；所有共享消费者能识别新的 endpoint 类型。

## M3 索引与任务服务

主要修改 `src/indexing/{pipeline,types,method,lease,journal}.ts`，新增轻量任务服务并桥接现有 refresh 编排。先实现无对话模型的 start/status/cancel，再增加 UI。

实施重点：token 预算、缓存指纹、同模型换引擎首次重建、候选 profile、原子激活、查询绑定、整文档提交、跨进程写锁、幂等、取消和孤立任务。尽量保留现有分块/词法/缓存算法，不顺带重写索引引擎。

完成条件：两种后端均完成真实文档 build、查询和增量 refresh；模型切换失败或取消不切活动指针；重复请求和竞争任务不会双写；原文与证据 handle 校验保持正确。

## M4 TUI 索引命令与自然语言操作

主要修改 `src/agent/{agent,pi-session,embedding-controls}.ts` 和相关命令/帮助入口，更新帮助与相关技能。TUI 直接调用内部任务模块，不经过 MCP，不新增对外任务服务。

先实现不依赖 LLM 的 `/index` 命令，再加入自然语言操作路由和原生操作工具。结构化参数与命令入口共享验证，不写任意 shell 调用。start/status/cancel 是内部 TypeScript 能力，不注册为新的 MCP 工具。

完成条件：未配置对话模型时可通过命令建索引；有对话模型时自然语言能发起、查看和取消任务；UI 在索引时保持可响应；退出持有任务的 TUI 进程时得到准确终态；本地/API 选择和数据边界一致。不以新增 MCP 工具或外部客户端测试作为完成条件。

## M5 全消费者与部署迁移

逐项执行 [04](04-MinSync移除与兼容迁移.md) 的消费者表，先验证真实的 endpoint、前缀和身份约束，再决定可宣传支持的范围。

更新本克隆开发镜像/Compose/healthcheck、正式 QA 镜像、安装包资源、live-E2E runner、setup/doctor/技能说明。容器入口改成 FastEmbed；保留现有独立 home、模型缓存、工作区卷，不做 `down -v`。

Research、Obsidian、memory、chat sidecar 等不能由于旧方法名或类型被删除而静默失效。原生 CLI 缺环境时写明 SKIP 原因；已配置且运行失败必须 FAIL，不能在总表隐藏。

完成条件：所有启用的消费者通过；未启用/环境不可用的消费者列出缺口与诊断；无隐藏 MinSync fallback；新镜像依赖、模型许可和资源预算达标。

## M6 移除旧运行路径与交付

删除旧 daemon/in-process/安装器及原生 addon 运行依赖，清理旧启动与自动安装引用。保留兼容别名的范围按 [04](04-MinSync移除与兼容迁移.md) 显式列出；不能保留实际执行 MinSync 的“兼容”导出。

执行 [06](06-测试验收与性能评估.md) 的最终门禁，包括无 MinSync 镜像、两后端、TUI 索引操作、恢复、共享消费者和供应链检查；现有 MCP 仅按受影响范围回归。生成迁移说明、回退说明、测试结果、模型清单与性能报告。

完成条件：全部必需项 PASS；任何失败、SKIP 或未测范围都在交付摘要列明。未满足则保持迁移未完成，不能宣布系统已稳定切换。

## 任务拆分原则

- 每阶段以明确接口和验收为边界，可审查后继续；不并行改同一套配置和身份定义。
- 不为简单入口新增通用框架；复用现有 refresh 与进度代码。
- 新运行依赖和模型制品在选型完成后按仓库要求确认；不扩大到 GPU、rerank 或 P2P 变化。
- 不更新无关业务行为、不迁移用户原文、不触碰共享真实 home 或其他克隆进程。
- 性能优化放在正确性之后，只针对计时证明的瓶颈调整。

## 迁移完成后的可选优化

MCP 扩展放在后续独立任务中：只有需要其他 AI 客户端远程/跨进程操作 AutoRAG 时，再将已实现的内部 start/status/cancel 包装成 MCP 工具，并另行设计权限、进度、生命周期与客户端验收。本阶段不注册这些新工具、不提供新的客户端配置、不升级 MCP SDK 或协议能力。

`BAAI/bge-small-zh-v1.5` 留在后续独立任务中。先确认 Qwen/FastEmbed 的真实耗时瓶颈，再决定是否为中文为主的场景增加该模型。引入时需独立 profile、明确下载、重新向量化和语言质量验收，不替换本轮确定的 Qwen 默认值，也不作为 M0 至 M6 的前置条件。

## 最终交付物

包括实现代码、锁定的 Python/TS 依赖、可复现模型 manifest、本地/API 配置示例、迁移预览与回退说明、TUI 索引命令及自然语言用法、隔离 QA 证据和资源/质量对比。新增 MCP 工具与客户端配置不在本阶段交付物中。当前这组文档只完成设计准备，不替代上述实现交付物。
