# 验收与评测

## 1 评测目标

评测必须分别回答：是否听懂用户、是否补齐正确参数、是否选对索引操作、是否真的执行了不该执行的写任务、节省或增加了多少模型调用。

仅验证 schema 合法或 mock 工具调用成功，不足以证明自然语言识别有效。真实模型评测必须记录所用提供方、模型 ID、提示词与规则版本、运行时间、样本和失败记录；无法调用的环境记为 SKIP，不能记为 PASS。

## 2 核心语义样例

这些样例是种子集，不是已经运行的测试结果。无特殊说明时，假设只有一个已配置本地 profile，全部配置目录可访问；涉及任务的样例另行提供当前会话任务夹具。

“候选识别”是允许的实现路径，不意味着每个例子必须调用模型；若以后用完整且正确的规则解析，应相应更新路径测试，但语义和副作用断言保持不变。

## 3 状态与副作用样例

| ID | 条件 | 期望 |
| --- | --- | --- |
| S01 | ensure_index，首次无索引 | 选择 build；允许执行后才准备服务 |
| S02 | ensure_index，已有兼容索引 | 选择 refresh；说明增量检查 |
| S03 | refresh，无可用活动索引 | 询问是否首次建立，不自行扩大操作 |
| S04 | 明确 rebuild，同 profile | 仍使用候选 build，失败保留活动索引 |
| S05 | refresh，源文件和相关指纹均未变化 | 实际报告无新增向量化，不凭 ready 跳过扫描 |
| S06 | 新增或修改部分文档 | 变化文档处理，按实际缓存复用向量 |
| S07 | 切换语义不兼容的 profile | build，不混用旧向量 |
| S08 | 分块参数变化 | 指纹失效，重新评估分块；缓存复用有依据 |
| S09 | 用户限制 local，但默认 profile 为 API | 不能无视限制发往 API |
| S10 | API profile 未在可信配置授权 | 在发送第一批文档正文前拒绝 |
| S11 | 目录暂不可读 | 报真实原因，不能把不可读直接当成全量删除 |
| S12 | 已有冲突写任务 | 返回忙碌或已有任务状态，不重复创建 |
| S13 | 预检查后配置或活动代改变 | 最终校验发现变化，不执行过期计划 |
| S14 | 重复提交同一 requestId | 任务幂等，不重复构建 |
| S15 | status，embedding 服务停止 | 读取任务/索引状态，不启动服务 |
| S16 | 普通问答，无索引 | 按原问答路径显示问题，不隐式建立索引 |
| S17 | 候选识别超时、格式错误、模型不可用 | 不执行写任务，给出错误与命令指引 |
| S18 | 无对话模型，完整明确规则请求 | 按 1102 新设计可确定性处理；复杂候选提示使用命令 |
| S19 | 候选请求 A 未返回，用户已取消或换成 B | A 的迟到结果失效，不能提交 |
| S20 | 原生工具传入与有效请求不同的 profile/operation/job | 拒绝调用，不能扩张许可 |

## 4 测试层次与现有测试衔接

1. **纯函数测试**：表驱动覆盖规则、参数解析、状态计划及澄清状态转换；不需要真实模型或索引。
2. **模型适配契约测试**：mock 返回 ordinary/operation/clarify、非法输出、超时及取消；断言调用次数和无工具能力。不得把这层通过写成模型识别准确率。
3. **入口集成测试**：沿用 `test/agent/index-controls.test.ts`、现有 Pi 输入/交互测试及 `test/embedding/profiles.test.ts` 的测试设施，证明路由在预取之前、普通输入只被提交一次、工具不能绕过许可。
4. **真实对话模型评测**：使用合成用户输入，测试当前实际配置的模型，不用另一个更强模型替代并报告为产品效果。
5. **索引端到端**：隔离 home/config/workspace，少量合成文档及本地 embedding，验证实际 start、进度、取消、增量和候选激活。沿用 1030 失败保护，不要求 refresh 具备未设计的全库回滚。

实现代码后按 AGENTS.md 执行 `bun run check`、`bun run lint`、`bun run typecheck` 和覆盖变更的测试；按影响面补充构建和真实 QA。若新增依赖或变更许可清单，还需对应审批与 supply-chain 检查。本方案本身不要求新增依赖。

## 5 对照设计

建议先构建约 200–300 条人工复核的合成用例，包含明确操作、普通问题、困难负例、多轮上下文和状态组合。该数量是开发起点，不是足以证明线上稳定性的统计结论。

按表达家族划分开发集与独立测试集，不能把同一句的近义改写随机分到两边。规则和提示词只在开发集调整。保留边界例、失败例，不为了获得高准确率从测试集删除难例。

比较三组：

- A：当前正则与操作集合许可，作为旧基线。
- B：只使用改进的确定性规则；疑似操作进入澄清或命令指引。
- C：完整分级方案，规则加按需模型识别与状态校验。

固定模型、网络条件和 Jev 开关，分别报告冷请求与稳定运行结果。真实模型存在波动时重复同一冻结集，并公布次数与失败分布。无需先引入另一个向量分类器作为强制对照。

## 6 必须报告的指标

| 指标 | 口径 |
| --- | --- |
| 操作识别精确率 | 预测为操作的样本中，真实要求该操作的比例 |
| 操作召回率 | 真实操作请求中被正确识别的比例；单列候选规则漏召回 |
| 非操作误执行率 | 非执行请求中实际触发 start/cancel 等状态改变的比例 |
| 参数正确率 | profile、范围、job 的最终解析正确比例 |
| 澄清质量 | 必要澄清命中率、多余澄清比例、澄清轮数 |
| 状态计划正确率 | 给定状态下 build/refresh/status/cancel/阻止执行选择正确比例 |
| 新增模型调用率 | 新识别器实际模型请求数除以总输入数；普通输入单独报告 |
| 延迟与 token | 新识别阶段及端到端 P50/P95、token；普通与候选分开 |
| 索引处理成本 | 实际 embedded/reused/unchanged 与任务耗时，不能用模型估算代替 |

同时报告样本数和混淆矩阵。对边界样本允许澄清，但不能用“所有请求都澄清”获得零误执行而掩盖不可用性。

零误执行仅代表固定样本上的观测结果，不代表任意输入零风险。例如 N 个独立负例零误执行时，常用近似的 95% 上界约为 3/N；合成样本的代表性仍需另行判断。

## 7 交付门禁

以下是拟定验收要求，不是已达到的数据：

- 核心负例与限制冲突用例中，实际误写入次数必须为零；每次修复后保留对应回归样例。
- 已支持的完整明确句式及 `/index` 命令不调用新增识别模型。
- 普通快速路径不调用新增识别模型，不触发索引服务准备；候选误召回造成的额外调用如实统计。
- 一条候选输入至多一次应用层识别；失败不自动多轮修复，不产生写任务。
- 在 Jev 关闭或无凭据情况下，新索引识别仍按设计运行。
- scope/profile/job 校验、任务幂等、取消和迟到回调保护通过集成测试。
- 新方案对独立测试集的操作召回与错误执行优于或不劣于基线；同时报告成本变化。具体模型的数值目标在基线测量后冻结，不能事后移动标准。
- 未完成真实模型或索引端到端验证时，只能标记相应层通过，不能标记整项功能完成。

## 8 开发完成后的记录与简历表述

后续新增实现验收记录时，至少填写：代码版本、模型与配置引用、数据集版本及划分、基线和新方案各指标、失败/跳过项、成本变化、已知限制、隔离 QA 清理结果。不要写入密钥、私人资料或完整认证文件。

可在真实完成后使用以下表述，再填入实测数字：

> 为本地 RAG 系统实现规则与 LLM 协同的分级意图路由，通过多轮参数澄清和索引状态校验区分问答与维护请求，支持增量更新与候选重建；建立独立评测集，验证误触发率、操作召回率和模型调用开销。

文档设计阶段不能把“实现”“准确率提升”“调用成本下降”作为已有成果。简历中的亮点应来自可复现的工程效果，而不是使用了多少框架或模型。
