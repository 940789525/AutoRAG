# 自然语言索引操作开发方案

本方案指导下一阶段开发：让 AutoRAG 区分普通问答与建立、重建、更新、查看、取消索引的请求，同时控制普通 RAG 问答的新增耗时。采用**本地规则分流、疑似操作按需调用已有对话模型、程序校验后复用现有索引任务**的实现方式，不以 Jev 或新增分类模型为前置条件。

状态：分级识别、澄清、状态规划与 TUI 接入代码已实现，针对性自动测试通过；真实托管模型准确率、完整端到端实测和成本基准仍待验收。见 [05 实现与验证记录](05-实现与验证记录.md)。01–04 保留需求和评测约束，不能将自动测试通过等同于所有指标完成。

## 核心流程

```text
用户输入
  ├─ /index 命令 → 现有解析器 → 参数和状态校验 → 内部任务
  ├─ 完整匹配的明确自然语言操作 → 确定性解析 → 同一校验与任务
  ├─ 普通问答 → 保持原问答流程
  └─ 疑似操作或待澄清回复 → 已有对话模型，一次结构化识别
        ├─ 普通问答 → 原问答流程
        ├─ 不明确 → 只补问缺失信息
        └─ 明确操作 → 参数和状态校验 → 同一内部任务
```

候选筛选不授予写权限。模型判断也不能跳过配置、作用域、远程授权和并发校验。

## 开发决策摘要

1. 不给每次普通提问新增一次统一的模型调用；只有疑似操作或必要的澄清回复需要新增语义识别。
2. 明确自然语言只能在完整句式、操作对象和限制条件均确定时走规则快速路径；关键词出现不等于操作授权。
3. 对话模型在一次请求内完成意图和参数提取，不再安排一次独立“复核模型”调用。
4. 使用当前配置的对话模型和认证，不借用 embedding 模型，也不自动切换提供方。
5. 程序根据真实状态选择 build、refresh、status、cancel；分块和向量复用继续由现有管线判断。
6. 明确要求重建时保留重建语义；普通“建一下索引”可按状态选择首次建立或兼容的增量更新，并说明选择。
7. 首版只支持现有全部已配置本地根目录。不得把用户指定的局部范围悄悄扩大为全部，也不得将原生数据源导入本地中央索引。
8. 需要澄清时才提问；请求明确且条件满足时直接执行。
9. 不承诺任意自然语言零漏识别，也不宣称已有准确率或性能提升；用分层评测证明实际效果。

## 与现有文档的关系

1030 的任务边界、候选构建保护、远程授权、原文不被索引修改等要求继续有效。1102 细化自然语言入口，并拟作一项明确调整：**可完整确定性解析的自然语言命令无需调用对话模型；复杂自然语言仍需已有对话模型，无模型时引导使用 `/index`。** 这项调整不是当前系统已具备的行为，实现时应同步更新 1030 对“所有自然语言都需要模型”的表述。

当前 CLI/TUI 默认启用 Jev，与“1102 不依赖 Jev”是两件事。本阶段不自动修改已有 Jev 配置、不删除其问答路由；新的索引识别在 Jev 关闭或不可用时也必须可工作。性能报告应区分原有 Jev 耗时和本次新增开销。
