# 需求与设计边界

## 1 当前实现与缺口

`src/agent/index-controls.ts` 中的 `indexWriteOperations()` 与 `isIndexOperationInput()` 主要按正则判断自然语言。`agent.ts` 的 `routeInteractiveInput()` 在没有搜索运行时，使用它们决定是否进入 Pi 原生工具路径，并将操作集合保存为 `nativeIndexIntent`。`manage_local_index` 再检查该集合是否允许写操作。

这意味着候选路由和写操作许可目前共享了一组粗粒度匹配结果。

| 输入 | 当前入口函数结果 | 目标行为 |
| --- | --- | --- |
| 用本地 Qwen 模型给已配置的文档目录建索引 | 不命中索引写操作 | 识别为建立请求 |
| 用本地 Qwen 模型给已配置的文档目录建立索引 | 命中 build | 识别为建立请求 |
| 不要建立索引，只解释步骤 | 命中 build | 只解释，不允许写入 |
| 请告诉我如何建立索引 | 命中 build | 操作咨询 |
| 查找包含建立索引说明的文档 | 命中 build | 普通检索 |
| create a summary of this document | 命中 build | 普通总结请求 |

“命中 build”表示入口授予了对应类型的许可，不表示真实对话模型一定执行了建库。后续评测需要分别检查路由结果和实际任务调用。

已有可复用能力：

- `/index build/refresh/status/cancel`、受限原生工具和内部任务模块。
- profile 配置、远程发送授权、全部本地根目录范围检查。
- 任务 ID、进度、取消、写锁、幂等请求与任务终态。
- 文档变化检测、分块指纹、向量缓存、独立候选 generation、成功后激活。

缺少的是可靠的自然语言分流、参数澄清、与状态相结合的操作选择，以及针对真实模型的识别评测。

## 2 要达到的产品行为

### 区分执行与谈论

“建立索引是什么意思”“找介绍重建的文档”“不要重建”不能因为出现动作词而启动任务。“请重建当前索引”属于明确请求，不应反复要求确认。

### 区分目标与具体操作

内部识别目标建议分为：

| 目标 | 含义 | 状态解析后的操作 |
| --- | --- | --- |
| ensure_index | 让已配置资料具备索引或保持可检索 | 无兼容索引时 build；有兼容索引时 refresh |
| rebuild | 明确要求重新构建索引 | build，独立候选代 |
| refresh | 更新已有索引 | refresh；没有可用索引时说明并询问是否首次建立 |
| status | 查看状态或进度 | status，只读 |
| cancel_job | 取消具体索引任务 | cancel，限定任务身份与所有权 |
| abandon_request | 放弃尚未提交的澄清请求 | 清除待处理请求，不取消无关任务 |

明确 `/index build` 保留现有命令语义，不经 ensure_index 自动降为 refresh。用户“换一个 embedding 模型”的要求不能被解释成兼容增量更新。

### 只澄清影响执行的信息

- “用本地那个”：当前候选中只有一个符合约束的 profile 时可解析；有多个时询问具体选择。
- “索引这批文件”：无法确定范围时询问；指定未配置或局部目录时不能直接扩大为全部。
- “取消刚才的任务”：结合当前会话持有的任务 ID；不能随意选择其他进程或其他会话的最近任务。
- “新资料怎么搜不到”：先诊断；不能推断用户已经允许重建。

## 3 轻量化边界

首版不新增运行时依赖、模型服务、训练分类器、向量路由索引、通用规划框架、Redis、消息队列或多 Agent。

只使用本地字符串规则、现有 schema 校验能力、已有对话模型调用设施和索引任务。对话模型负责理解语言；程序负责校验参数、选择流程和检查实际状态。

新增识别不依赖 Jev。2026 年 11 月 2 日只读核查的日常环境中，Jev 配置为 OpenRouter，但缺相应环境密钥；日常容器停止。该事实只是当日基线，不应写成运行时代码的永久假设，也不应通过本任务修改用户的认证配置。

## 4 首版支持与延期

| 首版必须支持 | 后续独立扩展 |
| --- | --- |
| 明确句式快速路径，疑似操作按需模型识别 | 训练或部署独立小分类器 |
| 建立、重建、更新、状态、取消 | 任意目录子集索引 |
| 一项待澄清请求及参数修正 | 多个待执行计划和长期任务记忆 |
| profile 与作用域校验，复用现有任务 | 新增 MCP 索引接口 |
| 搜索与索引控制输入正确分流 | 任意多步 Agent 规划 |
| 识别“先更新再回答”属于组合请求，并要求拆开执行 | 自动等待维护完成并恢复任意问答链 |

组合请求首版不能只执行前半句、悄悄丢弃后半句，也不能因为含有操作词就自动执行。应说明首版需要分两步，并询问是否先处理明确范围的索引操作。

## 5 与普通问答的关系

判定为普通问答后，输入进入原有 `startInteractiveQuery()` 或原有 steering/follow-up 路径，保留用户原文和附件。不得因为新识别器接入而重复调用 `planQuery()`、改变问题、自动建索引或下载模型。

本地候选规则仍可能漏掉很间接的操作表达。优化方向是根据评测补齐高频候选表达，而不是将所有用户输入都交给额外模型。漏识别时至少保持“不擅自写入”的边界。
