# 实施与验收

依照[行为规格](./README.md)，分两步完成。测试结果见文末。

## 第一步：共用单文件操作

- 从 [CLI 删除命令](../../src/cli/commands/index.ts) 提取由 CLI、TUI 共用的内部操作。CLI 自己处理参数、交互确认和输出；TUI 通过受信任的运行环境传入当前配置、工作区和目标来源，模型不能指定配置文件或任意要删除的磁盘路径。
- 删除沿用“持久化排除 → 清理镜像 → 增量同步”。配置更新应在锁内读取最新值，只合并目标路径，保留并发写入的其他设置。镜像清理和刷新与其他索引写任务共用写锁，避免嵌套申请同一把锁。长驻 TUI 及后续刷新任务须看到新的排除状态；现有 Agent 在构造时读取该值，不能仅修改磁盘后继续复用旧快照。
- 恢复使用对应删除记录，不从普通文件清单猜测哪条排除是本功能创建的。将目标身份、是否新增排除和执行阶段记在现有工作区的索引任务记录中，使中断或重启后可按实际状态恢复。仅在已获准恢复、原件仍在允许范围且无其他排除时，解除目标排除，再用当前解析配置从原件重建镜像并执行增量同步。不得复用删除前的空 Markdown。

## 第二步：接入现有自然语言入口

- 扩展 [manage_local_index](../../src/agent/index-controls.ts)，仅 `remove` 与 `restore` 接受单个 `sourceId`；保留原有操作的参数和全库范围约束。扩展[任务控制器](../../src/indexing/jobs.ts)的记录和去重判断，使相同请求 ID 不能换操作或换目标。复用[本地会话授权](../../src/agent/agent.ts)及原有 Skill 检查。模型不通过 bash 调用 CLI 删除。
- 更新 [autorag-index](../../skills/autorag-index/SKILL.md) 的操作说明。让模型利用可信文件清单和上一轮回执确定目标，工具在实际写入前再次校验。回执至少给出操作、目标来源、任务 ID、状态及该文件实测结果。恢复的目标由回执提供；“帮我建立索引”仍走现有 `ensure`。

## 最小验收

使用隔离的合成资料库、已有活动索引、待删除文件 A 与对照文件 B。先记录两个原件的指纹、登记和块数。实际 TUI 工作流只需一组两轮对话；歧义和失败用聚焦测试覆盖，无需评分模型。

| 用例 | 操作 | 通过条件 |
| --- | --- | --- |
| 1. 按名字删除，下一轮恢复 | 本地 TUI 输入“去掉 A 的索引，原文件保留”；任务成功后执行一次普通刷新，再输入“把刚才那份重新建回来”。 | 删除后 A 无登记、无块，刷新后仍未收录；恢复后目标仍是 A，索引中查到 A 的实际内容。两份原件指纹不变，未变更的 B 仍可检索。回执与真实终态相符。 |
| 2. 意图与目标 | 两个目录放同名文件，只说文件名；另测“能删吗”“不要删”以及现有“帮我建立索引”。 | 同名时提供候选，选定后只操作对应来源；询问和否定零写入；原有建索引操作继续正常。 |
| 3. 部分失败与恢复 | 在排除项写入后令同步失败，再重试；覆盖原有父目录排除及零块文件。 | 回执报告真实失败和已生效阶段；重试不扩大范围，不撤销已有排除；零块文件的回执与实际登记、块数一致。 |

保留精简证据：两轮用户原话与最终答复、任务 ID 及终态、目标与对照文件的前后登记和块数。验证成绩单检索时使用合成课程表和新会话，检查目标来源的实际命中，避免旧会话图片被当作新索引的证据。若未实测真实扫描件 OCR，单独注明这项边界。实施阶段执行仓库规定的检查、相关测试，并核对既有 CLI 删除和 TUI 建索引回归。

## 2026-11-06 实施结果

在开发容器中启动真实 Pi TUI，通过 PTY 输入自然语言，使用隔离的配置、Pi 会话、合成 Markdown 和本地 embedding。第一轮删除目标文件的两条块，第二轮用原会话的“把刚才那份重新建回来”恢复同一个来源。两轮间另行执行普通刷新，目标继续排除。实读活动索引确认对照文件仍有原文，两个源文件的前后指纹一致。独立同名样本和否定问法均未提交任务。[用户原话、最终回答、任务及索引证据](./真实TUI验收.json)

首轮开发实测发现模型在读 Skill 的同时还调用了文件发现工具，触发了已有的外部内容保护。已将“索引维护只从索引清单定位目标”明确写入提示及 Skill，保留保护机制。最终两轮实测均只使用 Skill 和索引工具。check、lint、typecheck、构建及 179 项相关回归通过。此次会话使用文本夹具，真实扫描 PDF 的中文 OCR 效果不在本次验收范围。
