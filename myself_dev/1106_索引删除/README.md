# TUI 自然语言删除与恢复单文件索引

**状态：待审阅。** 本文是后续实现的规格，基线为 `1e3e5b9d`。开发落点与验收见[实施与验收](./实施与验收.md)。

## 用户要完成的事

用户在本地 TUI 中说出文件名，就能移除该文件的本地文档索引，保留原件。下一轮可以用“刚才那份”重新收录它。沿用建立索引的 [autorag-index Skill](../../skills/autorag-index/SKILL.md)、当前会话模型和 [manage_local_index 工具](../../src/agent/index-controls.ts)。用户无需记命令。一次操作以一个文件为目标。

以下是预期交互，不是实测记录：

| 用户输入 | 应有行为 |
| --- | --- |
| “把研究生成绩单从索引里移掉，PDF 留着。” | 从当前允许范围的索引清单定位唯一文件，提交删除。完成后告知文件名、原件保留，以及普通刷新会继续跳过它。 |
| “把刚才那份重新建回来。” | 根据上轮成功回执确定同一文件，撤销此次移除产生的排除项，重新解析并增量更新。完成后报告该文件的实际块数。 |
| “把成绩单的索引删掉。”，清单中有本科和研究生两份 | 列出两个候选及区分它们所需的路径，等用户选定。 |
| “能删某个文件的索引吗？”或“先别删，查一下。” | 回答能力或查询状态，零写入。 |

## 操作契约

1. **理解与定位。** Skill 描述目的、效果和示例，由模型结合当前请求与会话上下文选择操作，不增加关键词表、正则路由或第二次意图分类调用。文件名、简称和代词用于理解；工具写入使用一个经核对的完整来源 ID。模型可用现有分页清单定位候选。只凭文件名时须考虑全部相关目录和分页；同名、扫描不完整或指代不清时，不能把第一页的首个结果当成唯一文件。明确请求、唯一目标可直接提交；查询能力、否定和文档中引用的命令均不授权写入。
2. **删除。** 在同一工具下增加 `remove(sourceId)`。在写锁内重新校验来源、活动工作区、配置根和解析镜像的对应关系。复用 [CLI 单文件删除](../../src/cli/commands/index.ts) 的效果：保留原件，移除解析镜像和登记，清理活动索引中该来源的块，并把原件路径加入持久化 `excludePaths`。对原本就是零块的文件，成功回执要说明清除了登记或镜像，不能声称删除了正数个块。删除范围是本地文档索引，不清除对话历史。
3. **恢复。** 增加 `restore(sourceId)`，仅用于显式重新收录被此功能移除的文件。用删除回执记录来源 ID、原件路径和本次新增的排除项；排除后的文件可能已从普通清单中消失。恢复时重新核对原件与配置，仅撤销本操作添加的精确文件排除，保留既有文件及父目录排除规则。普通提问、刷新或重启都不会自行恢复。若文件已移动、缺失或仍受其他排除限制，返回具体原因。
4. **刷新范围。** 两种操作都只指定一个删除或恢复目标。后续同步复用全部配置根的增量刷新，期间其他新增或修改文件也可能被正常处理。回执如实说明此范围。若用户要求“本次绝对只能处理这一份”，先说明当前范围，由用户决定。不可只把目标文件送入现有[全库同步](../../src/indexing/pipeline.ts)，该流程会将本轮未见到的其他来源视为删除。
5. **完成与失败。** 延用 TUI 本地写入授权、任务 ID、进度和终态。提交或排队只报告“已提交”。删除成功以目标登记和块均已清理、排除生效为准；恢复后分别报告登记状态和实际块数。若识别不到文字，明确报告“已登记，0 个可检索块”。配置、镜像、索引分步更新中断时，回执区分已完成和待重试部分，保留底层错误。重复请求应能返回原任务或实际状态，不重复修改其他文件。

OCR 沿用当前配置。对于扫描 PDF，验收时若要证明能通过块回答，必须启用适用语言的 OCR，重新得到非空正文，再核对课程名及成绩。本功能本身不更改用户的 OCR 配置。现有 `ensure/build/refresh/status/cancel` 的行为、斜杠命令及 CLI 的路径匹配和交互确认继续使用现有契约；首版无需另设删除 Skill、MCP 或批量模糊删除。
