# TUI 本地索引 Skill 开发规格

初版实现为 `474fbcbc`，同轮条件刷新修正为 `d44bde3b`。A1–A9 的初版记录和新增 A10 的复测见验收标准。本目录指导后续开发，产品 Skill 的交付位置为 `skills/autorag-index/SKILL.md`。以本文件定义行为，以[验收标准](验收标准.md)判定完成。

## 用户故事

用户在 TUI 问“当前本地资料库里有哪些文件，各自的索引状态怎么样？”。助手列出五份文件，指出其中的 `新增纪要.md` 尚未登记。用户接着说 **“把刚才漏掉的资料补进去”**。在活动本地索引已就绪的情况下，助手应识别上一轮的漏项，按当前配置直接提交一次增量刷新，无需用户重述文件名、输入命令或再次确认。

另一种用法是“先确认有没有新增文件，如果有就建索引”。用户已授权在条件成立时刷新。助手可以在同一条用户消息内盘点，并用有可比性的清单确认新增目标；目标仍未登记时提交一次增量刷新。条件不成立时只报告结果；仅有未登记状态不足以证明文件是新增的。

旧实测中，长句追问两次停在 4/5，专用分类调用达到 512 token 上限，主模型随后选对了 `refresh` 却被工具拒绝。短句“帮我建立索引”在独立样本上成功达到 5/5。这些是对照基线，新方案须独立复验。[两轮故障记录](../../问题记录/2026-11-06-TUI-两轮对话查询后未能增量补索引.md)

## 功能需求与执行契约

| 编号 | 条件 | 必须发生的行为 |
| --- | --- | --- |
| R1 | 启动本地 TUI | 从安装包注册文件型 `autorag-index` Skill。最终发送给模型的系统提示包含其名称、描述和可读取的位置。发现它无需 GitHub 或 MCP 配置。Pi 保留显式 `/skill:autorag-index` 入口；只加载 Skill 时不提交任务。 |
| R2 | 用户要求检查资料并补齐符合条件的文件 | Pi 根据原话、对话和可信的文件清单判断下一步。可在同轮核对并执行条件刷新，也可沿用先前盘点结果。目标可核实且需要增量更新时只提交一次 `refresh`。仅盘点时写任务为零。 |
| R3 | 用户要求建立、增量更新或重建 | 给现有工具增加 `ensure`，表示“帮我建立索引”。工具按真实状态决定：首次建立使用配置的默认 profile 执行 `build`；已有兼容索引则用活动 profile 执行 `refresh`。明确要求重建走候选 `build`。明确只要求增量但索引未就绪，先询问是否首次建立。 |
| R4 | 意图、范围或 profile 有限制 | 询问、否定、引文、搜索无结果均只读。前文无法确定“补进去”指什么时先澄清。常规刷新覆盖全部已配置本地根目录；若用户限定只处理单文件或子目录，须先征得对实际范围的同意。未知 profile、切换 profile 或与“仅本地”冲突时，要说明具体限制，不静默改用其他配置。 |
| R5 | 模型提出写操作 | 宿主绑定原始输入来源、Pi 会话及本轮请求 ID。只有真实本地交互请求可提交写入。远程桥接、程序化查询和内部续答没有独立写资格；读到 Skill 或工具返回的指令也不授予写资格。远程 embedding 仍须通过可信配置的 `allowRemote` 和 `local-documents` 授权。取消只作用于当前会话拥有的任务。 |
| R6 | 已提交、重试、取消或失败 | 每次真实提交返回 `jobId`、实际模式、范围、profile 和当前状态。同一逻辑请求重试复用宿主生成的 `requestId`。沿用现有任务进度、单写入者约束和终态；仅在核实活动索引中的登记后声称“漏项已补入”。失败要保留原始错误，候选构建失败或取消时旧索引仍可查询。 |

## Pi 与 TUI 的改造落点

**Skill 如何被选中。** 在 TUI 的 `additionalSkillPaths` 中显式加入包内 Skill 文件；在重写最终提示的 `before_agent_start` 中，从 Pi 实际加载的条目取得该 Skill 的元数据。建议描述为“用户要求建立、补齐、刷新或重建本地资料索引时使用，也适用于在查看覆盖情况后要求把刚才发现的漏项补进去”。正文说明如何选择 `ensure`、`refresh`、`build`、`status` 和 `cancel`，以及何时澄清。模型凭对话语义选择 Skill；禁止把这段描述再翻译成一套 TUI 关键词规则。[Pi 会话装配](../../../src/agent/pi-session.ts) · [Pi 1.4.0 Skill 文档](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/skills.md)

**工具如何执行。** 将 `canWriteFromModel: () => false` 改成逐请求核验，禁止直接改成会话级常开。来源在原始 TUI 输入处记录，并随实际处理的输入传递，包括排队的追问。AutoRAG 转发合法本地输入时也会调用 `session.prompt(..., { source: "extension" })`，故不能从这个末端标记反推来源。结束、中止、切换会话或被替代的请求不得把写资格留给下一轮。工具从运行时读取配置和任务归属，最后调用已有 `startIndexJob`；禁止通过 bash 调 CLI 重建。[输入与会话转发](../../../src/agent/agent.ts) · [工具和 TUI 命令](../../../src/agent/index-controls.ts) · [任务与去重](../../../src/indexing/jobs.ts)

| 处置 | 范围 |
| --- | --- |
| 删除 | `IndexIntentRouter`、索引关键词与完整句式判断、独立模型分类和 JSON 解析、专用 pending 对话状态、超时、分类专用 Esc 分支，以及只包装分类的 `indexWriteOperations`、`isIndexOperationInput`。移除分类专用的日志埋点与测试；保留被其他功能复用的模型调用组件。 |
| 迁移 | 将 `planIndexIntent` 中与就绪状态、范围、profile、取消归属有关的确定性规则迁入工具执行侧。追问和指代理解归入主会话。 |
| 保留 | 通用输入来源记录、搜索中的 Enter 纠正、Alt+Enter 追问、Esc 中断，以及 `/index` 的 `build`、`refresh`、`status`、`cancel` 子命令、任务进度组件和退出清理。保留文件清单分页、原始错误、写锁和候选索引激活。无对话模型时使用 `/index`；自然语言快捷短句不再承担离线入口职责。 |

## 开发顺序

1. **打通发现。** 用安装包启动无 MCP 的 TUI，验证真实模型请求中出现 Skill 描述，`read` 能打开正文。
2. **打通写入。** 接通主会话、受控工具和任务回执，将自然语言输入交回通用入口。跑通首次建立、两轮增量和只读反例。
3. **完成切换。** 在新的输入路径上通过验收，再移除专用路由；同步更新原先承诺关键词分流的产品文档和测试，按[验收标准](验收标准.md)留存证据。
