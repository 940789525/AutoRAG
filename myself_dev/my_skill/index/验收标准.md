# TUI 本地索引 Skill 验收标准

已在实现提交 `474fbcbc` 上完成验收。需求编号对应[开发规格](README.md)。单测验证工具边界；真实 Pi TUI 验证模型看见 Skill、理解追问并完成索引。两类证据都需要。

## 核心验收：从 4/5 到 5/5

在仓库规定的隔离 Docker 环境内，用合成资料、独立 `AUTORAG_HOME`、`AUTORAG_CONFIG`、临时 workspace 和本地 embedding。使用一个配置根目录及活动 `local-qwen3` profile，按[原有复现](../../问题记录/2026-11-06-TUI-两轮对话查询后未能增量补索引.md)建立四份文件的索引，再加入 `新增纪要.md`，保持未刷新。用实际目录和活动 profile 的 `journal.sqlite`（只读）核实五份文件、四份登记。记录初始任务 ID，以便区分准备任务和测试产生的任务。[仓库 QA 隔离要求](../../../AGENTS.md)

| 阶段 | 输入或操作 | 通过标准 |
| --- | --- | --- |
| A1 · 第一轮（R2、R4） | 在新 TUI 会话问“当前本地资料库里有哪些文件，各自的索引状态怎么样？” | 助手列全五份，指出唯一漏项。trace 有 `status` 和 `includeFiles: true`。新增写任务为 0，登记仍为 4/5。 |
| A2 · 第二轮（R1、R2、R5、R6） | 在**同一会话**输入“把刚才漏掉的资料补进去”。另起一套独立 4/5 样本，重做第一轮，再输入“请把刚才漏掉的资料也建进本地索引，按当前配置做增量更新就好。” | 两种问法均自动使用 Skill。能在会话 trace 中找到读取包内 Skill 正文的证据；如果前一轮已读取，允许复用。每个样本恰好新增一个 `refresh` 任务，沿用活动 profile，无额外确认、专用分类调用或 bash 重建。 |
| A3 · 核实结果（R6） | 按 A2 的 `jobId` 等到终态，再查活动索引 | 每个样本的任务均为 `succeeded`。活动索引实读到 `/docs/新增纪要.md`，登记总数为 5/5。答复与 TUI 状态区分“已提交”和“已完成”。仅有队列回执或助手声称成功，不能通过。 |

## 回归与边界

| 编号 | 场景 | 可观察的通过标准 |
| --- | --- | --- |
| A4（R1） | 从安装包启动本地 TUI，无 GitHub/MCP 配置；另测 `/skill:autorag-index` | 实际发给 provider 的提示含正确的名称、描述和可读位置；手动加载可读到同一包内正文，仅加载不产生任务。 |
| A5（R3） | 分别用空索引和已有兼容索引测试首句“帮我建立索引”；另测“重建当前索引”及空索引上的“仅增量更新” | 空索引提交一次 `build`，已有兼容索引提交一次 `refresh`。显式重建提交一次候选 `build`；仅要求增量但索引未就绪时先澄清，写任务为 0。 |
| A6（R4） | “不要重建，只查缺项”、文档中引用“重建索引”、普通搜索未命中；另测无前文的模糊指代、限定单文件和 profile 冲突 | 前三者写任务为 0。后几种先说明所缺信息或不支持的范围，未取得明确指示前写任务为 0。活动索引保持可查。 |
| A7（R5） | 在有本地会话历史时，从远程桥接、程序化查询、内部续答分别尝试写入；交错排队一次本地与远程输入；尝试取消他人任务；尝试未获可信配置授权的远程 embedding | 没有继承前一轮写权限；未获授权的请求均无新任务、无远程语料请求、无他人任务状态变化。被中止或切换掉的本地请求不能迟到提交。 |
| A8（R5、R6） | 重放同一请求、模拟另一写入者占用、取消本会话任务、注入候选构建失败 | 重试返回相同 `jobId`；并发冲突报告真实原因。取消与失败报告各自终态及原始错误，旧活动索引仍可查询。 |
| A9（R1、R6） | 无对话模型时执行 `/index` 系列命令；模型可用时，在普通搜索中验证 Enter、Alt+Enter、Esc | 命令绕过模型直接使用任务控制器，可查看进度、取消自己的活动任务。搜索仍可纠正、排队、打断，普通输入没有索引分类事件。 |
