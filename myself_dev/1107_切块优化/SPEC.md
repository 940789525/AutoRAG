# 表格解析与检索实现规格

版本 `table-retrieval-v0.1`。T2 的配置和索引已接入，父表遍历和原页核读仍为 T3 的目标契约。

## 1 目标与当前缺口

目标是让中文、英文表格中的字段、分组和记录关系在解析、切块、召回、引用中持续保留，覆盖原生表格和图片型表格。核心回归为：第一轮询问全部体育课程时，能找全并正确关联学期、成绩，或准确说明未确认的区域。

当前实现与需要修改的边界：

| 位置 | 当前行为 | 实施要求 |
| --- | --- | --- |
| `src/parser/defaults.ts`、`kordoc.ts`、`ocr-engines.ts` | 中文默认注入返回字符串的 OCR；上游结构结果未保留 | 接入 Docling 结构化输出与 RapidOCR；保留语言、OCR 开关和兼容路由 |
| `src/parser/types.ts`、`isolated.ts`、`parse-worker.ts` | 主要传递 Markdown，解析有超时与 worker 隔离 | 扩展可序列化结构契约；取消、超时能够清理所启动的 Python 子进程 |
| `src/mirror/sync.ts`、`index-store.ts` | 保存 Markdown 与源／输出哈希，复用主要看文件和解析器版本 | 保存版本绑定的结构伴随文件，增加解析配置指纹和一致发布 |
| `src/indexing/chunker.ts` | 已有标题、管道表格按行切分、重复表头，默认 512／768 tokens | 增加结构表格的记录边界、多级表头与宽表策略，保留普通段落路径 |
| `src/indexing/pipeline.ts`、`lance-store.ts` | BM25 分析 heading＋text，向量使用 embeddingText；来源过滤已有 sourceIds／scope | 两种检索均使用完整表格上下文；增加父表精确遍历与定位，复用存储 |
| `src/indexing/evidence-reader.ts`、`src/agent/read-local-evidence-tool.ts` | 完整块读取严格验证原件、镜像和块正文 | 保留原契约，新增表格／页面读取不得绕过这些版本和授权边界 |

源文件名为仓库相对路径；设计落点不是只改这几处即可完成的保证，应核对其配置、导出、调用方和测试。

## 2 需求与首版边界

| ID | 必须满足的行为 |
| --- | --- |
| R01 | 新后端支持 PDF、DOCX、XLSX；开启 OCR 时支持 PNG、JPEG、WebP 和扫描页。中文、英文及混排各有测试。`ocr.enabled=false` 时不自动识别扫描页／独立图片。 |
| R02 | 保存表格、行列和合并关系；保留可取得的页码、区域和识别质量信息。布局、语义或坐标未知时显式缺省，不编造。 |
| R03 | 按完整逻辑记录组成行组，每组携带文档／表格标题、表头路径、单位和明确的分组标签。超宽、超长记录按第 4 节处理。 |
| R04 | 确定性生成的上下文同时用于 BM25 和向量输入；原始证据与检索描述分开，禁止 LLM 猜测／改写成绩。 |
| R05 | 由已检索证据定位父表，可分页回读全部已索引行组；指定文件时收窄来源范围。topK 不代表完整性，遍历不完整时不能宣称找全。 |
| R06 | 解析存疑时，能从已验证证据定位并渲染源 PDF 页／图片区域。第一次请求即可使用已有核读能力，不要求重复上传可访问原件。 |
| R07 | 原件、镜像、结构、索引代次和权限一致时才能回读；重建、删除、scope 变更和源文件变化使旧定位失效。保留 `read_local_evidence` 的完整块与哈希保证。 |
| R08 | 配置／模型／解析适配／序列化变化使相应缓存失效；失败或取消不发布半套文件。保留可回滚的旧索引，不把旧源版本伪装为最新。 |
| R09 | CPU 低并发运行；预置模型后离线工作；错误保留真实 stderr、退出状态及路径，质量警告和任务成功分别表达。 |
| R10 | 常用格式迁移可显式启用和回滚；HWP、旧 XLS、PPTX、EML、纯文本及已有 datasource 不发生未经约定的覆盖退化。 |

首版不引入新向量数据库、视觉多向量索引、SQL 问答系统、远端 OCR 或图像描述大模型；不做图表数值理解、手写成绩保证、整库自动迁移和通用无损文档编辑。

## 3 主解析路径与运行方式

`源文件 → Docling／兼容解析器 → 规范化 Markdown＋结构 JSON → 结构切块 → BM25＋Qwen → 行组证据 → 父表／原页回读`

### 3.1 路由与选型

- PDF、DOCX、XLSX 由新后端接管；图片仅在 OCR 开启时注册。按明确的配置选择后端，不能让两个解析器在现有 registry 中重复注册同一扩展名。
- HWP、HWPX、HML、HWPML 和旧 XLS 继续用 kordoc；PPTX、EML、纯文本沿用各自路径。未来移除兼容格式另行定范围。
- 使用 Docling 标准 PDF 解析、RapidOCR 的轻量 ONNX CPU 配置、版面模型和 TableFormer；不启用 VLM pipeline、图片描述、公式／代码增强和全量模型下载。
- T1 对照后冻结 **TableFormer ACCURATE**，与 Heron 版面模型配套；版本、哈希、资源和质量结果见 [RESULTS.md](RESULTS.md)。
- RapidOCR 的 `lang=["ch"]` 配合显式固定的 PP-OCRv6 multilingual small 权重和该模型自带字典，为简中、英文、混排共用一条识别路径。不能把现有 `['zh-hans','en']` 原样传给上游当作两个识别器。

### 3.2 本地进程与资源

- 建索引任务启动一个受控本地 Python 解析进程，任务内复用模型，任务结束、取消或超时后回收其进程树。无需常驻 HTTP 服务，不与 FastEmbed 共用或改装同一个虚拟环境。
- CPU 显式选择，解析并发 1，推理线程上限 4，页面队列和预解码缓冲均为 1；不强制申请 GPU。逐页处理，但不宣称文档总内存与页数无关。
- 保留当前每文件解析期限及配置覆盖；上游模型加载也计入期限。超过资源或时间预算时逐文件报告失败，禁止无限重试或静默转远端。
- 使用任务／工作区自有的模型缓存；记录依赖版本、模型 revision、SHA-256、代码与模型各自许可证。初始化阶段显式准备模型；日常离线任务缺模型时报告具体缺项，不临时联网下载。
- 首轮探针以 Compose 的 4 CPU／8 GB 声明为边界，核实实际 cgroup 和 WSL 上限；同一容器内 FastEmbed、Node、解析器的总峰值都要计入。

配置草案仅增加一个后端选择项 `parserOptions.documentBackend = 'kordoc' | 'docling'`，复用现有 languages、OCR 开关、fileTimeoutMs；解释器和模型目录由部署提供。具体版本、模型清单及进程协议在 T1 的探针记录中冻结，未冻结前不切产品默认。

## 4 结构文件与分块契约

### 4.1 两份派生文件

每个新后端文档产生规范化 `.md` 与版本化结构 `.json`。结构最小包含：

| 层级 | 字段含义 |
| --- | --- |
| 文档 | schemaVersion、sourceSha256、parserFingerprint、Markdown 哈希和结构哈希 |
| 表格 | 文档内 tableId、标题、表头路径、明确的分组标签、表格行列数 |
| 单元格 | 原始识别文本、逻辑行列范围、rowSpan／colSpan；有依据时记录表头角色 |
| 原件定位 | 可取得的页码／工作表、区域、坐标单位与原点、旋转／缩放变换；缺少定位时不伪造 |
| 质量 | 实际 OCR 语言和模型、上游警告、置信度的来源及可用性；置信度不解释成准确率 |
| 映射 | 表／记录到规范化 Markdown 区间及已索引行组的映射，绑定索引代次 |

PDF／图片的区域、DOCX 的块位置和 XLSX 的工作表／单元格引用分别建模；不能一律伪装成 PDF 页码。RapidOCR 的文字框与 TableFormer 单元格之间的对应关系必须验证，不能按数组下标直接拼接。

Markdown 与结构先写候选文件，完成校验后经 manifest／代次指针发布。索引只能读取同一代两份文件；崩溃中间态不得靠“两个路径都存在”判为有效。新增 manifest 字段在旧镜像中允许缺失；旧文档没有结构时继续原行为，不能猜出父表。

### 4.2 表格切块

- 小表在预算内整表保留；大表按完整逻辑行组切分，不横跨两个独立表。现有目标 512、上限 768 tokens 作为初值，使用现有实际 tokenizer 计数，并包含上下文、passagePrefix 及已有 special-token 预留检查。
- 在切块前恢复多栏阅读顺序和记录分组；合并单元格的继承值注明其结构来源。表头含义不明时保留矩阵及位置，不把第一行或相邻学期自动解释为所有行的语义。
- 行组重复必要的多级表头、单位、标题与分组标签。若按这些信息展开检索文本，则 BM25 与 embedding 使用同一份语义内容，不能只修改 embeddingText 而保留旧 lexical 输入。
- 超宽记录按列组拆分，并重复结构行标识；缺少原生主键时使用派生 rowId，不编造业务主键。单个长单元格再按内容边界拆分，各片保留相同行、列与连续片段标识；标明片段不能单独代表完整记录。
- 宽表列组或长单元格产生的派生片段，先确定性序列化到同代 Markdown，再计算连续 offset，并在结构映射中标明其原始单元格。不能拼接非连续列后套用首尾 offset；全表结构仍以 JSON 为准，父表遍历按逻辑行去重而非按片段计数。
- Markdown 区间保持为真实连续子串，`chunk.text === markdown.slice(start, end)` 继续成立；额外上下文进入检索字段和受信任元数据。不得把重写后的句子配上旧 offset。
- 保留普通段落切块；跨页表仅在表头、列布局和上游结构有足够依据时连接，并记录各页来源；不明的跨页关系必须在读取覆盖信息中披露。

检索表达示例使用合成数据：`表：课程记录；学期：第一学期；课程：体育A；成绩：88；学分：1.0`。字段来自已解析单元格，不能用课程常识补写缺失成绩。

## 5 父表回读与原件核读

在现有本地 agent 工具边界新增受限的 `read_local_table`；不创建独立 MCP 服务，不改变 `read_local_evidence` 的参数或完整块含义。拟定输入为已检索 `evidenceId`、可选分页 cursor 和 `view: 'rows' | 'image'`，不接受任意文件路径或由模型声明的可信 tableId。

- rows 视图由 ledger 定位受信任的父表，按稳定顺序分页返回其已索引行组及必要表头。每组登记／复用自己的证据 ID，不能用最初命中的一个块引用整张表；复用原块正文和精确读取校验。
- 返回覆盖行／片段、总数、nextCursor 和 exhausted。服务端设定输出预算；达到预算返回游标，不截断后再标“全部读取”。对“全部／计数／例外”请求应完成目标表遍历或明确未读范围，不能依赖扩大 topK。
- image 视图按结构位置用现有 PDF.js／Canvas 或图片解码能力渲染对应页面／区域，并把图像实际交给支持图像的回答模型。没有可靠裁剪位置时读取已验证的整页；模型不支持图像时明确阻塞。
- 每次读取校验 source、Markdown、structure 哈希、活动索引代次和当前 roots／exclude／scope，游标绑定同一版本。源改变、会话分支改变、删除、重建及权限收紧时拒绝过期读取。
- 优先用现有 scope／sourceIds 收窄已明确的文件，不根据低分或启发式标签全局丢弃其他合法来源。搜索结果排序分数不当作 OCR 正确率。
- 本地解析和结构读取不发送内容到远端；原页图像进入已配置回答模型也属于内容外发，必须沿用现有可信 provider 授权边界。本规格不新增任何上传授权。

## 6 迁移、质量与失败语义

parserFingerprint 包含适配／序列化版本、Docling／RapidOCR／推理引擎版本、模型与字典哈希、语言选择、OCR 开关、表格模式及影响输出的预处理参数；结构策略变更纳入 CHUNKER_VERSION 和相关索引指纹。字段缺失的旧缓存不能直接判为新后端已处理。

新配置先生成候选镜像和索引代次，成功后切换活动指针；失败／取消保留原代次。源已变化时，旧数据只能标为陈旧并拒绝作为当前原件核证。回滚到旧后端必须选择其匹配代次或显式重建，不能把两个后端的结构和正文混用。

质量状态至少能区分文本层读取、OCR 已执行、结构存疑和处理失败。非空文字、OCR 开关、块数、任务 succeeded 均不代表内容识别准确。保留原警告和底层错误；缺模型、超时、损坏、OOM、非法 JSON／坐标分别给出真实诊断，一份失败不拖垮其他文件。

## 7 技术依据

- [Docling 结构文档](https://docling-project.github.io/docling/concepts/docling_document/)：统一表格、图片、阅读顺序与可取得的位置。
- [Docling OCR](https://docling-project.github.io/docling/concepts/OCR/)：RapidOCR 语言配置与单识别路由限制。
- [Docling 分块](https://docling-project.github.io/docling/concepts/chunking/)：结构先行、token 预算、表头上下文。
- [Docling 资源控制](https://docling-project.github.io/docling/usage/advanced_options/)：线程、页面缓冲与离线模型准备。
- [Docling 格式支持](https://docling-project.github.io/docling/usage/supported_formats/)：旧 XLS 等格式的额外运行时边界。
- [RapidOCR 安装](https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/install/)：ONNX Runtime 与轻量发行包；下载体积不等于进程内存。

这些资料支持接口和选型，不替代本项目的中文表格质量、峰值内存和端到端检索验收。
