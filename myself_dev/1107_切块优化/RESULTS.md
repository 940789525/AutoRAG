# T1 本地解析与资源探针结果

2026-11-07 · **T1 通过，T2 使用 Docling＋RapidOCR＋TableFormer ACCURATE。** 现有 kordoc 产品路由继续使用；本次只运行隔离探针。

## 表格识别

同一批 12 份合成文档、48 条目标记录，覆盖中文、英文和混排的原生／扫描 PDF、PNG／JPG／WebP、DOCX、XLSX，以及双栏、合并表头、宽表和跨页表。4 份保留样本按版式家族划分。课程、学期、成绩和学分必须在同一行对应到正确表头，且每条目标记录唯一匹配；单独找到“体育”或分数不算通过。

| 暖态识别 | kordoc 4.21.30＋Tesseract 7.0.0 | Docling FAST | Docling ACCURATE |
| --- | ---: | ---: | ---: |
| 全部目标记录 | 24/48 | 31/48 | **48/48** |
| 中文双栏扫描／英文双栏原生／中英双栏扫描 | 0/4、4/4、0/4 | 2/4、2/4、3/4 | **4/4、4/4、4/4** |
| 独立图片（3 份） | 0/12 | 3/12 | **12/12** |
| 保留样本（4 份，部分与上面重合） | 8/16 | 12/16 | **16/16** |
| 全部目标记录正确的文件 | 6/12 | 5/12 | **12/12** |

基线按现有 AutoRAG 适配器产出的 Markdown 评分，语言配置为 `zh-hans`、`en`；Docling 按结构化网格评分。这是**能否保留供索引使用的字段关系**的对比。基线在两份扫描双栏样本中没有返回可评分的表格；FAST 则有网格，但在混排样本中把 `Spring` 和 `79` 放进了同一格。ACCURATE 在这批样本上恢复了两种情况下的目标关系。

首轮混排保留样本有两处双语表头画出了格子，无法按参考答案有效评分。最终批次仅加宽这两列并加上生成时的溢出检查，保留参考答案、解析参数及样本分组，重跑了全部三组。首轮原始输出保存在任务证据目录；最终批次的该样本不等于一次从未检查过的盲测。

## 耗时与内存

在 i7-10750H 主机的隔离 Linux x86_64 Docker 中，核实 cgroup 配额为 **4 CPU、8 GiB、无额外 swap**，与日常 Compose 限额一致。每组启用同版本的独立本地 FastEmbed／Qwen3-Embedding-0.6B（1024 维），在解析前、中、后发送合成嵌入请求。全程断网，无 GPU。

| 指标 | kordoc 基线 | FAST | ACCURATE |
| --- | ---: | ---: | ---: |
| 首份中文扫描件：冷／暖 | 2.16 / 1.40 秒 | 24.09 / 8.04 秒 | **28.67 / 9.96 秒** |
| 暖态单份：中位数／P95（12 份） | 0.56 / 1.56 秒 | 7.34 / 11.10 秒 | **8.35 / 11.01 秒** |
| 解析进程树峰值 RSS（0.1 秒采样） | 0.56 GiB | 1.71 GiB | **1.72 GiB** |
| 容器 `memory.peak`（含 FastEmbed、页缓存） | 2.49 GiB | 3.28 GiB | **3.99 GiB** |
| 解析器专用权重（不含 Qwen） | 6.28 MiB | 332.70 MiB | **396.89 MiB** |
| 成功嵌入请求／超时／OOM | 3 / 0 / 0 | 13 / 0 / 0 | **15 / 0 / 0** |

冷启动包含首次解析进程及模型加载，FastEmbed 已就绪；暖态复用解析进程。P95 取最近秩，小样本下等于最大值。ACCURATE 的 9 份单页 PDF／图片暖态耗时 6.42–10.01 秒（中位数 8.58 秒）；两页样本整份 11.01 秒（平均 5.51 秒／页，没有独立的逐页计时）。全部低于现有 120 秒文件期限，ACCURATE 容器峰值约为上限一半；未对大批量或长扫描件外推。

## 冻结配置与边界

- Linux x86_64、CPython 3.12.3，独立解析 venv；Docling 2.148.0、RapidOCR 3.10.0、ONNX Runtime 1.31.1、PyTorch 2.9.1+cpu。Heron 版面模型配 TableFormer ACCURATE；三种语言场景共用固定的 PP-OCRv6 multilingual small 和内置字典。模型来源、revision、SHA-256 与许可见 [模型锁](../../scripts/manual-qa/table-probe/models.lock.json)；Python wheel 见 [依赖锁](../../scripts/manual-qa/table-probe/requirements.lock)。
- 解析并发 1，CPU 推理线程配置上限 4，页面队列／预解码缓冲 1，阶段批大小 1；不启用视觉大模型或增强。使用本地模型目录，v1 JSONL 请求 8 KiB、响应 4 MiB，stderr 独立记录。探针硬期限 120 秒，Docling 转换内部期限 110 秒。
- **A01 解析层通过**：新后端六类格式可用；离线对照验证关闭 OCR 时扫描件没有产生识别文字或单元格文本。**A02 解析层通过**：三组核心双栏及保留集目标字段全部正确。**A08 探针通过**：断网使用预置模型，缺模型时返回具体缺失路径；与嵌入服务共存，无超时或 OOM。离线失败用例使用共享配置的 FAST 路径，正式 ACCURATE 批次也在断网环境运行。
- 产品路由与旧格式兼容性、行组切块、检索召回和父表回读还没有进行端到端验收。这一轮未处理真实成绩单，也未把试验依赖加入产品；生产集成时仍需单独确认 Python 依赖及模型许可。
